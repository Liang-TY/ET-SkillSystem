### 1.2 核心架构

**技能定义 = 代码（在 SkillDefs 项目里写），不是 Excel 配置表。**

ET-SkillSystem Demo（状态同步）把技能做成 Excel 配置表，那是因为 MMO 状态同步的技能由策划配表驱动。我们是帧同步，技能逻辑在客户端确定性执行，用 C# 代码写技能更灵活、更好调试、更容易保证确定性。

**Buff 的配置解释器模式参照 Demo 的 Actions 系统**：Buff 的效果（加减属性、施加伤害、施加子 Buff）通过 Actions 机制驱动。简单效果用已有 Action 组合，复杂效果写一个新的 ILSAction 实现类。

```
框架包（cn.etetet.skill）提供运行时基础设施：
  - LSNumericComponent（数值计算，纯 int key）
  - NumericType（数值 key 常量，框架包定义）
  - LSActionDispatcher（Action 分发）
  - LSShapeData（形状判定）
  - SkillLogic 基类 + SkillContext API（逻辑驱动，所有状态存 LSCast）
  - LSBuff 配置解释器（根据 BuffDef 定义执行 AddAction/TickAction/RemoveAction）
  - LSCast 逻辑驱动（SkillLogic.OnUpdate 每帧执行）

SkillDefs 项目定义具体游戏内容：
  - 技能类（BurningZone、IceArrow、Charge...）
  - BuffDef 定义（每个 Buff 绑定哪些 Action、持续时间、Tick 间隔）
  - ILSAction 实现（NumericChange、Damage、CastBullet、Attract...）
  - 所有 ID 常量（SkillIds、BuffIds、ActionIds）
```

### 1.6 帧更新流程

```
Room.Update(OneFrameInputs)
  → 分发输入到各 LSUnit 的 LSInputComponent
  → LSWorld.Update()
      → LSUpdater 按实体 ID 顺序遍历所有 ILSUpdate
          → LSInputComponent.LSUpdate     ← 移动（检查 ForbidMove 数值）
          → LSSkillComponent.LSUpdate     ← 技能施放请求
          → LSCast.LSUpdate               ← 委托 SkillLogic.OnUpdate
          → LSBullet.LSUpdate             ← 弹道移动 + 碰撞
          → LSArea.LSUpdate               ← 区域效果 tick
          → LSBuffComponent.LSUpdate      ← Buff 倒计时 + Tick
```

### 1.7 回滚兼容性原则

帧同步回滚时，整个 LSWorld 从 MemoryPack 快照反序列化恢复。因此：

1. **所有运行时状态必须存 LSEntity 上**（带 `[MemoryPackable]`），不能存在普通 C# 对象中
2. **SkillLogic 必须无状态**——只提供行为，不持有数据。所有数据存 LSCast
3. **不能用 delegate/lambda**——不可序列化，回滚后丢失
4. **不能用事件驱动视图**——LSUpdate 在回滚重放时也会执行，事件会重复触发
5. **FP 构造用 `FP.FromRaw(long)`**——`RawValue` 只有 getter
6. **注意防止技能递归**——技能通过 Action 间接创建新 Cast 时可能产生无限递归（A→B→A），设计时需避免互触发的技能组合

### 2.1 LSInput 扩展

```csharp
[MemoryPackable]
public partial struct LSInput
{
    [MemoryPackOrder(0)]
    public TSVector2 V;

    [MemoryPackOrder(1)]
    public int Button;          // 0=无, 1~4=技能槽位

    [MemoryPackOrder(2)]
    public TSVector2 Target;    // 技能目标位置（XZ 平面）

    public bool Equals(LSInput other)
    {
        return this.V == other.V
            && this.Button == other.Button
            && this.Target == other.Target;
    }

    public override bool Equals(object obj)
    {
        return obj is LSInput other && Equals(other);
    }

    public override int GetHashCode()
    {
        return HashCode.Combine(this.V, this.Button, this.Target);
    }

    public static bool operator==(LSInput a, LSInput b)
    {
        if (a.V != b.V) return false;
        if (a.Button != b.Button) return false;
        if (a.Target != b.Target) return false;
        return true;
    }

    public static bool operator !=(LSInput a, LSInput b) => !(a == b);
}
```

### 2.4 LSInputComponentSystem — 通过数值组件检查移动禁用

```csharp
[LSEntitySystem]
private static void LSUpdate(this LSInputComponent self)
{
    LSUnit unit = self.GetParent<LSUnit>();

    // 如果有数值组件且 ForbidMove > 0（眩晕/冰冻），跳过移动
    var numeric = unit.GetComponent<LSNumericComponent>();
    if (numeric != null)
    {
        if (numeric.Get(NumericType.ForbidMove) > FP.Zero) return;
    }

    TSVector2 v2 = self.LSInput.V * 6 * 50 / 1000;
    if (v2.LengthSquared() < 0.0001f) return;
    TSVector oldPos = unit.Position;
    unit.Position += new TSVector(v2.x, 0, v2.y);
    unit.Forward = unit.Position - oldPos;
}
```

## 四、层③ — 技能系统框架包

### 4.1 LSNumericComponent — 数值组件（纯 int key）

参照 ET 框架的 NumericComponent 设计（`Book/5.6数值组件设计.md`），适配帧同步（FP 替代 int）。

框架包内部用 `int` 作为 key。NumericType 常量类定义在框架包 Model/Share 中，供框架包和 SkillDefs 共同使用。

```csharp
[ComponentOf(typeof(LSUnit))]
[MemoryPackable]
public partial class LSNumericComponent : LSEntity, IAwake, ISerializeToEntity
{
    [MemoryPackOrder(0)]
    public Dictionary<int, FP> NumericDic = new();

    public FP Get(int key)
    {
        NumericDic.TryGetValue(key, out FP value);
        return value;
    }

    public void Set(int key, FP value)
    {
        NumericDic[key] = value;
        // key % 10 != 0 表示是子属性（add/pct/finalAdd/finalPct），需要重算 final
        if (key % 10 != 0) UpdateFinal(key / 10 * 10);
    }

    public void Add(int key, FP value) => Set(key, Get(key) + value);

    // 五层公式：final = (((base + add) * (1 + pct) + finalAdd) * (1 + finalPct)
    private void UpdateFinal(int finalKey)
    {
        FP baseVal  = Get(finalKey + 1);
        FP add      = Get(finalKey + 2);
        FP pct      = Get(finalKey + 3);
        FP finalAdd = Get(finalKey + 4);
        FP finalPct = Get(finalKey + 5);

        NumericDic[finalKey] = ((baseVal + add) * (FP.One + pct) + finalAdd) * (FP.One + finalPct);
    }
}
```

**NumericType 常量定义在技能框架包**：

```csharp

    public const int MaxHpBase = 10021;

    public const int MaxHpPct = 10023;
    public const int MaxHpFinalAdd = 10024;
    public const int MaxHpFinalPct = 10025;
```

**与 ET-SkillSystem Demo 的 NumericComponent 对比**：

| 维度 | ET-SkillSystem（状态同步） | 本方案（帧同步） |
|------|--------------------------|-----------------|
| 值类型 | `long`（定点，乘 10000） | `FP`（TrueSync 定点数） |
| Key 类型 | `NumericType` 枚举 | `const int`（框架包 NumericType.cs） |
| 公式 | `((base+add)*(100+pct)/100+finalAdd)*(100+finalPct)/100` | `((base+add)*(1+pct)+finalAdd)*(1+finalPct)` |
| 序列化 | 可选 | MemoryPack（快照回滚） |
| 事件 | `Game.EventSystem.Run` | 帧同步内不需要（确定性，无事件总线） |

**为什么用 ET 的 NumericComponent 而不是自定义 LSStatsComponent**：

1. 自定义组件字段写死（HP/Speed/Attack）——加属性改代码。NumericComponent 用 key-value，新属性加个常量
2. Buff 效果无法统一——MoveSpeedMod 要单独字段。NumericComponent 统一用 `Add(NumericType.SpeedAdd, value)`
3. ET 框架自带五层公式（base/add/pct/finalAdd/finalPct），复杂 buff（+50 速度再 +20%）自动计算
4. 多来源叠加天然支持（眩晕 A + 眩晕 B → ForbidMove=2，移除 A → ForbidMove=1，仍然禁移动）

#### Action 分发器

```csharp
public static class LSActionDispatcher
{
    private static readonly Dictionary<LSActionType, ILSAction> handlers = new();

    // 初始化时扫描所有 ILSAction 实现并注册
    public static void Init()
    {
        foreach (var type in typeof(LSActionDispatcher).Assembly.GetTypes())
        {
            if (typeof(ILSAction).IsAssignableFrom(type) && !type.IsAbstract)
            {
                var attr = type.GetCustomAttribute<LSActionAttribute>();
                if (attr != null)
                    handlers[attr.Type] = (ILSAction)Activator.CreateInstance(type);
            }
        }
    }

    public static void Run(LSUnit owner, int actionId, LSActionRunType runType)
    {
        var config = LSActionConfigCategory.Get(actionId);
        if (!handlers.TryGetValue((LSActionType)config.Type, out var handler)) return;
        handler.Run(owner, config.Param, runType);
    }

    // 批量执行
```

```csharp
// LSCastSystem — 逻辑驱动
[LSEntitySystem]
private static void LSUpdate(this LSCast self)
{
    if (self.Finished) return;

    self.ElapsedMs += LSConstValue.UpdateInterval;

    LSWorld world = self.IScene as LSWorld;
    LSUnit caster = world.GetComponent<LSUnitComponent>().GetChild<LSUnit>(self.CasterId);

    // 委托给 SkillLogic
    SkillLogic logic = self.GetLogic();
    if (logic != null)
    {
        var ctx = new SkillContext(world, caster, self);
        logic.OnUpdate(ctx, self, LSConstValue.UpdateInterval);
    }

    // 自动结束检查
    if (self.TotalTimeMs > 0 && self.ElapsedMs >= self.TotalTimeMs)
    {
        SkillLogic endLogic = self.GetLogic();
        if (endLogic != null)
        {
            var ctx = new SkillContext(world, caster, self);
            endLogic.OnEnd(ctx, self);
        }
        self.Finished = true;
    }
}
```

**回滚兼容性**：回滚时 LSWorld 从快照反序列化，LSCast 的所有 `[MemoryPackOrder]` 字段恢复。`_logic` 标记 `[MemoryPackIgnore]`，反序列化后为 null，下次 `GetLogic()` 时自动从 `SkillLoader.Create(SkillId)` 重建。因为 SkillLogic 无状态，重建后行为完全一致。

```csharp
// LSBuffComponentSystem — Buff 配置解释器
// 使用预分配列表避免 GC（参考 LSUpdater 的 updateIds 模式）
[LSEntitySystem]
private static void LSUpdate(this LSBuffComponent self)
{
    int dtMs = LSConstValue.UpdateInterval;
    LSUnit owner = self.GetParent<LSUnit>();

    self._toRemove.Clear();

    // 直接遍历 SortedDictionary，无 GC
    foreach (var kv in self.Children)
    {
        LSBuff buff = (LSBuff)kv.Value;
        buff.RemainingMs -= dtMs;
        if (buff.RemainingMs <= 0)
        {
            // 移除：执行 RemoveAction
            var config = BuffRegistry.Get(buff.ConfigId);
            LSActionDispatcher.RunAll(owner, config.RemoveActions, LSActionRunType.BuffRemove);
            self._toRemove.Add(buff.Id);
            continue;
        }

        // Tick
        var buffConfig = BuffRegistry.Get(buff.ConfigId);
        if (buffConfig.TickTime > 0)
        {
            buff.TickTimer += dtMs;
            if (buff.TickTimer >= buffConfig.TickTime)
            {
                buff.TickTimer -= buffConfig.TickTime;
                LSActionDispatcher.RunAll(owner, buffConfig.TickActions, LSActionRunType.BuffTick);
            }
        }
    }

    // 第二遍：移除过期的 buff
    foreach (long id in self._toRemove)
        self.GetChild<LSBuff>(id).Dispose();
    self._toRemove.Clear();
}
```

### 4.5 LSShapeData — 技能形状

支持圆形、矩形、扇形、环形：

```csharp
public enum LSShapeType
{
    Circle = 1,
    Rectangle = 2,
    Fan = 3,
    Ring = 4,
}

[MemoryPackable]
public partial struct LSShapeData
{
    [MemoryPackOrder(0)]
    public LSShapeType Type;

    [MemoryPackOrder(1)]
    public TSVector Center;

    [MemoryPackOrder(2)]
    public TSVector Direction;     // 扇形朝向

    [MemoryPackOrder(3)]
    public FP Radius;              // 圆形/环形外半径

    [MemoryPackOrder(4)]
    public FP InnerRadius;         // 环形内半径

    [MemoryPackOrder(5)]
    public TSVector HalfExtents;   // 矩形半尺寸

    [MemoryPackOrder(6)]
    public FP Angle;               // 扇形半角（度）

    [MemoryPackOrder(7)]
    public FP Range;               // 扇形范围

    // 判断点是否在形状内
    public bool Contains(TSVector point)
    {
        switch (Type)
        {
            case LSShapeType.Circle:
                return TSVector.Distance(Center, point) < Radius;

            case LSShapeType.Rectangle:
                return AABBUtil.FromCenter(Center, HalfExtents).Contains(point);

            case LSShapeType.Fan:
                TSVector toPoint = point - Center;
                FP dist = toPoint.Length();
                if (dist > Range || dist <= FP.Zero) return false;
                FP angle = TSVector.Angle(Direction, toPoint / dist);
                return angle < Angle;

            case LSShapeType.Ring:
                FP d = TSVector.Distance(Center, point);
                return d >= InnerRadius && d < Radius;

            default: return false;
        }
    }
}
```

```csharp
    // 初始化：扫描程序集
    public static void Init()
    {
        foreach (var type in typeof(SkillLoader).Assembly.GetTypes())
```

```csharp
    public override void OnCast(SkillContext ctx, LSCast cast)
    {
        // 所有状态写入 cast，不持有实例字段
        TSVector dir = cast.TargetPosition - ctx.Caster.Position;
        if (dir.Length() > 800) dir = dir.normalized * 800;
        cast.SavedPos = ctx.Caster.Position + dir;
        cast.Reached = false;
        ctx.SetAttackHitbox(new TSVector(0, 0, 5), new TSVector(5, 5, 10));
    }

    public override void OnUpdate(SkillContext ctx, LSCast cast, int dtMs)
    {
        // 从 cast 读状态，不持有实例字段
        if (cast.Reached) return;

        LSUnit caster = ctx.Caster;
        TSVector toTarget = cast.SavedPos - caster.Position;
        FP dt = FP.FromRaw(dtMs * FP.One.RawValue / 1000);
        FP moveAmount = 30 * dt;

        if (moveAmount >= toTarget.Length())
        {
            caster.Position = cast.SavedPos;
            cast.Reached = true;
        }
        else
        {
            caster.Position += toTarget.normalized * moveAmount;
        }

        foreach (LSUnit enemy in ctx.GetEnemies())
        {
            if (ctx.CheckHit(caster, enemy))
            {
                ctx.AddNumeric(enemy, NumericType.Hp, -100);
                ctx.MoveUnitTo(enemy, cast.SavedPos);
            }
        }
    }

    public override void OnEnd(SkillContext ctx, LSCast cast)
        => ctx.DisableAttackHitbox();
}
```

## 七、关键设计决策

### 7.1 为什么 skill 引用 lockstep 而不是反过来

skill 包的实体定义直接使用 lockstep 包的类型（`[ComponentOf(typeof(LSUnit))]`），所以 skill 必须引用 lockstep。lockstep 包通过 `ILSUpdate` 接口多态驱动 skill 实体，不需要知道具体类型。

### 7.2 为什么状态/属性在 skill 包，不在 lockstep 包

LSNumericComponent、LSBuffComponent 属于战斗系统概念，不是帧同步基础设施。一个没有技能的帧同步项目（如棋类）不需要它们。

眩晕阻止移动的问题：通过数值组件 `NumericType.ForbidMove` 控制。lockstep 包定义自己的 NumericType.cs（只含 ForbidMove/ForbidSkill），与技能框架包的 NumericType.cs 保持值一致。

> **后期重构计划**：当前方案中 LSInputComponent 及其移动逻辑留在 lockstep 包，lockstep 包需要检查数值组件。后期重构时可将 LSInputComponent 及其逻辑移到技能框架包（方案 B），按键处理、角色移动完全由技能框架包控制。届时 lockstep 包只负责输入数据的收集和传递，不再需要定义 NumericType.cs。

### 7.3 为什么用 ET 的 NumericComponent 而不是自定义属性组件

自定义组件字段写死（HP/Speed），加属性改代码。NumericComponent 用 key-value + 五层公式，Buff 效果统一通过 `Add(key, value)` 操作，不需要每种 buff 效果一个字段。多来源叠加天然支持（两个眩晕叠加 → key 值为 2，移除一个 → 值为 1，仍禁��动）。

NumericType 常量定义在技能框架包中，SkillDefs 直接使用。lockstep 包也有一份同名文件（仅含 ForbidMove/ForbidSkill），值保持一致。

### 7.4 为什么 SkillLogic 必须无状态

帧同步回滚时整个 LSWorld 从 MemoryPack 快照恢复。只有 LSEntity（带 `[MemoryPackable]`）的状态能恢复。SkillLogic 由 `Activator.CreateInstance()` 创建，不属于 LSEntity 体系，回滚后状态丢失。

解决方案：所有运行时状态存 LSCast（LSEntity），SkillLogic 只提供行为不持有状态。SkillLogic 实例缓存在 LSCast 的 `[MemoryPackIgnore]` 字段中，回滚后为 null 自动重建。

### 7.5 为什么不能用 lambda/delegate 回调

`delegate` / `lambda` 不能被 MemoryPack 序列化。回滚后回调丢失。区域效果（CreateArea）改为配置驱动（int[] actionIds），通过 LSActionDispatcher 执行。

### 7.6 为什么 buff 效果用 Actions 配置驱动而非硬编码

参照 ET-SkillSystem Demo 的 Actions 模式：简单 buff 用已有 Action 组合（NumericChange + Damage + AddBuff），复杂 buff 写一个新的 ILSAction 实现类。BuffDef 在 SkillDefs 代码里定义，注册到框架的 BuffRegistry 中。

### 7.7 为什么统一用逻辑驱动而非配置解释器

ET-SkillSystem Demo 用 CastConfig 配置表驱动时间轴（HitActionTimes: [500, 1000]）。帧同步项目选择统一用 SkillLogic 代码驱动：

- 复杂技能（冲撞移动、变身换技能、黑洞吸引）必须用代码
- 简单技能（丢火球）用代码也不复杂
- 统一一条路径，降低复杂度

Buff 的配置解释器模式保留（BuffDef + BuffRegistry），因为 Buff 生命周期固定（add/tick/remove），配置驱动比每个 Buff 写一个类更轻量。

### 7.8 为什么 LSArea 改为配置驱动

原方案用 lambda 回调（`onEnter: (unit) => ctx.AddBuff(unit, BuffIds.Burn)`），不可序列化。改为 int[] actionIds 配置驱动，与 Buff 的 Actions 模式一致。
