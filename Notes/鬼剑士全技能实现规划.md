## 1. 游戏现状

### 1.1 项目概况

基于 ET9 帧同步的 2D 像素网游（借鉴 DNF）。Unity 6000.0.25f1，UI 框架 YIUI。
开发机（本机）无 Unity，编译/构建走任务总线（automation/）由 Unity 机执行。

### 1.2 技能系统架构

```
技能内容层（DotNet~/，独立 dotnet 编译，Unity 永不编译）
  Skills/*.cs     技能逻辑（SkillLogic 子类，[SkillId] 注册）
  Actions/*.cs    效果节点（LSAction 子类，[ActionId] 注册）
  Buffs/*.cs      Buff 配置
  Bullets/*.cs    投射物配置
  Areas/*.cs      区域效果配置
  编译产物 ET.SkillContent.dll.bytes → YooAsset → Assembly.Load

技能框架层（Runtime/，ET.Skill 程序集，F6 编译）
  SkillLogic/SkillContext/SkillCastHelper  生命周期+门面
  LSAction/LSActionContext                  效果节点
  BuffDefinition/BulletDefinition/AreaDefinition  配置基类
  ContentLoader<TAttr,TBase>               泛型注册器+守门员

逻辑实体层（Scripts/Model/Share/，ET.Model 程序集）
  LSCast/LSCastComponent/LSSkillComponent
  LSNumeric/LSHitbox/LSCombat/LSInputBuffer
```

**关键约束**：
- 技能内容在 DotNet~ 目录，**Unity 不编译**——改了要手动 `dotnet build` → DLL 改名 .bytes
- 帧同步铁律：禁 float/double（用 TSMath/FP）、禁实例字段、禁 UnityEngine、禁反射
- 每个类一个文件

### 1.5 NPK/IMG 资源管线

NPK 按需加载管线已建好（`Notes/NPK按需加载架构方案.md`）：

```
NPK 原始文件 → 改名 .npk.bytes 放 Bundles/NPK/ → YooAsset 加载
  → NpkArchive.Mount（读索引，不解像素）
  → NpkMountManager.ReadByFilename（文件名反查→提取字节）
  → NpkImgParser.Parse（解析像素帧）
  → RectpackSharp 打图集 → Sprite.Create → 注册
```

**NPK 源目录**：`E:\Download\dnf客户端\70不悔客户端\ImagePacks2`
**项目存放**：`Packages/cn.etetet.lockstep/Bundles/NPK/*.npk.bytes`
**旧管线**：`Bundles/AnimRes/*.img.bytes`（手工提取的 IMG，作为 fallback 保留）

**NPK→IMG 映射规则**：
1. NPK 文件名 → 内部虚拟路径前缀（如 `sprite_character_swordman_effect.NPK` 含 `sprite/character/swordman/effect/*.img`）
2. 挂载时自动建文件名反查表（`katana9200b.img` → `sprite/character/swordman/equipment/weapon/katana/katana9200b.img`）
3. 运行时按文件名查找，不需要知道完整路径

**找不到 NPK 中的 IMG 时**：
1. 先检查 ImagePacks2 目录是否有对应 NPK（文件名关键词匹配）
2. 用 Python 脚本扫描 NPK 索引确认虚拟路径
3. 确实缺失的 → 告诉用户补充对应 NPK

### 1.6 动画翻译工具

DnfConfigTranslation（`E:\Projects\cs\parse-img-ani\DnfConfigTranslation`）：
- `ani` 子命令：.ani → JSON（AnimClipData 格式，含 frames[].image.path）
- `als` 子命令：.als → JSON（AnimOverlayConfig，特效叠加配置）

**当前问题**：翻译时 `[IMAGE]` 标签的路径被简化成纯文件名（如 `BantuAmazones.img`），丢失了 NPK 虚拟路径前缀。

**需要改造**（双版本兼容）：
- 旧版 JSON：`"path": "BantuAmazones.img"`（只有文件名，当前游戏的形态）
- 新版 JSON：`"path": "sprite/character/swordman/effect/BantuAmazones.img"`（完整虚拟路径）
- 运行时：NpkMountManager 的 `ReadByFilename`（文件名反查）兼容旧版，`Read`（完整路径）兼容新版
- 改造点：AniParser 保留 .ani 里的原始路径不简化，新版 JSON 写完整路径

### 3.3 NPK/IMG 查找方法

```python
# Python 脚本：扫描所有 NPK 找指定 IMG
import struct

def xor_decrypt(data, key):
    return bytes(a ^ b for a, b in zip(data, key))

base = b'puchikon@neople dungeon and fighter '
key = bytearray(256); key[:len(base)] = base
pos = len(base)
while pos < 256:
    key[pos] = ord('D'); pos += 1
    if pos >= 256: break
    key[pos] = ord('N'); pos += 1
    if pos >= 256: break
    key[pos] = ord('F'); pos += 1
key[255] = 0

import os
npk_dir = 'Packages/cn.etetet.lockstep/Bundles/NPK'
search = '目标img名'.lower()  # 如 'hardattack'

for f in os.listdir(npk_dir):
    if not f.endswith('.npk.bytes'): continue
    data = open(os.path.join(npk_dir, f), 'rb').read()
    if data[:16] != b'NeoplePack_Bill\x00': continue
    count = struct.unpack('<i', data[16:20])[0]
    for i in range(count):
        off = 20 + i * 264
        name = xor_decrypt(data[off+8:off+8+256], bytes(key)).split(b'\x00')[0].decode('utf-8', errors='replace')
        if search in name.lower():
            print(f'{f}: {name}')
```

## 6. 翻译工具改造

### 6.1 改造目标

DnfConfigTranslation 的 AniParser 保留 .ani 原始路径，产出双版本 JSON。

### 6.2 改造点

文件：`E:\Projects\cs\parse-img-ani\DnfConfigTranslation\Ani\AniParser.cs`
文件：`E:\Projects\cs\parse-img-ani\DnfConfigTranslation\Ani\AniModels.cs`

当前行为：
```
.ani 里：`Monster/Bantu/BantuAmazones.img`
JSON 里：`"path": "BantuAmazones.img"`  ← 简化了
```

改造后：
```
.ani 里：`Monster/Bantu/BantuAmazones.img`
新版 JSON：`"path": "sprite/monster/bantu/bantuamazones.img"`  ← 完整虚拟路径（小写+sprite前缀）
旧版兼容：`"pathLegacy": "BantuAmazones.img"`  ← 旧格式保留
```

规则：
- .ani 路径 → 拼上 `sprite/` 前缀 → 全小写 = NPK 虚拟路径
- 同时保留旧格式（纯文件名）在 pathLegacy 字段
- 运行时优先用 path（完整路径）查 NpkMountManager.Read，找不到用 pathLegacy 查 ReadByFilename

### 6.3 何时做

在第一个技能实现时一起做——翻译第一个技能的 .ani 时改 AniParser，后续所有技能自动受益。

### 鬼斩实现踩坑补充（用户修复 3 bug）

| 坑 | 根因 | 教训 |
|---|---|---|
| **OnUpdate 第二参是 dtMs 不是 elapsedMs** | `OnUpdate(ctx, dtMs)` 的 `dtMs` = 每 tick 增量（帧同步 50ms/tick），不是从技能开始累计的经过时间。累计时间用 `ctx.GetElapsedMs()` | 写 OnUpdate 前必须读 SkillContext.cs 确认参数语义，不猜 |
| **TSVector 坐标 y/z 对调** | DNF 坐标 (x=横向, y=纵深, z=高度) ≠ 我们 TSVector (x=横向, y=高度, z=纵深)。笔记/分析文档里的偏移量是 DNF 坐标，直接搬 y/z 反了 | DNF→TSVector 映射规则：`TSVector(dnf.x, dnf.z, dnf.y)`（y/z 对调） |
| **新目录/新文件缺 .meta** | 开发机创建的新文件没有 Unity .meta，Unity 不识别 → YooAsset 找不到 | 提交前检查新文件是否有 .meta；或让 Unity 机提交时补上 |

**OnUpdate 正确写法（模板）**：
```csharp
public override void OnUpdate(SkillContext ctx, int dtMs)
{
    int elapsed = ctx.GetElapsedMs();   // ← 累计时间从 SkillContext 取，不用第二参
    if (elapsed >= OnMs) ctx.SetAttackHitbox(offset, halfExtents);
    else if (elapsed >= OffMs) ctx.DisableAttackHitbox();
}
```

**TSVector 坐标映射规则（模板）**：
```
DNF (x=横向, y=纵深, z=高度)  →  TSVector (x=横向, y=高度, z=纵深)
映射公式：TSVector(dnf.x, dnf.z, dnf.y)   ← y/z 对调
```
