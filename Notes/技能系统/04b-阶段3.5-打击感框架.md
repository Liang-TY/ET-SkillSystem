# 阶段 3.5：打击感框架（硬直 / 帧事件 / 输入缓冲）

> DNF 风格格斗游戏的"手感命脉"。框架我搭好，数值你调。
> 前提：阶段 1-3（HP + 碰撞 + 扣血闭环）已完成。
> 验证：玩家攻击命中怪物 → 怪物硬直 → 受击动画 → 扣血。
>
> **DNF 研究修正**（见 `Notes/dnf源码研究/01,07 总结`）：
> - 受击反应是**攻击方配置驱动**（DNF 的 damageAct/upForce/backForce/hitStunTime 挂攻击方 AttackInfo，命中后引擎应用到受击方）→ 我们 attack.json 顶层加这些字段。
> - **攻方普攻不停帧**——DNF 打击感靠"受击方僵直 + 每帧判定框变化 + 攻速节奏"，攻方动画照常播完。
> - 连段窗口 = [cancelFrame, 动画末]（不是固定 300ms 缓冲）。
> - 调参参考值（DNF 实测）：轻击 upForce=10/backForce=3；终结段 DOWN+300/300；多段 PO hitStun=0。

## 0. 速查

- **目标**：实现打击感的三大支柱——帧事件、受击硬直、输入缓冲。
- **暂不实现**：顿帧（Hitstop）——设计保留在 §4，DNF 证实攻方不停帧、靠受击僵直+每帧判定框制造打击感即可，日后再看。
- **核心原则**：全部是**逻辑层确定性状态**（可回滚），视图层只读表现。
- **Route B**：状态标记 + 视图轮询 diff（不用事件总线，回滚安全）。

## 1. 四大支柱总览

```
玩家按攻击键
  → 输入缓冲记下"想放攻击"
  → 技能/动画系统检查：能取消当前动作吗？
  → 进入攻击动作
  → 动画推进到【判定帧】（比如第 3 帧）
  → 攻击盒激活 → 碰到怪物受击盒
  → 【命中】：
      ① 受击硬直：被击者进入 hitstun 状态 M 帧（不能动）
      ② 受击反应：按攻击方配置（damageAct/upForce/backForce/hitStunTime）
      ③ 受击动画：被击者切到 Hurt 动画
      ④ 扣血
      （顿帧暂不实现——见 §4）
  → 攻击动作推进到【收招帧】
  → 【取消窗口】：收招期间可以输入缓冲里的下一个动作取消后摇
  → 动作结束
```

## 2. 帧事件系统

### 2.1 给 AnimFrameData 加帧事件标记

在 `AnimClipData.cs` 的 `AnimFrameData` 扩展（你已经有 damageBox，加这几个）：

```csharp
[Serializable]
public struct AnimFrameData
{
    // ... 已有的 index/image/imagePos/delay/damageBox ...

    // 帧事件标记（JSON 里配 0/1，或在代码里按帧号设）
    public int hitFlag;       // >0 = 判定帧（攻击盒激活）
    public int cancelFlag;    // >0 = 取消窗口开始（可被输入缓冲的动作取消）
}
```

JSON 里怎么配（扩展 `move.json` / `attack.json`）：
```json
{
  "index": 0, "delay": 60, "hitFlag": 0, "cancelFlag": 0,   // 起手
  "image": {...}, "damageBox": {...}
}
{
  "index": 2, "delay": 80, "hitFlag": 1, "cancelFlag": 0,   // 判定帧
  "image": {...}, "damageBox": {...}
}
{
  "index": 4, "delay": 60, "hitFlag": 0, "cancelFlag": 1,   // 收招可取消
  "image": {...}, "damageBox": {...}
}
```

> 你现有的 stay.json / move.json 没有这些字段——JsonUtility 忽略缺失字段（默认 0），不影响。等做 attack.json 时再配。

### 2.2 LSAnimComponentSystem 读帧事件

`LSUpdate` 推进帧后，检查当前帧的 flag，驱动攻击盒：

```csharp
// 在 LSAnimComponentSystem.LSUpdate 推进帧之后
AnimFrameData frame = clip.frames[self.FrameIndex];

// 判定帧：激活攻击盒（从 damageBox 或 attackBox 采样）
if (frame.hitFlag > 0)
{
    // 通知 HitboxComponent 激活攻击盒
    var hitbox = unit.GetComponent<LSHitboxComponent>();
    if (hitbox != null) hitbox.AttackEnabled = true;
}
else
{
    var hitbox = unit.GetComponent<LSHitboxComponent>();
    if (hitbox != null) hitbox.AttackEnabled = false;
}
```

> 注意：这段放在 LSAnimComponentSystem 还是 LSHitboxComponentSystem 都行。建议放在一个专门的 `LSCombatComponentSystem` 里（见下），保持职责清晰。

## 3. 受击硬直（Hitstun）

### 3.1 LSCombatComponent（战斗状态组件）

给 LSUnit 加一个战斗状态组件，管硬直/顿帧计时：

```csharp
// skill 包 Model/Share
[ComponentOf(typeof(LSUnit))]
[MemoryPackable]
public partial class LSCombatComponent : LSEntity, ILSUpdate, IAwake, ISerializeToEntity
{
    [MemoryPackOrder(0)]
    public int HitstunTimer;     // 受击硬直剩余 ms（>0 时不能行动/不能放技能）

    [MemoryPackOrder(1)]
    public int HitstopTimer;     // 顿帧剩余 ms（>0 时不推进动画/不推进 Cast）

    [MemoryPackOrder(2)]
    public int LastHitstunTimer; // 上一帧值（视图 diff 用，Route B）
}
```

### 3.2 硬直效果

被打中时：`combat.HitstunTimer = 硬直时长（ms）`。

`LSInputComponentSystem.LSUpdate` 和 `LSCast.LSUpdate` 里检查：
```csharp
// 硬直中不能移动
var combat = unit.GetComponent<LSCombatComponent>();
if (combat != null && combat.HitstunTimer > 0) return;  // 跳过移动/技能逻辑
```

`LSCombatComponentSystem.LSUpdate`：
```csharp
self.LastHitstunTimer = self.HitstunTimer;  // 记上帧值（Route B diff）
if (self.HitstunTimer > 0)
    self.HitstunTimer -= LSConstValue.UpdateInterval;
```

### 3.3 视图层（Route B 轮询）

视图组件读 `combat.HitstunTimer`：
- `LastHitstunTimer == 0 && HitstunTimer > 0` → 刚被击中 → 播受击动画 + 受击特效。
- `HitstunTimer > 0` → 持续受击状态（保持受击动画）。
- `LastHitstunTimer > 0 && HitstunTimer == 0` → 硬直结束 → 回 Idle。

## 4. 顿帧（Hitstop）——暂不实现，设计保留日后看

> **DNF 实证**（`原始笔记/R3-J` §1.6 + `07 总结` §1.4）：DNF 普攻**攻方不停帧**——
> attack.nut 的 onAttack 只挂特效，攻方动画照常播完。打击感靠：
> ① 受击方僵直（hitStunTime）② 每帧判定框变化（视觉反馈）③ 攻速节奏。
> `hitStunTimeAttackerDamager` 字段同时影响攻受双方僵直（最接近 hitstop 的数据层机制），
> 但它是"僵直时间参数"不是"暂停动画"机制。
>
> 我们先不做顿帧，用"受击硬直 + 每帧判定框 + 受击动画"覆盖打击感。
> 如果不够再加。以下设计保留供日后参考。

### 4.1 原理

命中瞬间，**攻击者和被击者**各自冻结几帧（HitstopTimer > 0 期间不推进动画帧/不推进 Cast）。其他实体照常。模拟"刀砍进肉的阻力感"。

### 4.2 触发

在命中检测代码里（攻击盒碰受击盒）：

```csharp
// 命中！
targetCombat.HitstunTimer = hitstunMs;   // 被击者硬直
targetCombat.HitstopTimer = hitstopMs;   // 被击者顿帧
attackerCombat.HitstopTimer = hitstopMs; // 攻击者也顿帧（刀卡住的感觉）
```

### 4.3 冻结效果

在 `LSAnimComponentSystem.LSUpdate` 开头：
```csharp
var combat = self.GetParent<LSUnit>().GetComponent<LSCombatComponent>();
if (combat != null && combat.HitstopTimer > 0) return;  // 顿帧中不推进动画
```

在 `LSCastSystem.LSUpdate` 开头同理：
```csharp
var combat = /* caster */.GetComponent<LSCombatComponent>();
if (combat != null && combat.HitstopTimer > 0) return;  // 顿帧中不推进技能
```

`LSCombatComponentSystem.LSUpdate` 递减 HitstopTimer：
```csharp
if (self.HitstopTimer > 0)
    self.HitstopTimer -= LSConstValue.UpdateInterval;
```

### 4.4 数值（你调）

| 参数 | 建议起点 | 调参方向 |
|------|---------|---------|
| 轻攻击顿帧 | 2 帧（~100ms） | 太短没感觉，太长像卡顿 |
| 重攻击顿帧 | 4 帧（~200ms） | |
| 硬直（被打） | 15-30 帧（~750-1500ms） | 取决于动作类型 |

## 5. 输入缓冲（Input Buffer）

### 5.1 为什么需要

DNF 的"普攻三连"：按一下=第一击，再按=第二击（第一击动作还没完就能预输入）。没有输入缓冲，必须等动作完全结束才能按下一个 → 手感僵硬。

### 5.2 LSInputBufferComponent

```csharp
[ComponentOf(typeof(LSUnit))]
[MemoryPackable]
public partial class LSInputBufferComponent : LSEntity, IAwake, ISerializeToEntity
{
    [MemoryPackOrder(0)]
    public int BufferedButton;      // 缓冲的按键（0=无, 1=攻击...）
    [MemoryPackOrder(1)]
    public int BufferTimer;         // 缓冲剩余 ms（超时清空）
}
```

### 5.3 写入缓冲

`LSInputComponentSystem.LSUpdate`：检测到按键输入，但当前在动作中（不能立刻放）→ 写入缓冲：

```csharp
if (self.LSInput.Button > 0)
{
    // 尝试立刻放；放不了（在动作中）→ 写缓冲
    var skill = unit.GetComponent<LSSkillComponent>();
    if (skill != null && !skill.TryCast(self.LSInput.Button, ...))
    {
        var buf = unit.GetComponent<LSInputBufferComponent>();
        if (buf != null)
        {
            buf.BufferedButton = self.LSInput.Button;
            buf.BufferTimer = 300;  // 缓冲窗口 300ms
        }
    }
}
```

### 5.4 消费缓冲

在技能/动画系统的 LSUpdate 里，检查取消窗口（`cancelFlag > 0`）时消费缓冲：

```csharp
// 当前动画帧是取消窗口 且 缓冲里有动作
AnimFrameData frame = anim.GetCurrentFrame();
var buf = unit.GetComponent<LSInputBufferComponent>();
if (frame.cancelFlag > 0 && buf != null && buf.BufferedButton > 0)
{
    int nextSkill = buf.BufferedButton;
    buf.BufferedButton = 0;
    buf.BufferTimer = 0;
    // 立刻切到下一个技能
    unit.GetComponent<LSSkillComponent>()?.TryCast(nextSkill, ...);
}
```

`LSInputBufferComponent` 也要 LSUpdate 递减 BufferTimer，超时清空。

## 6. 命中检测汇总（把以上串起来）

放在 `LSHitboxComponentSystem.LSUpdate`（或专门 `LSCombatSystem`）里：

```csharp
if (!self.AttackEnabled) return;
LSUnit attacker = self.GetParent<LSUnit>();
LSCombatComponent attackerCombat = attacker.GetComponent<LSCombatComponent>();
// 顿帧中不检测（刀卡住）
if (attackerCombat != null && attackerCombat.HitstopTimer > 0) return;

LSUnitComponent uc = attacker.LSWorld().GetComponent<LSUnitComponent>();
foreach (LSUnit target in uc.Children.Values)
{
    if (target.Id == attacker.Id) continue;
    LSHitboxComponent targetHit = target.GetComponent<LSHitboxComponent>();
    if (targetHit == null) continue;
    if (!AABBUtil.Intersects(self.CurrentAttackBox, targetHit.CurrentHurtBox)) continue;
    if (self.HitTargets.Contains(target.Id)) continue;  // 本次攻击已命中过

    self.HitTargets.Add(target.Id);
    LSCombatComponent targetCombat = target.GetComponent<LSCombatComponent>();

    // ① 受击硬直（被打的人僵住）—— DNF 实证：攻方不停帧，靠受击僵直制造打击感
    int hitstunMs = 500;
    if (targetCombat != null)   targetCombat.HitstunTimer = hitstunMs;

    // （顿帧暂不实现——见 §4，日后需要再加 attackerCombat.HitstopTimer / targetCombat.HitstopTimer）

    // ② 受击反应参数（从攻击方配置读，DNF 是攻击方配置驱动）
    // int hitStunTime = attackInfo.hitStunTime;  // 僵直时长
    // int upForce = attackInfo.upForce;           // 浮空力
    // int backForce = attackInfo.backForce;       // 击退力
    // int damageAct = attackInfo.damageAct;        // 0无/1僵直/2倒地

    // ③ 扣血
    var targetNum = target.GetComponent<LSNumericComponent>();
    targetNum.Add(NumericType.Hp, -(FP)50);

    Log.Info($"[Combat] 命中！target HP={targetNum.Get(NumericType.Hp)} hitstun={hitstunMs}ms");
}
```

## 7. Route B 状态标记（视图层用）

| 实体 | 标记字段 | 含义 | 视图层怎么用 |
|------|---------|------|-------------|
| LSCombatComponent | `LastHitstunTimer` | 上帧硬直值 | `Last==0 && Cur>0` = 刚被击中 → 播受击动画/特效 |
| LSCast | `JustStarted` | 本帧刚 OnCast | true → 播技能起手特效 |
| LSCast | `JustHit` | 本帧刚命中 | true → 播命中火花/音效 |
| LSCast | `JustFinished` | 本帧刚结束 | true → 清理技能特效 |
| LSBuff | `JustAdded` | 本帧刚添加 | true → 播 Buff 图标/特效 |
| LSBuff | `JustRemoved` | 本帧刚移除 | true → 移除 Buff 图标/特效 |

标记设/清规则：**LSUpdate 末尾设 true，下一帧 LSUpdate 开头清 false**。视图层 IUpdate（在 lockstep tick 之间跑）读到 true 就表现。

**实现记录（2026-08-17）**：
1. **攻击改动画帧驱动**（原阶段3的"按住凭空盒"删除）：按 J 点按 → 缓冲 → 起手播 kneekick → 帧 1-3（有 attackBoxes）激活攻击盒，帧 0/4 无盒=前摇/收招无判定；播完回默认动画。
2. **多盒落地**（用户指出）：CurrentHurtBox/CurrentAttackBox 单 AABB → CurrentHurtBoxes/CurrentAttackBoxes 列表；受击盒走 damageBoxes 数组（旧 JSON 回退单数 damageBox）；CheckAttack 双层循环（我的每攻击盒 × 对方每受击盒）。
3. **新 AnimId**：Attack1=3（kneekick.json）、Hurt=4（damage.json）；LSAnimClipRegistrar 注册。
4. **不连发**（用户定案）：LSInputComponent.LastButton 沿检测，按住只触发一次；缓冲窗口 300ms。
5. **组件挂载顺序**（Id 序 = LSUpdate 序）：Input < Anim < Numeric < Combat < Buffer < Hitbox——Combat 先记上帧值，命中写在 Hitbox（后跑），视图渲染帧能看到 last=0/cur>0 的"刚被击中"边沿。
6. 临时常量：伤害50 / 硬直500ms / 缓冲300ms / 取消帧3——阶段4 attack.json 化。
7. **视图层锚点修复**（验证时发现：攻击起手角色左漂 0.81 单位）：`imagePos` 锚定 DNF 帧画布，Sprite 是紧致内容框，旧代码 `localPosition=imagePos/100` 丢了 `NpkSprite.X/Y` 内容偏移项（Idle/Move 各帧 X 恰好接近所以没暴露，膝踢 X=289 暴露）。修复：`LSAnimResComponent.FrameOffsets`（建图集时按校准帧=idle首帧算相对修正，8 字节/精灵）+ 摆位 `(imagePos+offset)/100`。Idle 零变化，膝踢/down.ani 回到真实相对锚定。详见 `Notes/dnf源码研究/02-坐标系与包围盒-总结.md` §2.1。
