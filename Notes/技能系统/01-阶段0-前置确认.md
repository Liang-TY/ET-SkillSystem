## 1. 确认 aabb / collision 包

### 1.1 查存在性

```bash
# 找这俩包
ls Packages/cn.etetet.aabb/
ls Packages/cn.etetet.collision/
```

如果不存在——需要新建。aabb 包提供 AABB 结构体 + 相交检测；collision 包提供宽相遍历（暴力双循环：遍历所有 LSUnit 检查 AABB 相交）。这俩是纯逻辑包（Model/Share），用 TrueSync 定点数，不含 ECS 组件，只是工具类。阶段 0 先确认存在 + API；若缺失，按下面 API 新建。

### 1.2 查 API

文档假设的 API：

```csharp
// cn.etetet.aabb
public struct AABB { public TSVector Min, Max; }
public static class AABBUtil {
    public static AABB FromCenter(TSVector center, TSVector halfExtents);
    public static bool Intersects(AABB a, AABB b);
}

// cn.etetet.collision
public static class CollisionSystem {
    public static void Query(AABB box, List<LSUnit> results);
}
```

实际包里可能命名不同（比如 `Aabb` 不是 `AABB`，或方法名不一样）。**读实际源码，记下真实 API**，后续阶段的代码要按真实 API 调。

### 1.3 验证

写个临时测试：构造两个相交的 AABB，`Intersects` 返回 true。Log 打出来确认。

## 2. 建 cn.etetet.skill 包骨架

### 2.1 目录结构

```
Packages/cn.etetet.skill/
├── package.json              # 依赖：core, sourcegenerator, truesync, lsentity, aabb, collision, lockstep, npkparser
├── Runtime/
│   └── ET.Skill.asmdef       # 程序集名 ET.Skill（纯框架代码，先空）
├── Scripts/
│   ├── Model/Share/AssemblyReference.asmref      → { "reference": "ET.Model" }
│   ├── Hotfix/Share/AssemblyReference.asmref     → { "reference": "ET.Hotfix" }
│   ├── ModelView/Client/AssemblyReference.asmref → { "reference": "ET.ModelView" }
│   └── HotfixView/Client/AssemblyReference.asmref→ { "reference": "ET.HotfixView" }
└── DotNet~/
    └── ET.Skill.csproj       # 服务端编译（引用 truesync/lsentity/aabb/collision/lockstep 的 DotNet~ 项目）
```

### 2.2 package.json

```json
{
  "name": "cn.etetet.skill",
  "version": "1.0.0",
  "dependencies": {
    "cn.etetet.core": "1.0.0",
    "cn.etetet.sourcegenerator": "1.0.0",
    "cn.etetet.truesync": "1.0.0",
    "cn.etetet.lsentity": "1.0.0",
    "cn.etetet.aabb": "1.0.0",
    "cn.etetet.collision": "1.0.0",
    "cn.etetet.lockstep": "1.0.0",
    "cn.etetet.npkparser": "1.0.0"
  }
}
```

### 2.3 关键：asmdef 引用要加到 lockstep 的 asmdef

skill 的代码会编进 `ET.Model`/`ET.Hotfix` 等共享程序集（通过 asmref）。**不需要改 lockstep 的 asmdef**——asmref 机制是"skill 包的 Scripts/ 文件夹贡献代码到游戏的共享程序集"，lockstep 包感知不到 skill 的存在。

但如果 skill 包有独立的 `Runtime/ET.Skill.asmdef`（纯框架工具代码，如 LSShapeData 这种不依赖 ECS 的结构体），那需要在 `ET.Model`/`ET.Hotfix` 的 asmdef 里加引用 `ET.Skill`。先建空骨架，编译跑通再说。

### 2.4 验证

skill 包建好后，Unity 刷新，编译通过，无报错。没写任何逻辑代码，只是个空壳。
