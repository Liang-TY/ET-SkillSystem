## 1. Route B 轮询机制（统一说明）

**不做**：`EventSystem.Publish(CastHit)` + 视图订阅（回滚重放会重复触发）。

**做法**：视图组件（`IUpdate`，Unity 帧跑）每帧读逻辑实体的状态标记/字段，跟上一次缓存的值 diff，变了才表现。

### 三种检测模式（2026-08-18 定案，实测验证）

| 模式 | 适用场景 | 机制 | 状态 |
|---|---|---|---|
| **① Just\* 布尔标记** | 事件型（"这个瞬间发生了"）：技能起手/命中/结束、Buff 出现/消失 | 逻辑帧内设 true → 下帧 LSUpdate 开头清 false → 视图窗口（~3 渲染帧）读到 true 触发 | ✅ 可靠 |
| **② 视图侧缓存 diff** | 值变型（"这个值变了，变了多少"）：伤害数字、受击闪白 | 视图组件自己缓存上一帧值（如 LastHp 字典），跟当前持久值比较 | ✅ 可靠 |
| **③ 逻辑直驱** | 状态型（"进入这个状态了"）：受击动画、回默认动画、弹位置 | 逻辑层直接调 Play()/设 Position，视图只负责渲染（零检测） | ✅ 可靠 |
| ❌ 逻辑侧数值边沿 | ~~LastHitstunTimer==0 && HitstunTimer>0~~ | 逻辑帧和视图在**同一个 Unity Update 回调**里跑，逻辑先执行覆盖"上一帧值"，视图永远读到覆盖后的值 | **不可用** |

**❌ 为什么逻辑侧数值边沿不可用（2026-08-18 诊断实证）**：

```
逻辑帧 N：Combat 开头 LastHitstunTimer=0，Hitbox 后段 HitstunTimer=500
          （帧 N 结束：Last=0, Hitstun=500 —— 边沿存在！）
渲染帧：  还没来得及读……
逻辑帧 N+1（同一 Unity Update 紧跟着跑）：Combat 开头 LastHitstunTimer=500 ← 覆盖！
          HitstunTimer -= 50 → 450
视图 Update：读到 Last=500, Hitstun=450 → 边沿检测永远失败
```

**修复方式**：需要"刚被打"检测时，要么用 Just\* 标记（逻辑帧内设 true），要么用视图侧 HP diff（持久值不会被覆盖）。当前受击闪白用的是 HP diff（`hp < lastHp` → 红闪 150ms）。

## 3. 血条 UI

- 视图组件读 `numeric.Get(Hp)` / `Get(MaxHp)`，算比例 → 设 `Image.fillAmount`。
- 血条跟随 unit（世界坐标 → 屏幕坐标，或挂在 unit 物体上偏移头顶）。
- 单纯读取，不参与逻辑。

---

## 4. 伤害数字

- 视图组件每帧读 `numeric.Get(Hp)`，跟上一帧缓存比，减了就飞一个伤害数字（差值 = 伤害量）。
- 数字 prefab + Tween（往上飘 + 淡出）。
- 对象池管理。

---

## 5. 特效（prefab）

- 技能起手/命中特效：粒子或序列帧 prefab，YooAsset 加载，对象池。
- 在标记 diff 触发时 `Instantiate`（或从池取），播完 `Recycle`。

---

## 6. 注意

- **标记的时效**：逻辑层标记在 LSUpdate 开头清、末尾设。视图 IUpdate 在 lockstep tick 之间跑（可能一帧 Unity 跑多次逻辑，或多个 Unity 帧跑一次逻辑）。所以视图读到 true 就立刻表现，不要等"下一帧"——因为逻辑层下一个 tick 开头就清了。
- **顿帧期间的视图**：顿帧只冻结逻辑层动画/Cast 推进，视图层的 SpriteRenderer 已经被设到当前帧 sprite 了（顿帧前最后一帧），视觉上是"卡住"——这正是顿帧要的效果。视图层不需要额外处理。

**~~遗留问题（2026-08-18）~~ 已解决**：受击闪白的边沿检测（LastHitstunTimer==0 && HitstunTimer>0）在视图中不触发——
**根因**：逻辑帧和视图更新在同一个 Unity Update 回调里跑，逻辑先执行（Combat 递减 LastHitstunTimer），视图后读到的永远是递减后的值（last=500, hitstun=450），0→500 的边沿帧被跳过。
**修法**：改用 HP 下降检测（`hp < lastHp`）——HP 是持久值不会被下一帧覆盖，跟伤害数字共用同一个 diff 点。
