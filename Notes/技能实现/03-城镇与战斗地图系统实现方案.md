# 城镇与战斗地图系统实现方案

> 实例四：实现 DNF 同款的"选角色→进城镇→选地图→进战斗地图"流程。
> 数据源：`E:\Projects\cs\dnforigin\pvf源码提取部分\pvf\` 的 town/、dungeon/、map/ 三目录。
> 原始考察报告：`Notes\dnf源码研究\原始笔记\R6-T/D/M/G-*.md`
> 新会话必读：§1 总体流程 → §2 城镇设计 → §3 战斗地图设计 → §4 瓦片与碰撞 → §7 进度
>
> **架构决策（2026-08-22 用户定案）**：
> - 服务器在战斗中**纯中继**（只收输入帧→广播→存帧历史，**不模拟**——DNF 同款）
> - 哈希校验：**客户端定期上报哈希→服务器比对→不一致广播回滚指令**（异步校验，不阻塞）
> - 怪物创建：**只有客户端建**（从同一份 room.Init 代码，服务器不跑）
> - 城镇：MMO 模式（客户端权威+服务器纯转发），不用锁步
> - Unity 场景：**城镇和战斗共用 Game.unity**（全运行时动态创建，场景文件只需 Camera+Light）

## 1. 总体流程

### 1.1 全链路（客户端+服务端）

```
┌─ 登录 ──────────────────────────────────────────────────────────────────┐
│ 客户端: Login → Realm → Gate → PlayerId                                 │
│ 改动: LoginFinish 后不开 UILSLobby，改为发 C2G_EnterTown                │
└────────────────────────────────────────────────────────────────────────┘
         ↓
┌─ 进城镇 ────────────────────────────────────────────────────────────────┐
│ 服务端: Gate 转发 → TownScene 纤程                                      │
│         TownScene: 加入成员列表，广播 T2C_PlayerEnterTown                │
│         Player 实体: AddComponent<PlayerTownComponent>                   │
│ 客户端: SceneChangeTo("Town")                                           │
│         加载 Town 资源（瓦片+装饰物+角色动画）                            │
│         创建 TownPlayerComponent（本地权威移动，WASD）                    │
│         （sync=on 时：创建远端角色管理器，插值移动）                       │
└────────────────────────────────────────────────────────────────────────┘
         ↓
┌─ 城镇中 ────────────────────────────────────────────────────────────────┐
│ 客户端: WASD 自由走动（非锁步，客户端权威）                               │
│         位置同步（可选，默认关）：                                       │
│           移动中每 200ms / 静止每 1000ms 报位置+朝向                     │
│           位置没变跳过，停止移动时发最终包                                │
│ 服务端: TownScene 收到位置包 → 转发给成员列表里其他所有人                  │
│         （不模拟、不校验，纯中继站）                                      │
└────────────────────────────────────────────────────────────────────────┘
```

### 1.2 进战斗（含纤程转移完整时序）

```
客户端                                     服务端
──────                                     ──────
按 N 键
  → 记住当前城镇位置
    （TownPlayerComponent.LastTownPosition）
  → 发 C2G_Match { MapId }
                                           Gate 收到 C2G_Match
                                             ① 通知 TownScene:
                                               移除该玩家，广播"XX 离开"
                                             ② Player 实体:
                                               RemoveComponent<PlayerTownComponent>
                                               （Gate 从此不再路由 ITownMessage 到城镇纤程）
                                             ③ 走现有 Match 流程:
                                               Match → Map 纤程 → 创建 RoomRoot 纤程
                                             ④ Player 实体:
                                               AddComponent<PlayerRoomComponent>
                                               .RoomActorId = 新房间的 ActorId
                                               （Gate 从此路由 IRoomMessage 到战斗纤程）
       ↓
收到 Match 成功（Match2G_NotifyMatchSuccess）
  → SceneChangeTo("Battle")
      RemoveComponent<Room>()（清城镇的全部组件）
      AddComponent<Room>() Name="Battle"
      await LoadSceneAsync("Game.unity", Single)
      await LSAnimClipRegistrar.RegisterAll()
      await SkillContentLoader.Load()
      await MapResourceLoader.Load(MapId)
        ← 加载瓦片贴图+装饰物+碰撞矩阵
      发 C2Room_ChangeSceneFinish
       ↓
                                           RoomRoot 收到 Finish
                                             → 组 Room2C_Start
                                               { StartTime, UnitInfo, MapId }
                                             → 【不跑 room.Init()！纯中继不模拟】
                                             → 广播 Room2C_Start
       ↓
收到 Room2C_Start
  → room.Init(unitInfos, mapId)
    ← 客户端创建锁步世界（唯一模拟方）
    ← 创建玩家+按地图配置创建怪物+碰撞矩阵进快照
  → AddComponent<LSClientUpdater>（预测回滚帧循环）
```

**纤程转移期间 Gate 的路由规则**：

| 阶段 | Player 实体上有 | Gate 收到消息路由到 |
|---|---|---|
| 在城镇 | PlayerTownComponent | TownScene 纤程 |
| 按了 N、Match 中（过渡态） | 无 Town、无 Room | 消息走普通 Gate 处理（不做纤程转发） |
| Match 成功 | PlayerRoomComponent | RoomRoot 纤程 |
| 战斗中 | PlayerRoomComponent | RoomRoot 纤程 |
| 回城中（过渡态） | 无 Room、无 Town | 消息走普通 Gate 处理 |
| 回到城镇 | PlayerTownComponent | TownScene 纤程 |

Gate 的路由实现：收到 IActorMessage → 检查 Player 实体上的 Component → 取 ActorId → 按 ActorId 发到对应纤程。移除/添加 Component 就是切换路由的开关。

### 1.3 战斗中（锁步帧循环，服务器纯中继）

```
服务器: 攒各玩家输入帧 → 打包广播 → 存帧历史（不模拟！）
客户端: 收输入帧 → 本地模拟（预测回滚）
        定期（每 ~100 帧）上报世界哈希
服务器: 收哈希比对 → 一致=正常 / 不一致=找最近一致帧→广播回滚指令+帧历史
怪物死亡: 客户端各自模拟（结果一致），无需通知服务器
```

### 1.4 战斗结束→回城镇（含纤程销毁时机，用户纠正 2026-08-22）

**核心原则：RoomRoot 纤程等所有玩家都安全离开后才销毁**（不是战斗一结束就销毁——频繁进出不会频繁创建销毁）。

```
客户端                                     服务端
──────                                     ──────
（锁步模拟中，客户端检测到）
所有怪物 HP ≤ 0
  → 发 C2Room_BattleClear 给服务器
                                           RoomRoot 收到 BattleClear
                                             → 广播 Room2C_BattleEnd
                                             → 停止帧输入收集/广播
                                             → 【此时不销毁纤程！等玩家走完】
       ↓
收到 Room2C_BattleEnd
  → 等 3 秒（客户端播完收场动画）
  → SceneChangeTo("Town")
      RemoveComponent<Room>()（销毁 LSWorld+全部锁步组件）
      AddComponent<Room>() Name="Town"
      await LoadSceneAsync("Game.unity", Single)
      await TownResourceLoader.Load()（瓦片+装饰物，可缓存秒加载）
      TownPlayerComponent.Position = 记住的城镇位置（回原位）
  → 发 C2G_EnterTown（通知服务器"我回来了"）
                                           Gate 收到 C2G_EnterTown
                                             ① Player 实体:
                                               RemoveComponent<PlayerRoomComponent>
                                               （Gate 停止路由到战斗纤程）
                                             ② Player 实体:
                                               AddComponent<PlayerTownComponent>
                                               （Gate 开始路由到城镇纤程）
                                             ③ TownScene: 加入成员列表
                                             ④ 检查: 该房间还有没有玩家
                                               （还有 PlayerRoomComponent 指向此房间？）
                                               → 全走完 → 销毁 RoomRoot 纤程
                                               → 还有人 → 等（他们还在加载/切换中）
```

**为什么等玩家走了再销毁**：
- 纤程创建/销毁有 GC 开销（整个实体树回收）
- 频繁进出战斗 → 如果立即销毁+重建 = 频繁 GC
- 等最后一人离开才拆 = 同一批玩家连续打多把时纤程复用，零创建销毁

### 1.5 服务器纯中继架构（DNF 同款）

| 环节 | 服务器做什么 | 服务器不做什么 |
|---|---|---|
| 输入帧 | 收各玩家输入 → 打包 → 广播 → **存帧历史** | ~~模拟世界~~ |
| 哈希校验 | 收客户端上报的哈希 → **比对** → 不一致广播回滚指令 | ~~自己算哈希~~ |
| 怪物 | 什么也不做（不知道怪物存在） | ~~创建/模拟怪物~~ |
| 战斗结束 | 收客户端上报"怪物全灭" → 广播 BattleEnd | ~~检测怪物 HP~~ |
| 纤程生命周期 | 等所有玩家离开后才销毁 RoomRoot | ~~战斗一结束就销毁~~ |
| 断线重连 | （demo 不做；以后用帧历史重放） | ~~从快照恢复~~ |

### 1.6 room.Init() 拆分（服务器只跑中继部分）

当前 `room.Init()` 做两件事——拆成两半，服务器只跑前半：

```csharp
// ── 前半：中继基础设施（服务器+客户端都跑）──
public static void InitRelay(this Room self, long startTime, int frame = -1)
{
    self.StartTime = startTime;
    self.AuthorityFrame = frame;
    self.PredictionFrame = frame;
    self.FrameBuffer = new FrameBuffer(frame);           // 输入帧存储（服务器存帧历史/广播用！）
    self.FixedTimeCounter = new FixedTimeCounter(startTime, 0, LSConstValue.UpdateInterval);
}

// ── 后半：游戏世界创建（只有客户端跑）──
public static void InitWorld(this Room self, List<LockStepUnitInfo> unitInfos, long startTime, int frame = -1)
{
    self.InitRelay(startTime, frame);
    LSWorld lsWorld = self.LSWorld;
    lsWorld.AddComponent<LSUnitComponent>();
    lsWorld.AddComponent<LSBulletComponent>();
    lsWorld.AddComponent<LSAreaComponent>();
    for (...) LSUnitFactory.Init(lsWorld, unitInfos[i]);  // 创建玩家（含全部战斗组件）
    // + 按 MapDefinition 创建怪物 + 碰撞矩阵
}
```

**服务器为什么不跑后半**：LSWorld/单位/怪物是模拟用的——服务器不模拟就不需要。FrameBuffer 必须保留（输入帧存储/广播/哈希回滚都靠它）。

### 1.7 战斗结束的状态清理（天然不泄漏）

**锁步世界的全部战斗状态都挂在 Room 实体子树上，Room 销毁 = 连根拔起**：

```
Room 实体
├── LSWorld
│   ├── LSUnitComponent
│   │   ├── 玩家 LSUnit
│   │   │   ├── LSNumericComponent（HP！战斗中扣的血）
│   │   │   ├── LSBuffComponent（Burn/Bleed/Freeze！）
│   │   │   ├── LSSkillComponent（技能 CD！）
│   │   │   └── LSCastComponent（正在施放的技能！）
│   │   └── 怪物 LSUnit
│   ├── LSBulletComponent（飞行中的弹）
│   └── LSAreaComponent（区域效果）
└── FrameBuffer（输入帧历史）
```

**切场景清理时序**：
```
BattleEnd → 客户端等 3 秒 → SceneChangeTo("Town")
  → root.RemoveComponent<Room>()
      → Room.Destroy() 递归触发
          → LSWorld.Dispose() → 所有 LSUnit.Dispose() → 所有组件 Dispose()
          → Buff 清了、CD 清了、HP 状态清了、弹清了、区域清了
  → 全部完成后，才创建 Town 组件
```

**城镇和战斗的状态完全隔离**：

| 状态 | 城镇 | 战斗 | 互相影响 |
|---|---|---|---|
| 玩家位置 | TownPlayerComponent.Position | LSUnit.Position | 不会（两个不同组件） |
| 玩家 HP | **城镇不跟踪 HP** | LSNumericComponent | 不会（战斗 HP 随 Room 销毁） |
| 技能 CD | **城镇没有 CD** | LSSkillComponent | 不会（随 Room 销毁） |
| 活跃 Buff | **城镇没有 Buff** | LSBuffComponent | 不会（随 Room 销毁） |

**数值一致性（进战斗前=离开战斗后）**：
```
进战斗:  LSUnitFactory 创建全新玩家 → HP=1000 满血、无 Buff、无 CD
战斗中:  扣血/挂 Buff/起 CD ... （全在 LSWorld 里）
离开:    Room 销毁 → 上面那些全没了
回城镇:  TownPlayerComponent 只有 Position/Forward → 没有 HP/Buff/CD 概念
结果:    每次进战斗都是满状态开局，战斗内变化不带回城镇（DNF 同款行为）
```

**静态注册表不清理（by design）**——AnimConfigRegistry/SkillLoader/SkillSystemConfig 是**只读配置**不是**状态**（像字典/规则书），战斗结束字典还在，下次战斗直接用。

### 1.8 帧同步怪物创建原理（只有客户端建）

```
                                        客户端（唯一模拟方）
                                        room.Init(unitInfos, mapId)
                                          → 创建玩家单位
                                          → 按 MapId 读 MapDefinition
                                          → 创建怪物（配置驱动）
                                          → 碰撞矩阵进快照
                                               ↓
                                        客户端世界（确定性模拟）
```

服务器不创建任何东西——只把 `Room2C_Start` 广播出去（含 MapId），各客户端收到后各自初始化。

## 2. 城镇设计（MMO 模式）

### 2.1 架构

```
客户端 TownScene:
  TownPlayerComponent     自己的角色（客户端权威移动，WASD）
  TownInputComponent      输入采集（WASD → 直接改 Position，不走帧同步）
  TownSyncComponent       位置同步（可选，默认关）
    移动中每 200ms / 静止每 1000ms 报位置+朝向
    位置没变跳过；停止移动时发最终包
  TownRemotePlayerManager 远端角色（sync=on 时，收到包插值移动）
  TownMapViewComponent    城镇视觉（瓦片地面+装饰物）

服务端 TownScene 纤程（轻量，不模拟，常驻不销毁）:
  成员列表 Dictionary<PlayerId, TownPlayerInfo>
  玩家进入: 加入列表 → 广播 T2C_PlayerEnterTown → 给新人发现有成员
  玩家离开: 移除列表 → 广播 T2C_PlayerLeaveTown
  位置包转发: 收到 → 转发给其他所有人（不校验不模拟）
```

**TownScene 常驻**：一个服务器只有一个 TownScene 纤程，启动时创建，不随玩家进出销毁。玩家进来加入列表，走了移除——纤程本身永活。

### 2.2 位置同步协议

```protobuf
// C2T_PositionUpdate  客户端 → 服务器
message C2T_PositionUpdate {
    TSVector Position;
    TSVector Forward;
    bool IsMoving;
}

// T2C_PositionBroadcast  服务器 → 其他客户端
message T2C_PositionBroadcast {
    long PlayerId;
    TSVector Position;
    TSVector Forward;
    bool IsMoving;
}

// T2C_PlayerEnterTown / T2C_PlayerLeaveTown
message T2C_PlayerEnterTown {
    long PlayerId;
    TSVector Position;
    int CharacterId;
}
```

远端角色表现：收到位置包 → 平滑插值过去（~200ms 内走完）；
IsMoving=true 时沿 Forward 外推；IsMoving=false 时停止。

### 4.4 坐标模型定案（2026-08-23，第 6-7 轮沉淀——新会话必读）

**逻辑层不是 3D，是"2D 地面平面 (x,z) + 1D 高度 y"打进一个 TSVector；DNF 的 2.5D 透视全部烘在美术里（格子 16px 宽 × 18.67px 高非正方形），引擎零投影计算。**

| 坐标系 | 维度 | 内容 | 存在于哪 |
|---|---|---|---|
| 逻辑层 TSVector(x,y,z) | 平面+高度 | (x,z)=地面平面（z=纵深，W/S 轴）；y=高度（跳跃/浮空/击飞） | LSWorld，唯一进快照/帧同步 |
| 碰撞网格 (col,row) | 2D | 地面平面俯视量化，**y 故意缺席**（TryMove Y 轴恒通过） | LSCollisionComponent |
| 屏幕 (screenX, screenY) | 2D | `screen = (x, z + y, 0)`——z（纵深）与 y（高度）**叠加在同一根屏幕纵向轴** | 纯视图 |

转换链与规则：
```
按键 → LSInput.V（TSVector2 归一）→ delta=(v.x, vy, v.z × ZCellRatio) → Position
逻辑→网格: col=(x−OriginX)/CellSize，row=(OriginZ−z)/CellSizeZ（row0=贴图顶，z 翻转）
逻辑→屏幕: (x, z+y, 0)；排序 sortingOrder=−(int)(z×100)；不随 z 缩放（billboard）
屏幕→逻辑（点击移动等未来用途）: x=screenX，z=screenY−y
```

由此长出的规则（DNF 同款）：
- **跳跃不改变所站行**（y 只是高度，(x,z) 不动；空中 WASD 仍按行移动）
- **跳不过墙**（网格碰撞只看 (x,z)）
- **渲染前后只看行不看高度**（起跳不会盖到上一行单位头上）
- **影子 = 真身线索**：以后加跳跃/浮空表现，影子画 (x,z)、本体画 (x,z+y)
- **移动手感 = 地面平面格子等速**：z 分量乘 `ZCellRatio`（CellSizeZ/CellSize≈1.167），屏幕上 W/S 比 A/D 快 ~17%（纵深感的来源），斜向同速
- 任何一层自带独立比例（如已废弃的 depthRatio=0.6）都会和其他两层打架——第 6 轮 bug 的全部原理

#### 根因分析（新会话必读）

**DNF 贴图分辨率 ≠ 碰撞网格逻辑分辨率**：
- 碰撞网格：56 列 × 30 行，DNF 逻辑 80px/格 → 逻辑宽 4480px = 44.8 单位
- 实际贴图：896×560px @ 100 PPU → 视觉宽仅 8.96 单位
- **贴图像素只有逻辑网格的 1/5**——DNF 引擎内部会缩放显示，但我们不缩放（原生分辨率）

**当前方案**：碰撞网格跟着贴图走（CellSize = 贴图世界宽 / 格子数），不跟 DNF 逻辑 80px 走。

#### 第 6 轮修复（2026-08-23，叠图上线后三重发现，已改待验证）

**叠图实测结论**（截图+日志 `walkable=869/1680` 与 json 重演完全一致）：

#### 第 5 轮修复（2026-08-23，用户纠正坐标系）

**用户纠正**：W/S 改变的是角色的 Unity **Y 轴**（transform.position.y），不是 Z 轴——**z 始终为 0**。角色在 XY 平面移动（屏幕平面），不是"深度"。
之前"摄像机透视/深度"的分析是错的——W/S 就是屏幕上下移动。

**当前行映射公式**（`LSCollisionComponentSystem.IsBlocked`）：
```csharp
// z 轴反转：row = (OriginZ - z) / CellSize
// z+（W，屏幕上方）→ row 减小 → 靠近贴图顶部（墙区）
// z-（S，屏幕下方）→ row 增大 → 靠近贴图底部（地板）
int row = (int)TSMath.Floor((self.OriginZ - position.z) / self.CellSize);
```

**OriginZ** = `gridHeight × CellSize / 2`（贴图顶部的世界 z）
