## 2. 技能逻辑走读

### 2.1 注册与文件链（全查实测，无一处命中）

grep `bleedingmaster`：`swordman_load_state.nut`、`sqr\character\swordman\` 全树
（`passive_skill_swordman.nut` 无 case 90、appendage/beidong 无）、`sqr\character\JG_SwordMan\`、
`passiveobject\character\swordman\`、`character\swordman\effect\animation\`——全部无命中。

**结论（F3 引擎内置）**：感知半径内"出血状态敌人/友军"的枚举与计数、力量/命中率的动态叠层、
出血抗性减益，全在引擎 appendage 管线内；pvf 侧只有 .skl 数据。**注意本技能的引擎依赖链
是最长的**：状态查询（出血 in-radius）+ 目标计数 + 动态叠层。

### 2.2 机制归纳

```
学得即常驻：
  血气系列技能出血 Lv + col0（出血 debuff 的等级与命中抵抗结算）

  周围 800px 内每个出血状态单位（敌或友军）→ 自身力量 +col1、命中率 +col2（各一层，最多 5 层）
```

## 5. 实现方案草案

⛔ 暂缓——四条缺失能力叠加（本批被动里依赖链最长）：
1. **属性数值无伤害消费链**（力量/攻击力增益无处生效，176 §8）；
2. **状态等级（Lv）系统**（出血 Lv+col0：我们的 BuffDefinition 无等级位，出血命中也不做等级抵抗结算）；
3. **状态抗性系统**（出血抗性 -col3：无抗性数值位，与元素抗性同族缺口）；
4. **目标状态查询 + 计数门面**（R3-A11"命中 N 敌触发 Y"已记档；本技能是其"持续感知版"——
   需每拍枚举半径内带出血 Buff 的单位并计数，属同一立项）。
另涉**命中率**（我方 CheckHit 纯 AABB 相交实测无命中 roll，命中率无数值位）与**阵营判定**
（"敌人或友军"都要数——比 89 更早撞阵营）。
