# 轮间经验（每轮结束后增补，下一轮 agent 必读）

> 目的：把已趟过的确定性结论传给下一轮，避免重复劳动。主循环在每轮验收后增补；
> 子 agent 发现新结论也写进自己文档 §8，由主循环汇集到此。
> 规则：只收**确定性/高置信**结论（实测或多方印证），存疑项不进本文件。

## 通用结论（所有技能适用）

- **L1 · [name2] 不是英文**：本 pvf 的 [name2] 多为中文别名（IceWave 实测 name2="冰刃 · 波动剑"）。
  文档"英文名"一律取 skl 文件名去扩展名。
- **L2 · pushState 参数语义（R1-A3 修正）**：`pushState(job, nut路径, 状态名, 状态号, 技能ID)` ——
  **第 4 参是状态号、第 5 参才是技能 ID**（-1=不绑定特定技能）。bloodboom (229,229) 两值相同造成
  早期误读；实证：GrandWave (27,50)=状态27/技能50，attack.nut (8,-1)=普攻状态8。
  老一代技能的状态号是小数字（6 跳/7 后跳/8 普攻/22 三段斩/24 波动剑/27 大波/50 鬼影闪；
  流心家族 61=架势/62=刺/63=跃/64=升，R2-A9 实证 `UseSkillState(109,64)`），
  与技能 ID 无关。**按技能 ID 反查注册行要 grep 第 5 参位置。**
  ⚠ "状态号=技能号"是错误惯例假设——状态归属必须找到 UseSkillState/SetSkillState 直接证据
  （064 曾把状态 64 误判给十字斩，已勘误）。
- **L3 · 被动对象的攻击信息走自有表**：`sq_GetCustomAttackInfo(obj, N)`（如 103），角色
  `attackinfo\` 下常无对应 .atk——查命中参数别只翻角色目录。
- **L4 · 特效 ani 可能在 zrr_skill 子树**：`passiveobject\zrr_skill\newswordman\animation\`（mod/增强
  系产物）。白名单已加 `passiveobject\zrr_skill\`（见 03 手册 §1.2）。
- **L5 · .ptl 粒子文件**：DnfConfigTranslation 无子命令、游戏无粒子系统。遇到统一记：
  "粒子：翻译缺口+系统缺口，视觉用特效 ani 替代或跳过"。
- **L6 · 状态附加的标准链路**：`sq_SetChangeStatusIntoAttackInfo(attackInfo, 0, ACTIVESTATUS_X, 概率, 等级, 时长)`
  → 映射 `HitReaction.ProcBuffId + ProcChance`（已支持，FreezeBuff/MonsterIceBreath 先例）。
- **L7 · 空占位 ani**：[IMAGE] 路径为空（``）的 ani 是纯时间轴占位（bloodboom overlay、icewave.ani
  均是）——不产 img 需求，视觉由特效层承担，直接标注跳过。
- **L8 · sks 数值格式速记**：[level property] 数据行 (类型, 基准值, 每级成长) 三元组；
  模板行里的 <int>/<float1>/<float2> 对应各列。向量读法若无 nut 印证，公式标"推断"。
- **L9 · 被动对象 .obj 结构（首个完整样本 064-GoreCross）**：`[basic motion]`(相位1 动画) +
  `[attack info]`(相位1 命中) + `[etc motion]` 序列(后续相位，各配 `[etc attack info]`) +
  `[add object effect]`(纯视觉叠加层) + `[object destroy condition]`。多相位 PO 在我们侧
  映射为**多个 Area 顺序创建**（每相位独立 HitReaction，单 Area 表达不了参数切换）。
  PO 的 atk 在 `passiveobject\character\swordman\attackinfo\`。
- **L10 · .ani 触发点可能越出动画时长**：算 Area/PO 触发时机时要把"帧号×帧时长累计"与
  动画总长对表（064 案例：PO 相位2 落在 1390ms > 动画 1330ms，帧号驱动到不了，须时间驱动）。
- **L11 · 角色动画名 ≠ 技能名是常态**（R1-A1）：上挑实际动画是 `up_Attack.ani`（etc 槽 202）——
  按技能名搜不到动画时，用 `swordman_header.nut` 常量值对 .chr `[etc motion]` 槽位。
- **L12 · [none effect add] 官方 .als 也存在**（R1-A1，up_attack.ani.als 实证）——非 mod 专属，
  AlsParser 已兼容，见到别惊讶。
- **L13 · PO .obj 命名惯例**（R1-A1）：`xxxsub.obj` = 命中判定型 PO；etc motion 后无
  etc attack info 配对 = 纯视觉层（不构成多相位命中，不按 L9 拆相位）。
- **L14 · 通用特效在 Common\CommonEffect\**（R1-A1，银光落刃 EarthQuake 系）：NPK 推导必须按
  .ani 内完整 img 路径走，跨目录复用（Monster 贴图借给角色特效）是常态，别想当然按技能树推。
- **L15 · GRAPHIC EFFECT 工具已支持**（R1-A3 实测修正）：AniParser.cs:140 → json `graphicEffect`
  字段（1-4），游戏侧 AnimClipData.cs:22 消费（1=LINEARDODGE 加法混合发光）——README"未识别节"
  清单与手册 §2.1 描述滞后，**见到 [GRAPHIC EFFECT] 不是缺口**。064 文档相应表述按此修正理解。
- **L16 · 鬼剑士角色动画必需 img 普遍为零**（R1-A3 再次实证）：角色 .ani 的图集引用全是
  `sm_body%04d.img` 模板 → 单图集 `sm_body0000.img`（已入库，bloodboom 帧号 78+ 正常渲染在案）。
  角色侧"缺失 img"只可能出现在特效层。
- **L17 · growtype→职业 实测映射**（R1-A4 四点锚定：FlowMind=1/Kalla=2/bloodyrave=3/IceWave=4）：
  **1=剑魂 2=鬼泣 3=狂战士 4=阿修罗 5=剑影**，0=共通。skl 的 [skill fitness growtype] 值即职业，
  职业列可低成本直读（不再只靠常识猜）。
- **L18 · 草案 ID 号段协调**（R1-A4 起记账）：多 agent 并行写实现草案会各自分配新 SkillId/AnimId/
  BuffId/ActionId 号——**必须按批号顺延避免冲突**。当前占用：SkillIds 到 17（A6/A7/A9 均从 15 起已互撞，无妨）、AnimIds 到 76（A6 占 59-76 含 66-69 预留、A7 占 59-72、A9 占 59-67——互撞无妨）、
  BuffIds 到 8、ActionIds 到 11、AreaIds 到 4、BulletIds 到 3、NumericType 到 1007。
草案撞号一律无妨，实现期统一重排；新批次从 SkillIds 34 / AnimIds 178 / BuffIds 18 / AreaIds 39 / ActionIds 15 / BulletIds 8 顺延（R5-B5 到 AnimIds 177/AreaIds 38/BuffIds 17/BulletIds 7）（R4-B2 到 AnimIds 151/BuffIds 19；R5-B3 到 AnimIds 160/BuffIds 16/AreaIds 31/BulletIds 6）  （R2-A10 用到 SkillIds 18/AnimIds 75；R3-A14 用 SkillIds 19-22/AnimIds 77-103/BuffIds 9/AreaIds 9-15）。
- **L19 · 多段连段的"命中重置"已落地**（R1-A4 修正认知）：DNF flag100/101+resetHitObjectList 对应
  我们的 `ctx.ClearHitTargets()` 段间调用——**段间多段（连段每段重新可命中）不算延后**；
  延后的只是"同段内定时自动重置"。里鬼/月光/三段这类连段用单 cast 子状态机即可表达。
  **R2-A8 反例修正**：4/8 段的"同段定时多段"可用**双同心 Area 的 Tick（无去重特性）直接表达**——
  多段不全在延后档，§6.3 应分"连段段间（已通）/同段定时（Area Tick 可表达）/穿透重置（Bullet 需字段）"三档。
- **L20 · PO 24370 是共享打击 PO**（R1-A4 发现，R3-A15 修正）：`ap_bloodboom.nut` 是空文件；
  本 pvf 中 24370 **并非纯引擎内置**——passiveobject.lst 被 mod 指向 `script_sqr_nut_qq506807329/.../
  qq506807329new_swordman_24370.obj` + `sqr\common_object\share_obj\swordman\*.nut` 六回调
  （load_state 8-13 行注册），其 [etc motion]/[etc attack info] **0 基直读无错位**。
  bloodboom/百剑/里鬼/鲜血暴掠/鬼斩炼狱都写包复用，按首 dword 分流。01§4 记载待收尾修正。
- **L21 · .skl [level property] 模板行解码法**（R1-A2 三例交叉验证）：模板行占位符顺序 ↔ 向量行
  一一对应；**向量首值非 -1**（如 `(8,8)`、`(1,1)`）→ 指向 **static data 槽**而非 level 列
  （HopSmash static[8]=2/[9]=3、VaneSlash static[1]=3 吻合）。064 当年 12 列全标未考证，可按此法回补。
  **R2-A6 细化**：向量实为 `(源, 索引, 系数)`——源 -1=取 level info 列、正值=取 static data 槽；
  021-IceWave §5 的"基准+成长"读法按此修正理解（其数值建议不变，推断标注照旧）。
  **R2-A10 补充**：源 **-2 也是 level info 列引用**（022 双列模板 + 066 static 对位双印证）——
  与 A6 的"-1=level 列"表述并存，-1/-2 细微差异未考证（疑系数语义不同），按各文档自证读法用，收尾统一。
  **R3-A11 新见**：源 **-4**（79 出血攻击力列，语义未考证）。已知源值：-1/-2=level 列、正值=static 槽、-4/-6=未解（R3-A15 再见 -6）。共性简化：按住蓄力输入缺失，蓄力技 demo 统一瞬发（R3-A15 四技全 🔶 的共性）。
- **L22 · atk 负 push = 拉拽语义**（R2-A9 鬼影鞭实证 push=-200）：命中把敌人**拉近**——
  我们 `HitReaction.KnockbackX` 负值经 LaunchOwner 天然反向，**钩锁/拉拽类技能零新机制可直接还原**。
- **L23 · 超长 DELAY 悬停帧的真相**（R2-A9 实证）：`delay=10000ms` 不是真播 10 秒——引擎按
  命中/落地/状态切换**事件推进**。直译进我们动画系统会永不播完；翻译工具需钳制（缺口在案），
  或消费侧约定"末帧超长 delay=待事件"。

- **L24 · LaunchOwner 击退方向语义差异**（R2-A7 上报，主循环单列）：我们的击退是**径向推离**
  （以施法者为中心向外），DNF 官方是**施放者面朝方向**——打身后敌人时两者方向相反，
  影响所有方向性击飞/击退技能，实现期需统一决策（LaunchOwner 加朝向模式或约定仅正面命中）。

  ```bash
  import re,io

  for i,m in enumerate(re.findall(r'\[FRAME(\d+)\](.*?)(?=\[FRAME\d+\]|\$|\\Z)',t,re.S)):
      d=re.search(r'\[DELAY\][^0-9-]*(-?\d+)',m[1]); f=re.search(r'\[SET FLAG\][^0-9-]*(-?\d+)',m[1])
      print(m[0],'delay=',d.group(1) if d else '?','flag=',f.group(1) if f else '-','ATKBOX' if 'ATTACK BOX' in m[1] else '')
  "
  ```
