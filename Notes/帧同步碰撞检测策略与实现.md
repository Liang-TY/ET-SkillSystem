# 帧同步碰撞检测与策略 — 格斗动作游戏实战指南

## 一、确定性碰撞检测

### 为什么需要确定性

帧同步中，所有客户端从相同输入必须产生相同结果。技能碰撞判定影响伤害、Buff 命中等核心逻辑，属于逻辑层。

如果客户端 A 判定"技能命中"而客户端 B 判定"未命中"，状态就分叉，后续所有帧都不同步。

**只有纯视觉表现**（命中特效、屏幕震动）不需要确定性，那些在视图层做。

### 怎么实现确定性

| 要点 | 做法 |
|------|------|
| 数学运算 | 使用 TrueSync 的 FP（定点数）和 TSVector，不用 float |
| 坐标系 | 所有位置、尺寸用 FP/TSVector，与帧同步实体一致 |
| 检测顺序 | 固定遍历顺序（按 ID 排序），不依赖字典遍历 |
| 无随机 | 碰撞检测本身不应涉及随机数 |
| 跨平台 | 避免 BitConverter、IntPtr 等平台相关操作 |

### AABB 确定性检测示例

```csharp
// 6 次 FP 比较，完全确定性
public static bool Intersects(AABB a, AABB b)
{
    return a.Min.x <= b.Max.x && a.Max.x >= b.Min.x
        && a.Min.y <= b.Max.y && a.Max.y >= b.Min.y
        && a.Min.z <= b.Max.z && a.Max.z >= b.Min.z;
}
```

## 二、碰撞检测的两层架构

| 层 | 职责 | 类比 | 包 |
|----|------|------|---|
| **窄相（Narrow Phase）** | 精确判定两个对象是否相交 | 量两栋��的墙是否挨着 | `cn.etetet.aabb` |
| **宽相（Broad Phase）** | 快速排除不可能碰撞的对象对 | 先看哪两栋楼在同一街区 | `cn.etetet.collision` |

上层技能系统只调用 collision 包，collision 包内部用 aabb 做精确检测。

```
技能系统（业务层）
  ↓ 调用
collision 包（宽相，决定检测谁）
  ↓ 调用
aabb 包（窄相，判定是否相交）
  ↓ 依赖
truesync（定点数数学）
```

### 为什么分两个包

| 原因 | 说明 |
|------|------|
| **职责不同** | AABB 是纯数学，遍历策略是数据结构，变化频率不同 |
| **依赖方向** | collision → aabb，反过来不依赖 |
| **可替换** | 换宽相策略只改 collision 包，aabb 不动 |
| **复用** | aabb 包可被其他项目复用，不绑定特定遍历策略 |

### AABB.cs — 核心结构体

```csharp
using TrueSync;

namespace ET
{
    // 轴对齐包围盒，零 GC
    [Serializable]
    public struct AABB
    {
        public TSVector Min;
        public TSVector Max;

        public TSVector Center => (Min + Max) * FP.Half;
        public TSVector Size => Max - Min;
        public TSVector HalfExtents => (Max - Min) * FP.Half;

        // 点包含
        public readonly bool Contains(TSVector point)
        {
            return point.x >= Min.x && point.x <= Max.x
                && point.y >= Min.y && point.y <= Max.y
                && point.z >= Min.z && point.z <= Max.z;
        }
    }
}
```

### AABBUtil.cs — 静态工具

```csharp
using TrueSync;

namespace ET
{
    public static class AABBUtil
    {
        // === 构造 ===

        // 从最小最大点
        public static AABB FromMinMax(TSVector min, TSVector max)
            => new AABB { Min = min, Max = max };

        // 从中心 + 半尺寸
        public static AABB FromCenter(TSVector center, TSVector halfExtents)
            => new AABB { Min = center - halfExtents, Max = center + halfExtents };

        // === 检测 ===

        // AABB 相交
        public static bool Intersects(AABB a, AABB b)
        {
            return a.Min.x <= b.Max.x && a.Max.x >= b.Min.x
                && a.Min.y <= b.Max.y && a.Max.y >= b.Min.y
                && a.Min.z <= b.Max.z && a.Max.z >= b.Min.z;
        }

        // A 包含 B
        public static bool Contains(AABB outer, AABB inner)
        {
            return outer.Min.x <= inner.Min.x && outer.Max.x >= inner.Max.x
                && outer.Min.y <= inner.Min.y && outer.Max.y >= inner.Max.y
                && outer.Min.z <= inner.Min.z && outer.Max.z >= inner.Max.z;
        }

        // === 变换 ===

        // 合并两个 AABB
        public static AABB Merge(AABB a, AABB b)
            => new AABB
            {
                Min = TSVector.Min(a.Min, b.Min),
                Max = TSVector.Max(a.Max, b.Max)
            };

        // 扩展尺寸
        public static AABB Expand(AABB box, TSVector expansion)
            => new AABB { Min = box.Min - expansion, Max = box.Max + expansion };
    }
}
```

### LSBoxComponent.cs — 帧同步碰撞组件（可选）

```csharp
// 挂在 LSUnit 上，定义角色的碰撞体
[ComponentOf(typeof(LSUnit))]
[MemoryPackable]
public partial class LSBoxComponent : LSEntity, IAwake, ISerializeToEntity
{
    [MemoryPackOrder(0)] public TSVector Offset;      // 相对角色位置的偏移
    [MemoryPackOrder(1)] public TSVector HalfExtents; // 半尺寸
    [MemoryPackOrder(2)] public int BoxType;          // 0=身体, 1=攻击, 2=受击
}

// System 中计算世界坐标 AABB
public static AABB GetWorldAABB(this LSBoxComponent self)
{
    TSVector center = self.GetParent<LSUnit>().Position + self.Offset;
    return AABBUtil.FromCenter(center, self.HalfExtents);
}
```

## 四、宽相 — 遍历策略详解

### 策略对比

| 策略 | 复杂度 | 适用场景 | 格斗游戏适用度 |
|------|--------|---------|--------------|
| **暴力双循环** | O(n²) | 对象少（<100） | 格斗对战：首选 |
| **扫掠裁剪（SAP）** | O(n·k) | 对象均匀移动，一维排序 | DNF 普通战斗 |
| **空间哈希** | O(n) | 固定场景，对象均匀分布 | DNF 刷图，帧同步 RTS |
| **八叉树** | O(n·log n) | 3D 开放世界，分布不均匀 | 不推荐（见下文分析） |
| **BVH** | O(n·log n) | 大量静态+少量动态 | 不推荐 |

### 4.1 暴力双循环

**原理**：遍历所有对象对，逐一做 AABB 检测。

```csharp
public static void DetectAll(LSUnit[] units, List<(int, int)> results)
{
    for (int i = 0; i < units.Length; i++)
    for (int j = i + 1; j < units.Length; j++)
    {
        AABB a = units[i].GetWorldAABB();
        AABB b = units[j].GetWorldAABB();
        if (AABBUtil.Intersects(a, b))
            results.Add((i, j));
    }
}
```

**性能估算**（格斗对战）：

```
2 角色 × 每人 5 box = 10 个 box
检测次数 = 10 × 9 / 2 = 45 次
4 角色 × 每人 5 box = 20 个 box
检测次数 = 20 × 19 / 2 = 190 次
```

20fps 下每秒不到 4000 次 AABB 检测，完全无压力。

**适用**：格斗对战（街霸、拳皇）、DNF 普通战斗。

### 4.2 扫掠裁剪（Sweep and Prune）

**原理**：按某个轴排序，只检查轴上重叠的对象对。

```
排序前：  C A B D E     → 不确定谁和谁近
排序后：  A B C D E     → 相邻的才可能碰撞

A────B  C──────D  E
     ↑重叠  ↑重叠     只检测 (A,B) 和 (C,D)
```

**DNF 横版特别适合**：角色主要在 X 轴移动，Y 轴跨度小，Z 轴几乎没用。按 X 轴排序一次就能排除 90% 的不相关对。

```csharp
public static void DetectSAP(LSUnit[] units, List<(int, int)> results)
{
    // 1. 按 minX 排序（确定性：按 ID 稳定排序）
    int[] sorted = Enumerable.Range(0, units.Length)
        .OrderBy(i => units[i].GetWorldAABB().Min.x)
        .ThenBy(i => i)  // 固定顺序保证确定性
        .ToArray();

    // 2. 扫掠
    for (int i = 0; i < sorted.Length; i++)
    {
        AABB a = units[sorted[i]].GetWorldAABB();
        for (int j = i + 1; j < sorted.Length; j++)
        {
            AABB b = units[sorted[j]].GetWorldAABB();
            if (a.Max.x < b.Min.x) break;  // X 轴不再重叠，后续更远，直接跳过
            if (AABBUtil.Intersects(a, b))
                results.Add((sorted[i], sorted[j]));
        }
    }
}
```

**性能估算**（DNF 刷图）：

```
200 个 box，X 轴均匀分布
每对象平均只和 5-10 个邻居重叠
总检测 ≈ 200 × 8 / 2 = 800 次
比暴力的 19,900 次少 96%
```

### 4.3 空间哈希

**原理**：把世界划分成等大的格子，每个对象注册到覆盖的格子。只查同一个格子里的对象。

```
世界
┌──┬──┬──┬──┬──┐
│  │B │  │  │  │    A 在格子(0,0)
│A │  │  │  │  │    B 在格子(1,0)
├──┼──┼──┼──┼──┤    A、B 不同格 → 不检测
│  │  │ C│ D│  │    C、D 同格(2,1) → 检测
│  │  │  │  │  │
└──┴──┴──┴──┴──┘
```

**核心实现**：

```csharp
// hash key 计算：不管世界多大，用质数异或
static long Hash(int x, int y, int z)
    => (long)x * 73856093 ^ (long)y * 19349663 ^ (long)z * 83492791;

public struct SpatialHash
{
    public int CellSize;
    public Dictionary<long, List<int>> Grid;

    public void Clear() { Grid.Clear(); }

    public void Insert(int id, AABB box)
    {
        int minX = FP.FloorToInt(box.Min.x) / CellSize;
        int maxX = FP.FloorToInt(box.Max.x) / CellSize;
        // y, z 同理

        for (int x = minX; x <= maxX; x++)
        for (int y = minY; y <= maxY; y++)
        for (int z = minZ; z <= maxZ; z++)
        {
            long key = Hash(x, y, z);
            if (!Grid.TryGetValue(key, out var list))
            {
                list = new List<int>();
                Grid[key] = list;
            }
            list.Add(id);
        }
    }

    public void Query(AABB box, HashSet<int> results)
    {
        for (int x = minX; x <= maxX; x++)
        for (int y = minY; y <= maxY; y++)
        for (int z = minZ; z <= maxZ; z++)
        {
            long key = Hash(x, y, z);
            if (Grid.TryGetValue(key, out var list))
                foreach (int id in list)
                    results.Add(id);  // HashSet 自动去重
        }
    }
}

// 使用
var hash = new SpatialHash { CellSize = 5 };  // FP 精度下的格子大小
hash.Clear();
for (int i = 0; i < units.Length; i++)
    hash.Insert(i, units[i].GetWorldAABB());

// 技能 hitbox 查询受影响的目标
var hits = new HashSet<int>();
hash.Query(skillBox, hits);
foreach (int id in hits)
    if (AABBUtil.Intersects(units[id].GetWorldAABB(), skillBox))
        ApplyDamage(units[id]);
```

**性能估算**（帧同步 RTS，500 单位）：

```
暴力：500 × 499 / 2 = 124,750 次
空间哈希：假设每格 10 个，每对象查 2-3 格 → 500 × 3 × 10 / 2 ≈ 7,500 次
减少 94%
```

### 4.4 八叉树 — 为什么不推荐

八叉树的核心优势是**自适应细分**：密集区域格子小，稀疏区域格子大。

**DNF/格斗游戏的场景特征与八叉树不匹配**：

| 特征 | 八叉树 | 空间哈希/SAP |
|------|--------|-------------|
| 对象分布均匀（都在屏幕内） | 自适应细分无优势 | 更简单直接 |
| 对象频繁移动（每帧更新） | 频繁重建子树 | 重算 hash key 即可 |
| 主要是 2D 平面 | 分 8 份中 4 份永远空 | 天然适合 |
| 实现复杂度 | 高（分裂/合并/跨边界） | 低 |

**八叉树适合的场景**：3D 开放世界（原神、Minecraft），对象分布不均匀，场景跨度大，有远近层次。

**帧同步游戏实体数量有限（通常 <500），空间哈希或 SAP 几乎总是够用。**

## 五、格斗动作游戏实战方案

### 技能碰撞系统架构

```
格斗游戏中，碰撞分三类：

1. 身体碰撞（Hurtbox）  — 角色自身的受击区域，始终存在
2. 攻击碰撞（Hitbox）   — 技能释放时出现的攻击区域，持续几帧
3. 防御碰撞（Guardbox） — 防御时的保护区域（可选）
```

### 每帧碰撞流程

```
LSUpdate 逻辑帧：
  1. 更新所有角色的 Hurtbox（根据当前动画帧）
  2. 更新所有活跃 Hitbox（根据技能配置 + 当前帧）
  3. 宽相排除（暴力/SAP/空间哈希）
  4. 窄相精确检测（AABB.Intersects）
  5. 命中处理（伤害、击退、Buff）
  6. 清理过期 Hitbox
```

### 包划分总结

```
cn.etetet.truesync    # 定点数数学（已有）
cn.etetet.aabb         # 窄相：AABB 结构体 + 相交检测
cn.etetet.collision    # 宽相：遍历策略（SAP/空间哈希/暴力）
cn.etetet.lockstep     # 业务层：技能系统、碰撞组件
```
