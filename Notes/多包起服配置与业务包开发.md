# 多包起服配置与业务包开发

## 一、多包起服配置不会冲突

### 核心机制：配置驱动 + 自动注册

ET的包是"拼装式"的，不是"覆盖式"的。多个包的起服配置不同，不会产生冲突。

#### 1. SceneType 通过 PackageType 隔离，天然不冲突

```
login 包:       SceneType.Realm = 9 * 1000 + 1 = 9001
                SceneType.Gate  = 9 * 1000 + 2 = 9002
statesync 包:   SceneType.Map   = 10 * 1000 + 2 = 10002
你的业务包:     SceneType.XXX   = N * 1000 + X
```

每个包声明自己的 PackageType，所有 SceneType 值自动错开，不会重复。

#### 2. FiberInit 按 SceneType 匹配，互不干扰

`EntryEvent2_InitServer` 做的事情就是：**读 StartConfig 表，逐行创建 Fiber**。

```csharp
foreach (StartSceneConfig startConfig in scenes)
{
    int sceneType = SceneTypeSingleton.Instance.GetSceneType(startConfig.SceneType);
    await FiberManager.Instance.Create(..., sceneType, startConfig.Name);
}
```

- StartConfig 里配了 Realm 行 → 创建 Realm Fiber → 触发 `[Invoke(SceneType.Realm)]` 的 FiberInit
- StartConfig 里配了 Gate 行 → 创建 Gate Fiber → 触发 `[Invoke(SceneType.Gate)]` 的 FiberInit
- StartConfig 里配了 Map 行 → 创建 Map Fiber → 触发 `[Invoke(SceneType.Map)]` 的 FiberInit

**配了什么就启动什么，没配的不会被创建。**

#### 3. MessageHandler 按 SceneType 过滤，互不影响

```csharp
[MessageSessionHandler(SceneType.Realm)]  // 只在Realm Fiber中处理
public class C2R_LoginHandler : ...

[MessageSessionHandler(SceneType.Gate)]   // 只在Gate Fiber中处理
public class C2G_EnterMapHandler : ...

[MessageHandler(SceneType.Map)]           // 只在Map Fiber中处理
public class C2M_PathfindingResultHandler : ...
```

Handler 注册到对应的 SceneType，消息只会被路由到匹配的 Fiber 处理。

#### 4. Event 也按 SceneType 过滤

```csharp
[Event(SceneType.StateSync)]    // 只在SceneType.StateSync的Scene中触发
public class EntryEvent1_InitShare : AEvent<Scene, EntryEvent1> { ... }

[Event(SceneType.Map)]          // 只在Map Fiber中触发
public class ChangePosition_NotifyAOI : AEvent<Scene, ChangePosition> { ... }
```

不同包的 Event 即使监听同一个事件名，也会根据 SceneType 分别处理，互不干扰。

public class FiberInit_LoginCenter : AInvokeHandler<FiberInit, ETTask>

    {

        await ETTask.CompletedTask;
    }
}

## 三、登录后衔接游戏流程

LoginCenter 验证通过后，需要把玩家引导到现有的 Gate → Map 流程。

### 方案A：LoginCenter 替代 Realm

客户端先去 LoginCenter 做账号验证，验证通过后再走原有 Realm → Gate 流程。

```
客户端 → LoginCenter(注册/登录验证，获取Token)
       → Realm(携带Token，Realm校验Token后分配Gate)
       → Gate(建立长连接)
       → Map(进入地图)
```

**实现方式：** 修改 Realm 的 LoginHandler，增加 Token 校验逻辑。

### 方案B：LoginCenter 验证通过后直接分配 Gate（跳过 Realm）

LoginCenter 验证通过后，直接向 Gate 请求 Key，返回给客户端。

```
客户端 → LoginCenter(注册/登录验证)
       → LoginCenter 向 Gate 请求 Key
       → 返回 Gate 地址 + Key 给客户端
       → Gate(建立长连接)
       → Map(进入地图)
```

**实现方式：** LoginCenter 的 LoginHandler 中调用 Gate 的 `R2G_GetLoginKey` 接口：

```csharp
[MessageSessionHandler(SceneType.LoginCenter)]
public class C2LC_LoginHandler : MessageSessionHandler<C2LC_Login, LC2C_Login>
{
    protected override async ETTask Run(Session session, C2LC_Login request, LC2C_Login response)
    {
        // 1. 验证账号密码
        bool valid = VerifyAccount(request.Account, request.Password);
        if (!valid)
        {
            response.Error = ErrorCode.ERR_LoginError;
            return;
        }

        // 2. 分配Gate（复用 RealmGateAddressHelper 的负载均衡逻辑）
        const int UserZone = 3;
        StartSceneConfig gateConfig = RealmGateAddressHelper.GetGate(UserZone, request.Account);

        // 3. 向Gate请求连接Key
        R2G_GetLoginKey r2GGetLoginKey = R2G_GetLoginKey.Create();
        r2GGetLoginKey.Account = request.Account;
        G2R_GetLoginKey g2RGetLoginKey = (G2R_GetLoginKey)await session.Fiber().Root
            .GetComponent<MessageSender>().Call(gateConfig.ActorId, r2GGetLoginKey);

        // 4. 返回Gate信息给客户端
        response.Address = gateConfig.InnerIPPort.ToString();
        response.Key = g2RGetLoginKey.Key;
        response.GateId = g2RGetLoginKey.GateId;
    }
}
```

客户端 LoginHelper 对应修改连接地址为 LoginCenter 即可。

## 四、总结

| 问题 | 答案 |
|------|------|
| 两个包的起服配置不同会冲突吗？ | 不会。SceneType 通过 PackageType 隔离，配置驱动创建 Fiber |
| 没配某个服务会影响已配的服务吗？ | 不会。每个服务是独立的 Fiber，配了才启动 |
| Handler 会串到别的 Fiber 吗？ | 不会。Handler 按 SceneType 过滤，消息只路由到对应 Fiber |
| Event 会串到别的 Scene 吗？ | 不会。Event 也按 SceneType 过滤 |
| 需要修改 statesync 包的代码吗？ | 不需要。只在 StartConfig 中加新行，写自己的 Handler 即可 |

**核心原则：包与包之间通过协议和 StartConfig 衔接，代码互不侵入。**
