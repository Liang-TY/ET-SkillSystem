# 2D 帧动画游戏 — 基于持续时间的实现方案

## 一、与帧数方案的唯一区别

本方案与《2D帧动画游戏实现方案》（帧数版）的唯一区别是：**动画帧持续时间用毫秒而不是逻辑帧数**。

得益于变速累积器 + 余数保留机制，毫秒和帧数的数学行为完全等价，只是单位不同。

| | 帧数方案 | 本方案（毫秒） |
|---|---|---|
| 配置表 | `持续帧数: 2` | `持续时间: 100ms` |
| 每tick累加 | `Speed` | `UpdateInterval * Speed` |
| 对比阈值 | `DurationTicks` | `DurationMs` |
| 策划直觉 | "这帧持续2个逻辑帧" | "这帧持续100毫秒" |
| 精度 | 相同 | 相同 |

其余所有内容（帧率、组件、视图、回滚、测试）完全相同，不再重复。本文档只列出**有差异的部分**。

---

## 二、有差异的文件

与帧数方案相比，只有以下文件不同：

| 文件 | 差异 |
|------|------|
| `Scripts/Model/Share/LSAnimComponent.cs` | FrameTick 类型改为 `long`，单位为毫秒 |
| `Scripts/Hotfix/Share/LSAnimComponentSystem.cs` | 累加方式改为 `UpdateInterval * Speed`，对比 `DurationMs` |

其余所有文件（LSConstValue、LSInputComponentSystem、LSUnitFactory、LSOperaComponentSystem、LSSpriteAnimViewComponent 等）**完全相同**，直接复用帧数方案的代码。

## 三、差异代码

### LSAnimComponent（差异部分）

```csharp
using TrueSync;

namespace ET
{
    [ComponentOf(typeof(LSUnit))]
    [MemoryPackable]
    public partial class LSAnimComponent : LSEntity, ILSUpdate, IAwake, ISerializeToEntity
    {
        [MemoryPackOrder(0)]
        public int AnimId;

        [MemoryPackOrder(1)]
        public int FrameIndex;

        [MemoryPackOrder(2)]
        public long FrameTick;          // ★ 用 long，单位毫秒（帧数方案用 FP，无单位）

        [MemoryPackOrder(3)]
        public FP Speed;                // 播放速度倍率

        [MemoryPackOrder(4)]
        public bool IsLoop;

        [MemoryPackOrder(5)]
        public bool IsFinished;
    }
}
```

### LSAnimComponentSystem（差异部分）

```csharp
using TrueSync;

namespace ET
{
    [EntitySystemOf(typeof(LSAnimComponent))]
    [LSEntitySystemOf(typeof(LSAnimComponent))]
    public static partial class LSAnimComponentSystem
    {
        [EntitySystem]
        private static void Awake(this LSAnimComponent self)
        {
            self.Speed = FP.One;
        }

        [LSEntitySystem]
        private static void LSUpdate(this LSAnimComponent self)
        {
            if (self.AnimId == 0 || self.IsFinished)
                return;

            // ★ 每逻辑帧累加：帧间隔(ms) × 速度倍率
            // 例如 50ms * 1.7 = 85ms 的动画推进量
            self.FrameTick += (long)(LSConstValue.UpdateInterval * self.Speed);

            AnimConfig config = AnimConfigCategory.Instance.Get(self.AnimId);
            long durationMs = config.Frames[self.FrameIndex].DurationMs;

            while (self.FrameTick >= durationMs)
            {
                self.FrameTick -= durationMs;  // 保留余数
                self.FrameIndex++;

                if (self.FrameIndex >= config.Frames.Count)
                {
                    if (self.IsLoop)
                        self.FrameIndex = 0;
                    else
                    {
                        self.IsFinished = true;
                        return;
                    }
                }

                durationMs = config.Frames[self.FrameIndex].DurationMs;
            }
        }

        public static void Play(this LSAnimComponent self, int animId, FP speed, bool loop = true)
        {
            if (self.AnimId == animId)
                return;

            self.AnimId = animId;
            self.FrameIndex = 0;
            self.FrameTick = 0;
            self.Speed = speed;
            self.IsLoop = loop;
            self.IsFinished = false;
        }
    }

    public static class AnimId
    {
        public const int None = 0;
        public const int Idle = 1;
        public const int Walk = 2;
    }
}
```

## 四、配置表设计

每帧的持续时间以毫秒为单位，策划直接填写直观的时间：

```
动画配置表 (AnimConfig)
┌──────────┬───────────┬──────────────┬──────────────────────────────┐
│ 动画ID    │ 帧序号     │ 持续时间(ms)  │ 精灵图名称                    │
├──────────┼───────────┼──────────────┼──────────────────────────────┤
│ Idle(1)  │ 0         │ 100          │ idle_0                       │
│ Idle(1)  │ 1         │ 100          │ idle_1                       │
├──────────┼───────────┼──────────────┼──────────────────────────────┤
│ Walk(2)  │ 0         │ 50           │ walk_0                       │
│ Walk(2)  │ 1         │ 50           │ walk_1                       │
│ Walk(2)  │ 2         │ 60           │ walk_2                       │
│ Walk(2)  │ 3         │ 50           │ walk_3                       │
│ Walk(2)  │ 4         │ 60           │ walk_4                       │
│ Walk(2)  │ 5         │ 50           │ walk_5                       │
└──────────┴───────────┴──────────────┴──────────────────────────────┘
```

策划可以自由配不同的持续时间（50ms、60ms、100ms 等），不需要考虑逻辑帧间隔是否整除。

## 五、不同速度下的行为验证

以 Walk 动画为例：6帧，每帧 50ms，总时长 300ms，逻辑帧间隔 50ms。

### Speed = 1.0（正常速度）

```
每tick加 50*1.0 = 50ms

Tick 1: tick=50,  50>=50 → 帧0→1, 余0
Tick 2: tick=50,  50>=50 → 帧1→2, 余0
Tick 3: tick=50,  50>=50 → 帧2→3, 余0
Tick 4: tick=50,  50>=50 → 帧3→4, 余0
Tick 5: tick=50,  50>=50 → 帧4→5, 余0
Tick 6: tick=50,  50>=50 → 帧5→0, 余0  ← 循环

每帧 = 1个tick = 50ms，6帧共300ms ✓
```

### Speed = 1.5（1.5倍速）

```
每tick加 50*1.5 = 75ms

Tick 1: tick=75,  75>=50 → 帧0→1, 余25
Tick 2: tick=25+75=100, 100>=50 → 帧1→2, 余50>=50 → 帧2→3, 余0
Tick 3: tick=75,  75>=50 → 帧3→4, 余25
Tick 4: tick=25+75=100, 100>=50 → 帧4→5, 余50>=50 → 帧5→0, 余0

4个tick走完6帧 = 4*50ms = 200ms
理论: 300ms / 1.5 = 200ms ✓
```

### Speed = 0.5（半速）

```
每tick加 50*0.5 = 25ms

Tick 1: tick=25,  25<50, stay帧0
Tick 2: tick=50,  50>=50 → 帧0→1, 余0
Tick 3: tick=25,  25<50, stay帧1
Tick 4: tick=50,  50>=50 → 帧1→2, 余0
...

每帧 = 2个tick = 100ms，6帧共12 tick = 600ms
理论: 300ms / 0.5 = 600ms ✓
```

### Speed = 1.7（非整数倍速）

```
每tick加 50*1.7 = 85ms

Tick 1: 85>=50 → advance, 余35
Tick 2: 35+85=120>=50 → advance(余70)>=50 → advance, 余20
Tick 3: 20+85=105>=50 → advance(余55)>=50 → advance, 余5
Tick 4: 5+85=90>=50 → advance, 余40
Tick 5: 40+85=125>=50 → advance(余75)>=50 → advance, 余25
...

长周期平均: 每tick推进 85/50 = 1.7帧
6帧用时: 6/1.7 ≈ 3.53 tick ≈ 176.5ms
理论: 300ms / 1.7 ≈ 176.5ms ✓
```

### 每帧持续时间不同的情况

Walk 动画帧2和帧4配60ms，其余50ms：

```
总时长: 50+50+60+50+60+50 = 320ms
Speed = 1.0, 每tick加50ms

Tick 1: tick=50, >=50 → 帧0→1, 余0        帧0显示50ms ✓
Tick 2: tick=50, >=50 → 帧1→2, 余0        帧1显示50ms ✓
Tick 3: tick=50, < 60, stay帧2
Tick 4: tick=100, >=60 → 帧2→3, 余40      帧2显示100ms（应为60ms，差40ms）
Tick 5: tick=40+50=90, >=50 → 帧3→4, 余40  帧3显示50ms ✓
Tick 6: tick=40+50=90, >=60 → 帧4→5, 余30  帧4显示50ms（应为60ms，差10ms）
Tick 7: tick=30+50=80, >=50 → 帧5→0, 余30  帧5显示50ms ✓

不均匀！但长周期余数会自动平衡：
一轮总推进: 7 tick * 50ms = 350ms，理论 320ms
下一轮从余数30开始，会自动补偿，多轮后平均趋近 320ms ✓
```

## 六、毫秒方案 vs 帧数方案的选择

| 场景 | 推荐 | 原因 |
|------|------|------|
| 策划习惯用毫秒配表 | **毫秒方案** | 直观，不用换算 |
| 需要每帧持续时间完全均匀 | **帧数方案** | 只有帧数方案能保证每帧显示时间完全相同 |
| 有非整数倍速需求（如1.7x） | 两者均可 | 累积器都正确处理 |
| 不同帧有不同持续时间 | **毫秒方案** | 策划更直观，短期不均匀可接受 |
| 极端追求精确性 | **帧数方案** | 帧数对齐无余数问题 |

**大多数项目用毫秒方案即可。** 只有格斗游戏等对每帧精确性要求极高的场景才需要帧数方案。
