# DNF 技能特效架构：.als、纯视觉对象、PO（被动物体）的关系

> 承接 09-动画系统整体架构认知。那篇说 .als 是"动作的特效叠加清单"——但技能特效（血爆的爆炸、波动剑的冰波）**大多不是 .als 做的**。
> 本篇讲清：DNF 的"特效"是四种机制的组合；血爆的完整过程（角色帧+特效帧+伤害怎么串起来）；"好看"和"打人"的关系。

---

## 0. 核心认知：DNF 没有"特效系统"

所谓技能特效 = 下面四种机制按需组合，没有统一的"特效管理器"：

| # | 机制 | 一句话 | 有伤害判定吗 | 典型例子 |
|---|------|--------|-------------|---------|
| ① | **.als 叠层** | 配置在动画边车上的装饰层，引擎自动播 | ❌ 无 | 普攻的剑光/尘土、称号光环 |
| ② | **纯视觉对象**（pooled draw-only） | 脚本在特定帧创建的"只好看"对象 | ❌ 无 | 血泊、地面焦痕、爆炸闪光残迹 |
| ③ | **PO 被动物体** | 脚本创建的独立实体：**有视觉、有攻击盒、有攻击信息** | ✅ **有** | 血爆的爆炸体、冰波弹道、火圈区域 |
| ④ | **屏幕反馈** | 震屏/闪屏 | — | sq_SetMyShake / sq_flashScreen |

**关键区分：".als 是给'动作'化装的；PO 是'技能实体'本体。"**
- .als 改不了任何逻辑，纯粹往既有动画上贴图层（哪帧开始、画在哪层），策划数据驱动，脚本零参与。
- 技能真正的"特效"——那些会打人的爆炸、会飞的波——是 **PO**。PO 自己有 .ani（视觉+攻击盒帧）、有 .atk（命中属性）、有 .nut（行为），是一个完整的"临时演员"。

---

## 1. 血爆技能全流程（角色帧 + 特效帧 + 伤害 如何串起来）

以男鬼剑血爆（技能/状态 229）为例，完整时序：

```
【施法者侧】
① 按技能键 → checkExecutableSkill_BloodBoom
   → obj.sq_IsUseSkill(229)（引擎校验CD/MP，通过则扣费进CD）
② obj.sq_AddSetStatePacket(229, USER) → 切进技能状态
③ onSetState_BloodBoom（脚本初始化）：
   · obj.sq_StopMove()                              停移动
   · obj.sq_SetCurrentAnimation(常量)  ──查.chr菜单──→ 血爆施法动画.ani
   · obj.sq_SetCurrentAttackInfo(常量) ──查.chr菜单──→ 血爆本体攻击信息.atk
   · 伤害双轨设置：sq_GetBonusRateWithPassive(229,..,列)   ← 从.skl按等级取
                  + sq_GetPowerWithPassive(229,..,列)
④ 引擎播【角色施法动画】：
   · 每帧：.img 贴图按 IMAGE POS 摆到角色锚点（角色帧）
   · 该动画全帧 [DAMAGE TYPE] SUPERARMOR —— 读条期间霸体
   · （如有 .als：装饰层自动叠加）
⑤ 动画播到【标记帧】（.ani 里编的 [SET FLAG]=1）
   → 引擎回调脚本 onKeyFrameFlag_BloodBoom(obj, 1)   ★特效的出生时机
⑥ 脚本在回调里干三件事：
   a. 发 PO 创建包（把技能参数序列化传给爆炸体）：
      obj.sq_StartWrite()
      obj.sq_WriteDword(229)          ← 技能ID
      obj.sq_WriteDword(伤害值×8个参数) ← 从.skl取的数值
      obj.sq_SendCreatePassiveObjectPacket(24370, 0, 0, 0, 60)  ← PO编号+偏移
   b. sq_SetMyShake(obj, 8, 300)      ← 震屏（屏幕反馈）
   c. sq_flashScreen(...)             ← 闪屏 + 地面血泊（纯视觉对象②）
      （血泊：sq_CreateAnimation→addLayerAnimation→sq_CreatePooledObject
        →sq_SetEnumDrawLayer(BOTTOM)→sq_AddObject）   ← 只好看，不打人

【PO 侧（血爆爆炸体 24370 —— "技能特效帧"的载体）】
⑦ 引擎收到创建包 → 生成 PO 实体 → 回调 setCustomData_po_*(obj, reciveData)
   脚本按写入顺序 readDword() 读回 8 个参数（纯位置协议）
⑧ PO 初始化：
   · obj.setCurrentAnimation(爆炸动画.ani)    ← 特效帧：effect贴图、发光帧
                                              (LINEARDODGE加法混合)
   · attackInfo = sq_GetCurrentAttackInfo(obj)
     sq_SetCurrentAttackPower(attackInfo, 读回的伤害值)   ← 伤害装填
   · 参数转存 getVar，供后续帧逻辑用
⑨ 引擎播【爆炸动画】，播到带 [ATTACK BOX] 的帧：
   引擎扫：PO当前帧的盒子 × PO的attackInfo × 怪物们的受击盒
⑩ 命中怪物！
   · 引擎按 attackInfo 的反应参数打怪物（切 STATE_DAMAGE、扣血）
   · 回调 onAttack_po_*：脚本追加"纯特效类"效果
     （如挂 ap_bloodboom.nut 附加体到怪物身上=持续出血debuff）
⑪ 爆炸动画播完 → onEndCurrentAni_po_* → sq_SendDestroyPacketPassiveObject
    （destroy 钩子里回收它挂的视觉对象，防泄漏）

【怪物侧】
⑫ 被切进 STATE_DAMAGE(3)，播自己的 damage1.ani（受击动画），血条掉
⑬ 若挂了出血附加体：ap 脚本每 tick 结算持续伤害
```

**一句话总结这个流程：**
> 角色动画的**标记帧**触发脚本 → 脚本创建 **PO**（把 .skl 的伤害数值序列化传过去）→ PO 播**自己的特效动画**、带**自己的攻击盒和攻击信息** → 引擎扫 PO 的盒子命中 → 伤害与受击反应落地 → PO 自毁。

**伤害和特效的关系**：伤害由 PO 的 attackInfo 承载（.skl 取值→参数包→PO 装填），特效帧（视觉）和攻击盒（判定）**住在 PO 的同一个 .ani 里**——"第几帧好看"和"第几帧打人"共用一个时间轴，天然同步。纯视觉对象（血泊/闪光）没有任何判定，纯粹氛围。

## 2. PO（被动物体）深入——技能特效的核心载体

### 2.1 PO 是什么
一个引擎管理的临时实体，**相当于"迷你角色"**：有位置/朝向/生命周期/自己的动画/自己的攻击信息/自己的脚本。编号 24300~24400 的 PO 可以挂 .nut 脚本（自定义行为）；普通特效编号（如 38001）只是纯视觉。

### 2.2 PO 的三种用法（R2-H 实证）
| 形态 | 机制 | 例子 |
|------|------|------|
| **弹道·链式生灭** | 不移动！每段播 10ms 就在前方生下一段 PO，链式接力 | 冰波动剑（地波） |
| **弹道·插值平移** | 单 PO 每帧匀速插值移动，出界销毁 | 崩山击波 |
| **原地爆炸/区域** | 站桩播爆炸动画，动画完自毁；可带 [SET FLAG] 做多段 | 血爆、火圈（Tick型） |

### 2.3 PO 的通用编程模式（背下来）
```
创建：  obj.sq_StartWrite() + N×sq_WriteDword(参数)
        + obj.sq_SendCreatePassiveObjectPacket(编号,槽,x,y,z)
接生：  setCustomData_po_名字(obj, reciveData) → reciveData.readDword() 按序读
行为：  setState_po_名字 / onProc_po_名字(procAppend) / onAttack_po_名字
        / onKeyFrameFlag / onTimeEvent / onEndCurrentAni_po_名字
自毁：  sq_SendDestroyPacketPassiveObject(obj)（动画完调用）
铁律：  只有 isMyControlObject() 端发包；destroy 钩子回收全部视觉对象
```

### 2.4 为什么伤害要走 PO 而不是本体直接打？
DNF 的选择逻辑（从实例归纳）：
- **近身挥砍**（三段斩/普攻）：本体动画的 [ATTACK BOX] × 本体 attackInfo 直接判定，**不建 PO**——判定跟角色动画帧走。
- **远程/延迟/持续/独立逻辑**（弹道/爆炸/区域）：必须建 PO——因为判定要在"角色已经收招之后"继续存在，需要独立生命周期的实体。
- 对照我们：本体判定≈阶段3 攻击盒；PO≈阶段6 Bullet/Area。分界线一样。

## 3. 四种机制的渲染层级（谁画在谁上面）

```
最底 ──→ 最高
ENUM_DRAWLAYER_BOTTOM（PO可指定底层，如地面波纹）
 .als 的 z序=-9999（角色身后层）
 ──────── 角色本体帧 ────────
 .als 的 z序=+9999（角色身前层，如剑光）
 PO/pooled 对象（sq_SetEnumDrawLayer 指定层）
 屏幕级反馈（闪屏/震屏，不在世界层里）
```
.als 的两个整数 =（触发帧, z序±9999）——同一个特效文件挂 -10000 和 +10000 就能做出"角色前后夹层辉光"。

## 5. 一页速查

```
"这个特效会不会打人？"
├─ .als / 层动画 / pooled纯视觉 / 震屏闪屏 → 不会（纯表现）
└─ PO（被动物体）→ 会（自己的.ani盒子×自己的.atk）

"特效什么时候出生？"
└─ 角色动画的 [SET FLAG] 标记帧 → onKeyFrameFlag 回调 → 脚本创建

"伤害数值从哪来？"
└─ .skl 按等级取 → 参数包传给 PO → PO 装填进 attackInfo → 引擎扫盒命中时结算

"视觉和判定怎么同步？"
└─ 住在 PO 同一个 .ani 里（特效帧带攻击盒），共用帧时间轴
```
