# DNF 装备系统整体架构：一篇看懂

> 承接 09（动画）/10（特效）/11（技能）系列。原始研究笔记：`原始笔记/R4-L-装备系统.md`。
> 目标：读完知道"装备是什么、属性怎么作用到角色、武器类型怎么改变战斗、有哪些子系统"。

---

## 0. 一句话总纲

**装备 = 一张明文数据表（.equ）+ 引擎原生解释。**
- 静态属性、外观绑定、条件特效**全部声明在 .equ 里**，由引擎（C++）直接解析生效。
- **穿脱装备没有脚本事件，静态加成不走 nut**——脚本层甚至拿不到"装备对象"，只能看到武器子类型和最终数值。
- 只有两种情况下沉到脚本：①武器类型改变战斗行为（技能分支）②精通类 buff。

**对比技能系统**（技能=脚本主导）正好相反：**装备是数据主导，脚本是例外。**

---

## 1. 装备数据长什么样

### 1.1 目录组织：职业 → 部位 → 材质/类型

```
pvf\equipment\
├─ equipment.lst          总注册表（5万+件：ID ↔ .equ 路径）
├─ character\
│   ├─ common\<部位>\<材质>\    防具：jacket/pants/shoes/... × cloth布/leather皮/larmor轻/harmor重/plate板
│   │                          首饰：amulet项链/wrist手镯/ring/support/magicstone/title称号
│   ├─ swordman\weapon\{ssword短剑,katana太刀,club钝器,hsword巨剑,beamsword光剑}
│   ├─ swordman\avatar\<部位>\  时装（10个外观位，独立于属性槽）
│   ├─ swordman\growtype\       觉醒强制外观（红眼/波动印）
│   └─ swordman.lay             外观层绑定表（见 1.3）
└─ creature\               宠物装备（宝珠）
```

### 1.2 一个 .equ 的字段（按职能分组）

| 组 | 关键字段 |
|----|---------|
| 身份 | name/name2/flavor text/explain |
| 分类 | equipment type（槽位）+ sub type（防具材质 0布~4板） |
| 品质 | grade / rarity(1普通/2稀有/3史诗) / random option(魔法封印) |
| 条件 | usable job / minimum level |
| **基础属性** | equipment physical/magical attack、defense、HP MAX、cast speed、stuck僵直…（**双列**=品级区间上下限） |
| 技能加成 | [skill levelup] 职业+技能ID+加等级 |
| **外观绑定** | [animation job]+[variation 图层号]+[layer variation 图层资源名]+[equipment ani script→.lay] |
| **条件特效** | [if]…[then]…（DSL，见 §2.2） |
| 套装 | [set name]/[set item 成员ID]/[set ability] |
| 经济/耐久 | price/repair/weight/durability |

### 1.3 .lay：装备=可换图层

`.lay` 把"职业目录名"映射到各基础动作动画（`[waiting motion] %[job]%s/Stay.ani`）。装备件指定**图层号+图层资源名**，引擎把武器/防具外观合到角色渲染层上——**换装=换图层**，不动角色本体。这是"纸片人换装"的正统做法。

## 2. 属性管线：装备怎么影响角色（五条路）

```
① 静态属性 ──── .equ 面板字段 ─────────────→ 引擎直读汇总（不走nut不走appendage）
② 条件特效 ──── .equ 内嵌 [if]/[then] DSL ──→ 引擎原生解释（★90%装备特效走这）
③ 复杂持续 ──── [appendage N] → appendage.lst → .apd 参数化状态包
④                        └──── 或 nut 版 appendage（与技能Buff同一套机制）
⑤ 精通/武器特化 ─ sqr 脚本（技能等级>0 且武器匹配 → 挂buff appendage）
```

### 2.1 ①静态直读
引擎穿装备时汇总面板。证据：sqr 全目录没有 getEquip*/isEquip API——**nut 层拿不到装备对象**。

### 2.2 ②条件特效 DSL（本次研究最重要的发现）
装备特效**不是脚本**，是 .equ 里的声明式微语言：
```
条件动词：[party count]=N / [change status] hp>%75 / [attack success]
         / [my appendage] 38 / [party death] / [cooltime] 30000 / [time]
动作：   [stat by condition] / [increase damage] %30 / [add absolute damage]
         / [consume item] / [restore] hp %10 / [appendage] 38 / [speech on]
```
真实例子：
- 称号：**攻击 2% 几率 +30 力量 20 秒**（attack success + probability 2 + stat）
- 史诗短剑：**按队伍人数 1~4 人给 +15~60 双攻**（4 组 party count 分支）；**队友死亡→变红+30%攻击 10 秒**；**HP<10% 且冷却 60s→消耗灵魂晶石回 10% HP**

一套 DSL 覆盖 90% 装备特效——策划零代码配装备逻辑。

### 2.3 ③.apd 参数化状态包
`[appendage] 38` → appendage.lst 第 38 号 → 356 个 .apd 之一，内容是 `[type] change status + [int data]` 的参数化 buff。复杂的才用 nut 版 appendage（与技能 Buff 同一套）。

### 2.4 套装：数据在每件成员上冗余声明
每件都带完整 `[set item]` 5件ID + `[set ability]`（可嵌 if/then），引擎统计已穿数。时装套装=纯视觉（走路脚印特效）。

### 2.5 ⑤精通
- 防具精通：`[skill fitness growtype]` 匹配防具材质，**引擎按身上该材质件数放大收益**，零脚本。
- 武器精通：.skl 提供每级数值列；**脚本在"技能等级>0 且 getWeaponSubType() 匹配"时挂 appendage**（物攻%/stuck 减免），换武器轮询摘除。
- **换装检测是轮询不是事件**：mysticequip 的 proc 每帧比对武器子类型变化。

## 3. 武器类型系统（对战斗影响最大）

### 3.1 三件套结构
```
枚举：    getWeaponSubType() → 0短剑/1太刀/2钝器/3巨剑/4光剑（按职业从0重编号）
          ↓ 唯一入口，脚本/引擎都只看这个整数
平行表：  .chr 尾部按武器索引对齐的数据表
          · WeaponCombo{Short,Blade,Blunt,Heavy,Light}*.ani → 每系普攻段数与动画
            （短剑3段/太刀4段/钝器3段/巨剑2段/光剑3段）+ 同名 .atk
          · [weapon wav] 每系音效 / [weapon hit info] 打击表现（利刃 cut+blood vs 钝器 blow+no blood）
          · [weapon skill info] 24列系数 / [upgrade weapon attack power rate] 强化倍率
          · [weapon durability decrease rate] 耐久倍率（巨剑1.05磨损快）
脚本分支： 技能 nut 里 if (getWeaponSubType()==K) 散点分支
```

### 3.2 脚本分支的三种用法（实例）
1. **换动画/攻击数据**：attack.nut 的 weaponcombo——switch(武器){switch(段数){设动画+atk}}
2. **换行为**：拔刀斩——钝器(==2)时 onBeforeAttack 对可抓敌人 `sq_HoldAndDelayDie` 强控+浮空200（同技能不同武器手感完全不同！）
3. **作为状态参数**：`sq_IntVectPush(getWeaponSubType())` 传给状态机选分支

**门槛**：系别使用许可是**技能**（"光剑掌握"passive），不是 .equ 条件。

## 4. 其他子系统速览

| 系统 | 一句话 |
|------|--------|
| **时装 avatar** | 10 个外观位独立于属性槽；穿时选属性/选技能+1；徽章镶嵌槽；觉醒强制外观 |
| **光环时装** | 纯外观+面板（前后两层 ani） |
| **玩法光环 .ora** | 装备赋予的**范围 debuff 场**：range/duration/周期事件/给范围内目标挂 appendage |
| **耐久** | 四方协作：.equ 上限 + .chr 武器系倍率 + **.skl 技能消耗倍率**（1332个技能都有）+ 引擎扣 |
| **强化** | etc\upgrade.etc（成功率/费用/掉级大表）+ .chr 强化倍率表 |
| **增幅(红字)** | etc\amplifyitem.etc（按稀有度权重） |
| **魔法封印** | .equ [random option] + etc\randomoption\ 随机属性池 |
| **附魔** | **不在 pvf 内**（服务器侧，缺口） |
| 宠物装备 | 同一套 DSL 挂宠物 |

## 5. 和我们项目的对照/借鉴

| DNF | 我们可借鉴 | 备注 |
|-----|-----------|------|
| .equ 声明式装备表 | 装备 JSON：字段分组（身份/分类/属性/条件特效/套装） | 表结构可照抄 |
| [if]/[then] 特效 DSL | **强烈借鉴**：条件(触发时机)×动作(效果)的声明式装备特效，配 our Buff/Actions 系统 | 覆盖90%特效不用写代码 |
| .lay 换图层 | 我们 2D 纸片换装：图层号+资源名的换装表 | 视图层实现 |
| 武器类型三件套 | **枚举+平行数据表（每武器一套普攻段/atk）+脚本散点分支** | 做多武器时直接抄 |
| 精通=passive技能+轮询挂buff | 武器精通做成 passive 技能（技能等级>0 且武器匹配→挂buff） | |
| appendage 双轨（.apd 参数化 / nut 逻辑） | BuffDef（简单参数化）+ 复杂 Buff 写逻辑 | 与我们阶段5设计同构 |
| 静态属性引擎直读 | LSNumericComponent：穿装备时 Set 各 Base key | 管线一致 |

**核心借鉴**：DNF 装备系统的精髓是"**能用配置表解决的绝不写代码**"——条件特效 DSL + 参数化 .apd 让策划配了 5 万件装备，脚本只维护武器分支和精通。我们做装备系统时也应该先设计好声明式表结构 + 少量通用解释器，而不是每件装备写逻辑。

## 6. 一页速查

```
装备是什么？   .equ 明文表（属性/外观/条件特效全声明在里面）
属性怎么生效？ ①静态引擎直读 ②if/then DSL ③.apd ④nut appendage ⑤精通脚本
穿装有事件吗？ 没有（nut 拿不到装备对象；换装检测靠轮询武器子类型）
武器影响战斗？ 枚举(getWeaponSubType) + .chr 平行表(每系普攻段/atk/音效/耐久)
              + 技能脚本 if(武器==K) 分支
套装怎么算？   每件冗余声明成员表，引擎数已穿件数
强化/增幅？    etc 表（成功率/倍率），折算进 .chr 攻击力表
时装？         10 个外观位独立于属性槽，换装=换图层(.lay)
```
