# 第二轮总结①：DNF 按键到伤害全链路（文件级实证）

> 课题：Q5——从键盘按键到怪物扣血，串联了哪些文件/系统/API。
> 来源：输入链路（hotkeysystem.co/rdarkeyindex.dat/.lst）+ 配置绑定链（.chr/.skl/.atk/.ani 全明文实证）+ 第一轮状态机/命中成果。
> 用途：对照我们 LSInput→LSSkillComponent→LSCast→Hitbox→Numeric 链路，验证架构、找缺口。**只列建议，改不改用户定。**

---

## 1. DNF 怎么做的

### 1.1 全链路总图（一次"按 A 键放三段斩"的完整旅程）

```
【输入层】
① 物理键按下（VK 码 65='A'）
② 默认键位表 clientonly/hotkeysystem.co：VK → OPTION_HOTKEY_QUICK_SKILL1(20)（逻辑热键）
   （玩家自定义存服务器账号数据，不在 pvf）
③ 技能定位（两条路殊途同归）：
   a. 快捷栏路径：逻辑热键槽位 → 该槽位放的技能ID（角色数据，服务器端）
   b. 指令路径：.skl 的 [command]（如三段斩=→+Z）→ CNRDCommandChecker 序列匹配 → 技能ID
      （指令记号索引表：skill/rdarkeyindex.dat，0=UP...4=SKILL(Z) 5=ATTACK(X)）
④ 引擎登记"技能X的键已按下" → 脚本可查 sq_IsEnterSkill(X)

【施放门禁层】
⑤ checkCommandEnable_技能名(obj)：当前状态能否出招（脚本门禁①，兼图标亮灭）
⑥ checkExecutableSkill_技能名(obj)：脚本调 obj.sq_IsUseSkill(SKILL_ID)
   ——引擎在此做完整校验：CD → MP → 密封/禁用 → 通过则【扣MP+进CD】返回 true
   （消耗数值来自 .skl [dungeon][consume MP]；脚本只可用 useSkill_before/after 微调倍率）
⑦ obj.sq_AddSetStatePacket(状态ID, STATE_PRIORITY_USER, 带参)
   ——走网络包切状态（可被 addSetStatePacket_* 钩子驳回）→ 广播到所有客户端

【配置资源层】（全部明文 #PVF_File 格式！）
⑧ skill/swordmanskill.lst：技能ID(8) ↔ Swordman/TripleSlash.skl
⑨ .skl 技能数值表：
   [command] 指令 / [cool time] 2000 / [consume MP] 初值+满级值
   [static data] 静态列 / [level info] 首数=列数，每级一行（列0=百分比伤害 列3=固伤…）
⑩ 状态脚本 onSetState_*：
   sq_SetCurrentAnimation(CUSTOM_ANI_X=262) ──→ character/swordman/swordman.chr
                                                [etc motion] 第262行(0起)
                                                  = Animation/tripleslash_….ani
   sq_SetCurrentAttackInfo(CUSTOM_ATTACK_INFO_X=142) ──→ .chr [etc attack info] 第142行
                                                  = AttackInfo/tripleslash_….atk
⑪ .ani 动画帧数据（每帧）：[IMAGE] 贴图(+NPK图集index) [IMAGE POS] [DELAY]
   [ATTACK BOX] 六值攻击盒 [DAMAGE BOX] 受击盒 [SET FLAG] 关键帧标记 [PLAY SOUND]…
⑫ .atk 攻击信息（命中属性层，无盒几何！）：[lift up] 浮空力 [push aside] 击退
   [force hit stun time] 僵直 [damage reaction] 受击模式 [attack type] 物理/魔法…

【演出与判定层】
⑬ 帧驱动三机制：onKeyFrameFlag（.ani [SET FLAG] 帧标记回调）/ onProc 轮询帧号 / 时间-帧换算
⑭ 伤害设置：sq_SetCurrentAttackBonusRate（百分比，取 .skl [level info] 列）
            + sq_SetCurrentAttackPower（固伤）双轨
⑮ 命中判定在引擎：扫描【当前动画当前帧的 ATTACK BOX】× 已设置的 attackInfo → 命中
⑯ 命中回调 onAttack_*(obj, damager, boundingBox)：只做追加（控制/特效/挂debuff）
⑰ 受击反应：引擎读 .atk 的四件套（damageAct/upForce/backForce/hitStunTime）
   → 把受击方切进 STATE_DAMAGE(3)/STATE_DOWN(4)，扣 HP
⑱ 结束：onEndCurrentAni（动画完→回 STAND）；onEndState（真离开→手动 startSkillCoolTime 可选）
```

### 1.2 关键定论

- **CD 两种机制并存**：默认 `.skl [auto cooltime apply] 1` = `sq_IsUseSkill` 成功即自动进 CD；特殊技能（多段类如三段斩）用 `startSkillCoolTime` 手动控制起点（真正离开状态才计时）。
- **普攻不是技能**：X 键走引擎原生 `STATE_ATTACK=8`（skillId=-1），attack.nut 只做连段子状态推进（`sq_IsEnterCommand(E_ATTACK_COMMAND)` 检测重按）；"普攻取消进技能"由 `clientonly/cancelskilllist.co` 白名单控制。
- **盒几何与命中属性是两层**：盒（何时何地判定）在 .ani 帧数据；命中属性（打到后什么反应）在 .atk。脚本只组装绑定（数据提供素材清单，.nut 运行时拼装）。
- **新老年技能分型**：老技能（编号小）状态机在 C++ 引擎，.nut 只挂钩子；新技能（130+/220+）整条状态机在 .nut 写。
- **.act 与玩家技能无关**：那是怪物/AI 的帧级行为脚本（另一条链，做 Q12 怪物 AI 时用）。

| [SET FLAG] + onKeyFrameFlag | hitFlag/cancelFlag | ✅ 同构 |

## 3. 建议改动清单

1. **`04b-打击感`/`05-阶段4`：受击反应参数的"层"定案**——DNF 证明盒几何（帧数据）和命中反应（.atk 一份/技能）是**两层**。落到我们：AnimFrameData 保留盒字段；受击反应四件套（damageAct/hitStunTime/upForce/backForce）放 **attack.json 顶层（每技能一份）**，不放每帧。第一轮建议1 的落地位置由此确定。
2. **`05-阶段4`：CD 机制修正第一轮建议2**——不是"全部改到 OnEnd 起算"，而是：**默认 TryCast 时起算（=DNF auto cooltime apply）；多段/特殊技能支持延迟到 OnEnd 手动起**（=startSkillCoolTime）。LSSkillComponent 加 `ManualCooldown` 开关。
3. `05-阶段4`：普攻连段的重按检测参考 `sq_IsEnterCommand(E_ATTACK_COMMAND)` 模式——连段子状态推进时查"攻击键又按了"（我们的 LSInput.Button 持续采样即可）。
4. 将来配表（如果做）：参考 .skl 的 `[level info] 列数+每级行` 结构——我们的 const 调参区将来迁表时按此组织。
5. 输入系统后置项备忘：键位重配（hotkeysystem.co 等价物）、指令输入（→+Z 序列匹配，CNRDCommandChecker 等价物）——都不是现在做，记在输入系统设计时用。

## 4. 遗留/待验证

- 快捷栏槽位赋值不在 pvf（服务器角色数据）——对我们无影响（我们帧同步，输入直接广播）。
- 引擎 C++ 内部（输入匹配器细节、状态调度）无源码——数据侧+API 注释三角互证已够用。
- 六值盒 = 两角点（min/max xyz）：第一轮 D 实证 + 本轮 flwmxd/DNF-Porting 交叉，**结论可信**。
- 蓄力（长按）机制 `sq_IsEnterSkillLastKeyUnits` 只见声明未深挖——做蓄力技时再查。
