# DNF 地图与战斗场景系统整体架构：一篇看懂

> 承接 09~12 系列。原始研究笔记：`原始笔记/R4-M-地图与战斗场景.md`。
> 目标：读完知道"战斗场景的层级结构、进图流程、一张地图里有什么、怪物怎么配置怎么生成怎么被驱动、房间怎么流转、难度怎么缩放"。

---

## 0. 一句话总纲

**战斗场景 = 副本(.dgn 定义一张"迷宫网格") + 每格一个房间(.map) + 房间里一份刷怪表(.mob 引用)。**
进副本 = 引擎按迷宫网格逐格实例化房间；**进房间 = 按表一次性刷怪**（没有波次字段，Boss 阶段由行为脚本触发）；清完怪 → 门解锁 → 走到下一格。

数据规模：495 个副本 / 4521 张地图 / 3689 种怪物 / 5.2 万个怪物行为脚本——全是明文表。

---

## 1. 层级结构：从世界到房间

```
region 分区(.rgn)          阿拉德大陆 → 聚合城镇
  └─ town 城镇(.twn)        每个街区是一张 .map（城镇和副本用同一套地图格式！）
       └─ [dungeon gate]    街区里的"副本门"（走到按X弹选图）
worldmap(.wdm)             选图 UI 数据：本地区可进哪些副本
  └─ dungeon 副本(.dgn)     ★核心层：定义"迷宫网格"+难度+事件怪
       └─ [maze info]       size 6×3 的房间网格（多套变体按任务进度切换）
            └─ map 房间(.map)  每格一个实例：地形/刷怪表/门/出生点/装饰
```

**注意**：stagemap/ 不是关卡层（只有 1 个特殊模式选层 UI）。真正的层级是 **副本→迷宫网格→房间**。

## 2. 副本 .dgn 解剖（迷宫怎么定义）

```
grakkarak.dgn（格拉卡，最小完整例）
├ 门槛：最低等级10 / 怪物基准等级13 / 人数限制
├ [maze info]（可多套，任务进度选变体）
│   ├ [size] 6 3                    ← 迷宫 6列×3行
│   ├ [greed]                       ← 每格2字符的形状码网格：
│   │   "NN BB FF AA NN NN"           NN=空格、BB=起点、EE=终点、FF=走廊…
│   │                                  （形状码决定这个房间四面哪边有门）
│   ├ [start map] 列 行              ← 玩家从哪格进
│   ├ [boss map] 列 行               ← Boss房在哪格
│   └ [map specification] 列 行 图ID  ← 强制指定某格用哪张图（缺省按形状随机挑）
├ [pathgate object] 391..400        ← 10个门对象（左/右/上/下 × Normal/Boss/墙）
├ [champion] 3 6 9 12 14            ← 每难度精英怪数量
├ [monster difficulty bonus]        ← 13行×5列 难度缩放矩阵
├ [event monster] 61726 …           ← 事件怪（黄金哥布林乱入）
├ 深渊：[hell dungeon] 专用房/出现率/掉落表
└ 条件门：[boss room entrance condition] [hunt monster]（杀指定怪才开Boss门）
```

**房间怎么选图**：每个 .map 自己声明 `[greed]`（我实现的是哪个形状模板），引擎把迷宫网格的形状码和本副本的地图池做模板匹配——迷宫格(5,2)=GG ↔ 池里唯一 `GG GG` 的地图。**多套 [maze info] = 同一副本随主线任务"逐渐解锁更多房间"**（bwanga 有 7 套）。

## 3. 房间 .map 解剖（一张地图里有什么）

```
1002.map（普通房间）
├ 地形/碰撞：
│   [tile] → .til 文件 = 贴图 + [pass type] 32行×14列碰撞网格
│            （0=实心地面/墙、1=可下穿平台、2=通行）★全数据驱动，无物理
├ 表现：三层视差滚动率(far 56/middle 90/near 110) + 背景动画层 + BGM/环境音
├ 出生点：[dungeon start area] 矩形（start变体才有）
├ 刷怪表：[monster] 每行= 怪ID 等级 x y [fixed]    ★进房即全部生成
│          [ai character] 600 …                    ← 本房刷APC
│          [NPC]/[monster spawn pos]（塔类随机刷点）
├ 可破坏物：[passive object] 草丛/树/木桶/宝箱
│   [special passive object] + [item]地上物 / [trap]陷阱伤害区
│   （深渊房=封印门对象 + [hellparty] 掉落表）
└ 门位：[pathgate pos] 左/右/上/下 4 个坐标
```

同一房间有多张变体图：`1002.map`（普通）/`b1002.map`（Boss 版）/`s1001.map`（起点版）/`hell_97.map`（深渊版）——引擎按格子的角色（起点/普通/Boss/深渊）选变体。

## 4. 怪物生成管线（重点：配置→生成→行为驱动）

### 4.1 怪物配置 .mob（3689 个）
```
hillgab.mob（哥布林）
├ 属性：[ability category] '[HP MAX]' * 70   ← 系数 × 等级基础表
│        （基础表按1~140级给血量/攻防基数；Boss表≈普通表2.5倍）
│        [level] min max、16种抗性、攻速移速施放、硬直恢复
├ AI参数：视野/好战性/攻击间隔/索敌时间/思考间隔/智力…
├ 分类：[human][goblin][melee combat]（技能对怪类加成判定用）
├ 掉落：[item] 物品ID 权重
├ 战斗：[attack info] → 每技能一个 .atk（命中反应；判定框在 .ani 帧）
└ 行为：新式引用状态机 [attack action] Action/Attack_0..12.act + [ai pattern]
```

### 4.2 行为驱动：三代体系并存
| 代际 | 机制 | 适用 |
|------|------|------|
| **引擎默认 AI** | .mob 的视野/好战性字段驱动的追击+普攻 | 老怪/杂兵 |
| **.act 帧级行为脚本**（5.2万个） | `[MOTION]`动画+音效 → `[TRIGGER]`（帧窗口/限次/条件）→ `[BEHAVIOR]`（攻击/召唤/传送/切状态/震屏/说话…） | 95版起的怪 |
| **.ai 决策树**（1万个） | 嵌套 `[think]`：条件（目标在攻击区？技能转好了？）→ 叶子返回技能序号；按难度分 5 套文件 | 选技能用哪个 |

**.act 与 .ani 的关系**（连回 09）：ACT 的 `[FRAME] 起 止` 触发窗口对应 .ani 的帧号——判定框还是在 .ani 帧数据里，.act 只管"这帧该干什么事"（放技能/召唤/换状态）。

### 4.3 APC（.aic）：另一条路——"用玩家体系做AI角色"
陪跑队友/敌对人形NPC/Boss化人形怪。`.aic` = 玩家 Build（技能等级/装备/快捷栏）+ AI 参数。
**关键差异**：APC 的决策树返回**按键宏名** → 映射到 `key/*.key` 录制的**虚拟输入序列**——**APC 是"回放玩家操作"驱动，怪物是"技能序号→行为脚本"驱动**。即 APC 放技能走的就是玩家的技能状态机那套（技能系统复用）。

### 4.4 生成时机
**进房即按表全刷**（[fixed] 固定点）。没有波次字段——Boss 多阶段、召唤增援都由 .act 触发器（`[SUMMON MONSTER]`/`[SET ACTION]`）和 sqr/monster/ 的 appendage 脚本在运行时做。

## 5. 房间流转

```
进房 → 刷怪 → 战斗 → 怪物全灭（引擎检测，onDungeonClearMonsterEvent）
   → 对应方向 [pathgate object] 的门 .obj 播 Open 动画解锁
   → 玩家走进门 → 相邻格的房间实例化（新地图+新刷怪表）→ 旧房销毁
   → … 到达 [boss map] 格 → Boss房 → 通关
```
- 门=10 槽对象（四方向 × Normal/Boss/墙），迷宫拓扑决定放门还是封墙。
- 特殊流转：条件门（杀指定怪才开Boss门）、自定义通关条件、.act 的 TELEPORT、sqr/map/anton.nut 按 (副本ID,房间ID) 挂自定义机制。

## 6. 难度缩放（5档怎么实现）

**难度同时改四样东西**：
1. **属性矩阵**：.dgn `[monster difficulty bonus]` 13行×5列（等级加值/经验/血量/攻防/好战性/视野/回避/移速…）
2. **AI 换树**：.mob `[ai pattern]` 恰好按 5 难度各配一套 .ai 文件（easy~hero）
3. **精英数量**：`[champion] 3 6 9 12 14`——引擎从普通怪里随机升级 N 只（吃精英专属掉落表）
4. **等级区间**：.mob `[level] min max` × 副本基准等级 × 难度行1

## 7. 和我们项目的对照/借鉴

| DNF | 我们可借鉴 | 备注 |
|-----|-----------|------|
| .dgn 迷宫网格（greed 形状码选图） | 副本配置=房间网格+形状模板匹配选图 | roguelike 味道；单线性关卡可简化成一行 |
| .til 贴图+碰撞网格一一对应 | **强烈借鉴**：地图 JSON = 贴图层 + 碰撞网格（0实心/1平台/2通行），无物理引擎 | 与我们 TSRect 手工碰撞互补 |
| .map 刷怪表（进房即刷） | 房间配置：怪物ID/等级/坐标列表 | 我们 RoomSystem 已有雏形 |
| .mob 属性=系数×等级基础表 | 怪物配置：系数制（一种怪一条系数行，等级查全局表） | 比每怪写死数值好扩展 |
| .act 帧级行为脚本 | 怪物行为=帧触发器（帧窗口→行为），判定框仍在我们 AnimFrameData | 与我们 hitFlag/flags 体系吻合 |
| .ai 决策树（按难度换树） | 怪物 AI = 数据驱动决策树，可先 switch 后配表 | LSMonsterAIComponent 的目标形态 |
| APC=虚拟按键回放 | **远期亮点**：AI 队友用"录制操作回放"实现，复用玩家技能状态机 | 我们帧同步天然适合（输入流重放） |
| 门对象 10 槽 + 清怪开门 | 房间流转：清怪检测→开门状态 | Route B 轮询清怪数 |
| 难度 5 档×4 维缩放 | 难度表：属性系数+AI参数+精英数 | |

**最值得抄的三条**：① .til 的"贴图即碰撞网格"（0/1/2 三值完全够横版格斗）；② .mob 的"系数×等级基础表"（怪物数值框架）；③ APC 的虚拟按键回放（帧同步下做 AI 队友的绝配）。

## 8. 一页速查

```
副本是什么？   .dgn = 迷宫网格（形状码）+ 难度矩阵 + 门对象 + 事件怪
房间是什么？   .map = 地形(.til 贴图+碰撞格) + 刷怪表 + 门位 + 出生点 + 可破坏物
进图流程？     选副本→选难度→按任务选迷宫变体→逐格实例化房间→落在start格
怪怎么刷？     进房按 [monster] 表一次性生成（固定点）；波次/Boss阶段由行为脚本触发
怪怎么行动？   默认AI（.mob字段）→ .act帧脚本（触发器）→ .ai决策树（选技能）
APC是什么？    用玩家体系做的AI角色：决策树输出按键宏→回放虚拟输入
房间怎么流转？ 清怪→门播Open动画→走门→下一格实例化
难度怎么算？   属性矩阵 + AI换决策树 + 精英数量 + 等级区间，四维同缩放
```
