## 1. DNF 怎么做的

### 1.1 技能系统架构（总览）

- **配置/逻辑分离**：`.skl`（数值表：伤害/冷却按等级配）+ `.nut`（Squirrel 脚本逻）。脚本按（技能ID，数据索引）从表取数，**代码里几乎不写死数值**（技能 ID 本身硬编码数字）。
- **技能 = 状态机的一个状态**。`swordman_load_state.nut` 里 `IRDSQRCharacter.pushState(职业, "nut路径", "状态名", 状态ID, 技能ID)` 注册。**状态 ID 和技能 ID 是两套编号**（OutBreak：state 45 / skill 81）。
- **脚本 = 无状态函数集合**：.nut 里只有按命名定组织的全局函数（`on*_状态名`），无构造/无字段/无 this。引擎按函数名后缀路由调用（`checkExecutableSkill_*`/`checkCommandEnable_*` 全库 grep 无脚本调用方，确认为引擎钩子）。
- **运行时状态挂引擎对象上**：状态机 `sq_GetState()` + 子状态 `setSkillSubState(n)` + 通用变量槽 `getVar("名")`（可放 int/vector/timer）+ 动画帧号（时间基准外化为帧进度）。
- **多人同步**：一切状态迁移走网络包 `sq_AddSetStatePacket`；每个回调开头 `if(!obj.isMyControlObject()) return;`——属主端跑逻辑、全端播表现（服务端权威）。我们帧同步不需要这个开关，但逻辑/表现分离的精神一致。

### 1.2 技能生周期事件全表（实证版）

按一次施放的时序排列：

| 阶段 | 事件/函数 | 干什么 |
|------|----------|--------|
| 按键可用 | `flushCommandEnable_*` | 技能图标亮灭 |
| 出招检查 | `checkCommandEnable_*(obj)` | 当前**状态**能否出招（如仅 STATE_STAND） |
| 可施放检查 | `checkExecutableSkill_*(obj)` | `sq_IsUseSkill(SKILL_ID)` 判键并**使技能进 CD**；特殊分支（血气系施放中再按→变瞬发直接创 PO） |
| 消耗窗口 | `useSkill_before_*` / `useSkill_after_*` | 技能使用前/后修改 MP 消耗率 |
| 状态切换 | `obj.sq_AddSetStatePacket(状态ID, 优先级, 带参?)` | 走网络包切状态；可被 `addSetStatePacket_*` 拦截（return -1 驳回/改发别的状态） |
| 进状态 | `onSetState_*` / `onAfterSetState_*` | 初始化：`sq_StopMove` 停移动 → `sq_SetCurrentAnimation(常量)` 设动画 → `sq_SetCurrentAttackInfo(常量)` 设攻击信息 → 设伤害（双轨：百分比+固伤）→ `sq_SetStaticSpeedInfo` 锁攻速 → `setSkillSubState(n)` 记段数 |
| 帧驱动 | `onKeyFrameFlag_*(obj, flagIndex)` | **引擎在 .ani 数据里标记的关键帧回调**（bloodboom 标记1处：创 PO+震屏+闪屏） |
| 帧驱动 | `onProc_*`（组队双方跑）/ `onProcCon_*`（仅自己） | 每帧轮询：帧号判定/开连段输入窗/位移/特效 |
| 命中 | `onBeforeAttack_` → `onAttack_*(obj, damager, boundingBox, isStuck)` → `onAfterAttack_` | **判定循环在引擎**：脚本只设攻击信息，引擎逐帧扫盒，命中才回调；onAttack 返回受击对象（抓取技基础） |
| 结束 | `onEndCurrentAni_*` | 当前动画播完 → 回 STATE_STAND |
| 离开状态 | `onEndState_*(obj, new_state)` | 真离开本技能才 `startSkillCoolTime`（**CD 在这起算，不是施放时**）+ 恢复移动参数 |

被动物体（PO）侧：`setCustomData_po_*`（收创建参数包）/ `setState_po_*` / `onEndCurrentAni_po_*`（自毁）。
Buff（Appendage）侧：`sq_AddFunctionName("onStart"/"proc", 回调名)` 显式注册。

### 1.3 判定帧的三种机制（重要发现）

1. **脚本轮询帧号**：`onProc` 里 `obj.getCurrentAnimation().GetCurrentFrameIndex()` + `getVar` 标记防重入（`if(frameIndex==20 && Hit==0)`）。
2. **时间-帧换算**：`sq_GetCurrentTime(ani)` + `ani.getDelaySum(0,5)`（帧区间总时长）+ `sq_GetUniformVelocity`（匀速插值）——位移类技能用。
3. **`onKeyFrameFlag_*` 引擎帧标记回调**：标记编在 **.ani 二进制数据里**（对应我们发现的 `[SET FLAG]` 字段），引擎播到标记帧回调脚本。

→ **DNF 确实把关键帧标记放在动画帧数据里**，和我们 hitFlag/cancelFlag 配在 AnimFrameData 的设计同构；另两种机制是脚本层的补充。

### 1.4 命中判定与受击反应（攻击方配置驱动）

- **攻击盒**：按帧配在 attackInfo 数据（`CUSTOM_ATTACK_INFO_*` 常量索引），引擎逐帧扫盒。脚本还可 `sq_AddAttackBox(anim,x,y,z,xSz,ySz,zSz)` 动态加盒。
- **防多段**：`sq_SetMaxHitCounterPerObject(maxHit)`（同攻击对单目标最大命中数）。
- **必中/抓取绕过攻击盒**：`sq_SendHitObjectPacket(obj, target, x, y, z)` 直接发命中包。
- **受击反应四参数挂在攻击方的 AttackInfo 上**，命中后引擎应用到受击方：
  - `damageAct`：0 无反应 / 1 僵直 / 2 倒地 / 3 除人形外僵直
  - `upForce` 浮空力、`backForce` 击退力、`hitStunTime` 僵直时长(ms)
  - 击退类型（普通/长退/短退/**无受击时间像素退**/不退）、受击方向（自动/前/后/外侧/内侧）
- **受击方侧基本无脚本参与**，只有拦截钩子：`addSetStatePacket_*` 驳回状态切换；Appendage 钩子 `onApplyHpDamage`（改伤害值）/ `getImmuneTypeDamageRate`（减伤率）/ `onSetHp`（拦截 HP，可免死）/ `onDamageParent`（被击时）。

### 1.5 状态系统

- **STATE 枚举**：0-18 全职业通用 + 19+ 各职业自定义（每个职业一套，编号可撞）。通用段关键项：
  - `STATE_DAMAGE=3` 挨打（硬直受击）
  - `STATE_DOWN=4` **浮空与倒地共用**，靠子编号区分（`sq_GetDownState` 取子状态）
  - `STATE_QUICK_STANDING=18` 快速起身
  - 其余：STAND/SIT/DIE/JUMP/JUMP_ATTACK/ATTACK/HOLD(被抓)/DASH/CROUCH/THROW/BUFF…
- **5 级状态优先级**：0 AUTO（自动收尾）< 1 USER（玩家技能/攻击）< 2 HALF_FORCE < 3 **FORCE（倒地/伤害/投掷——受击类）** < 4 IGNORE_FORCE（抓取）。
- **异常状态（ACTIVESTATUS）18 种**：控制类（眩晕3/冰冻1/石化7/睡眠8/束缚16/混乱15）、伤害类（中毒2/燃烧9/出血11/感电6）、增益（加速12/祝福13）、破甲（武器10/护甲17）。施加带 概率/等级/时长 参数，可被受方 `setActiveStatus_*` 返回 0 拒绝（如 STATE_SPECIAL 下免异常）。
- **僵直时长** = 攻击方 hitStunTime × 受击方硬直率（`CHANGE_STATUS_TYPE_HIT_RECOVERY=34`），具体合成公式未收录（缺口）。

### 1.6 伤害与特效管线

- **伤害双轨**：`sq_SetCurrentAttackBonusRate`（百分比，随攻速面板）+ `sq_SetCurrentAttackPower`（固伤）成对设置；数值从 .skl 表按（技能ID,索引）取：`sq_GetBonusRateWithPassive` / `sq_GetPowerWithPassive` / `sq_GetLevelData`。
- **经 PO 结算的技能**（血爆类）：本体只写包（`sq_StartWrite` + N 个 `sq_WriteDword`）→ `sq_SendCreatePassiveObjectPacket(编号,0,0,0,z偏移)` → PO 端 `setCustomData_po_*` 按写入顺序 `readDword()` 读回 → PO 持攻击信息命中。**"技能参数从角色端序列化传给被动物体"是跨对象传参的标准模式。**
- **纯特效**：`sq_CreateAnimation("","路径.ani")` + `addLayerAnimation` 叠层 + `sq_CreatePooledObject`（对象池）+ `sq_SetEnumDrawLayer` 画层。
- **HP 消耗技（血气系）**：`obj.setHp(obj.getHp() - sq_GetLevelData(...), null, true)`。
- **震屏/闪屏**：`sq_SetMyShake(obj, 8, 300)` / `sq_flashScreen`——在关键帧标记回调里调。
- **Buff 载体 Appendage**：`sq_AppendAppendage` 创建、`sq_SetValidTime(ms)` 持续、ap 脚本 proc 里 `parentObj.getState() != 45` 时 `setValid(false)` 自杀（**生命周期绑定施法者状态**）。

### 1.7 连段/输入窗（三段斩实证）

`onProcCon` 里：帧号门槛后（`frmIndex >= 3`）→ `obj.setSkillCommandEnable(8, true)` **开输入窗** → `sq_IsEnterSkill(8)` 检测再按 → `sq_IntVectPush(下一段子状态)` + `sq_AddSetStatePacket(..., true)` **带参切下一段**。方向修正直接读键：`sq_IsKeyDown(OPTION_HOTKEY_MOVE_LEFT)` → `sq_SetDirection`。

### 1.8 源码包使用注意

- `.nut` 全部是**明文 Squirrel**，可直接读。
- **混有私服改档**：`common_object/share_obj/swordman/*.nut` 局部变量混淆（`QqpuHn5C49sl`）+ 函数名带 QQ 号，引用需谨慎；`outbreak.nut`/`tripleslash.nut`/`bloodboom.nut` 是干净版。
- 官方脚本工程化程度低（五个子状态整段复制粘贴），读时别假设有抽象。

## 2. 我们怎么对应（映射表）

| DNF 机制 | 我们的对应 | 评价 |
|---------|-----------|------|
| .nut 无状态函数集 | `SkillLogic` 无状态类（阶段4） | ✅ **思路被验证**；我们用强类型 LSCast 比它的 getVar 槽更好 |
| 状态存 obj（状态机+getVar+帧号） | 状态存 `LSCast [MemoryPackable]`（阶段4） | ✅ 同构；我们为回滚服务，更严格 |
| pushState 状态ID/技能ID 两套编号 | LSCast.SkillId 单编号 | ✅ 简化合理；**但连段需要 subState**（见建议3） |
| onSetState_* | LSCast 创建 + OnCast | ✅ |
| onProc_*/onProcCon_* | LSCast.LSUpdate → OnUpdate | ✅；我们无需"双方/仅自己"区分（帧同步全端同跑逻辑） |
| onKeyFrameFlag（.ani 帧标记） | AnimFrameData hitFlag/cancelFlag | ✅ **同构，我们设计对了**；DNF 的 [SET FLAG] 就是帧标记数据 |
| onProc 轮询帧号 | LSAnimComponent.FrameIndex | ✅；我们帧状态在逻辑层，比 DNF 更适合帧同步 |
| 引擎扫 attackInfo 盒 | 阶段2 LSHitbox 采样 damageBox/attackBox + 扫盒系统 | ✅ 同构 |
| onAttack 命中回调 | 命中检测 + Route B JustHit 标记 | ✅ |
| sq_SetMaxHitCounterPerObject | HitTargets 集合 | ✅ 对应 |
| 连段输入窗（setSkillCommandEnable + sq_IsEnterSkill + 带参切子状态） | LSInputBufferComponent + cancelFlag | ✅ 方向对；补"逐段开窗"细节（建议4） |
| **CD 在 onEndState 起算** | CooldownMs 在 TryCast 时起算 | ⚠️ **差异**（建议2） |
| checkCommandEnable（状态可出招）/checkExecutableSkill（进CD判键）分离 | TryCast 一次做两件事 | ⚠️ 可简化，但状态可出招表要有（建议5） |
| **受击反应四参数在攻击方 AttackInfo**（damageAct/upForce/backForce/hitStunTime） | **没有**——HitstunTimer 由命中代码写死固定值 | ❌ **缺失**（建议1，最重要） |
| STATE_DAMAGE/DOWN(浮空/倒地子态)/QUICK_STANDING | 只有 HitstunTimer/HitstopTimer | ❌ 缺失浮空/倒地/起身链（建议1） |
| 5 级状态优先级 + addSetStatePacket 拦截 | 无 | ⚠️ 可选；简化为 bool 规则（硬直中不能出招）可先顶住 |
| Appendage 受击被动（减伤/免死/改伤害） | 阶段5 Buff Actions | ✅ 可承载，设计阶段5时记得留受击钩子 |
| PO（被动物体）统一抽象弹道/区域/特效 | 阶段6 Bullet/Area | ✅ 同构；PO 的 setCustomData 跨对象传参模式值得抄 |
| sq_SendHitObjectPacket 必中/抓取 | 无 | 可选（做抓取技时加 DirectHit API） |
| .skl 数值表 (技能ID,索引) 取数 | 技能类 const 调参区 | ⚠️ 我们的 const 方案 OK（已议定），将来迁配表成本低 |
| HP 消耗技 / 震屏闪屏 | 无 | 阶段5/7 顺手加 |

## 3. 建议改动清单（改哪些我们文档，用户定）

1. **【最重要】`04b-阶段3.5-打击感框架`：受击反应改为"攻击方配置驱动"**
   - attack.json / AnimFrameData 增加受击反应字段：`hitStunTime`（僵直ms）、`damageAct`（0无/1僵直/2倒地）、`upForce`（浮空力）、`backForce`（击退力）。
   - LSCombatComponent 保留（受击方计时器），但参数从"命中代码写死"改为"读当前命中攻击的配置"。
   - 补浮空/倒地/起身状态链：受击→(upForce>0?浮空上升→下落→落地→倒地躺平(可追打)→起身) vs (damageAct=2? 直接倒地) vs (僵直)。
2. **`05-阶段4`：CooldownMs 起算点**从 TryCast 成功时改为技能真正结束（OnEnd）时——DNF 实证做法，连段/长动画技能手感更对。
3. **`05-阶段4`：LSCast 加 `SubState` 字段**（int，连段子状态）——DNF `setSkillSubState` 机制，三段斩实证：同一次技能多段，每段是子状态而非新 Cast。
4. **`04b`：连段输入窗补"逐段开窗"**：每段子状态的特定帧后才 `开输入窗`（我们 cancelFlag 已有此意，明确"每段一个窗"）；再按技能键 → 带 SubState+1 切下一段。
5. **`05-阶段4`：LSSkillComponent 加"当前状态可出招"检查表**（哪些状态下能放哪些技能）——对应 checkCommandEnable；先用简单规则（硬直/倒地/施法中禁），以后扩。
6. **`07-阶段6`：PO 跨对象传参模式**——Bullet/Area 创建时支持携带参数包（伤害值/来源技能ID），对应 setCustomData_po 模式。
7. `05-阶段4` SkillContext 预留 `DirectHit(target)`（必中/抓取，绕过攻击盒）。
8. `06-阶段5` Buff 设计时留**受击钩子**（受击方挂 buff 改伤害/减伤/免死）——DNF 的受击被动全在 Appendage 上。

## 4. 遗留/待验证

- STATE_DOWN(4) 的子编号取值表（浮空上升/下落/躺地怎么编号）——知识库未收录。
- 普通起身（非快速起身）的状态转换机制；倒地追打/落地弹跳规则。
- 僵直时长 × 硬直率(HIT_RECOVERY) 的合成公式。
- 多段命中的间隔规则（hit interval 如何受攻速影响）。
- `pushState` 同名状态重复注册（同状态绑不同技能ID）的优先级规则。
- `sq_GetBonusRateWithPassive` 第2参 `-1` 的确切语义。
- KNOCK_BACK_TYPE / HIT_DIRECTION 的 setter 函数签名。
- 私服混淆文件与原版的边界（引用 common_object 下文件前先确认）。
