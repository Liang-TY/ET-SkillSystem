## 0. 资料三层结构（先懂这个再读任何东西）

DNF 的内容分三层，**读的顺序永远是 ③→①→②**（先读人整理的知识库，再拿配置和脚本验证）：

| 层 | 位置 | 内容 | 说明 |
|----|------|------|------|
| ① PVF 配置数据 | `dnforigin/pvf源码提取部分/pvf/` | .skl（技能配置）/.ani（动画）/.etc（怪物等）/map/dungeon | 数据表，策划配置层。**量大，别通读，按需查** |
| ② SQR 脚本逻辑 | `pvf/sqr/` | .nut 文件（**Squirrel 脚本**，技能/怪物AI/Buff 的逻辑代码） | DNF 的"热更代码层"，相当于我们 Hotfix 层。**技能怎么写的真相在这** |

| ④ 网络资料（格式逆向） | WebSearch/WebFetch | NPK/IMG/.ani 等**文件格式**的社区逆向文档（DNF 模组/提取工具社区） | 格式细节（坐标/字段语义）知识库没讲的，**上网查**并记录来源 |

## 2. 初步侦察发现（本轮快扫的结论，供后续验证）

1. **DNF 技能逻辑 = Squirrel 脚本（.nut）**，在 `sqr/` 下。配置（.skl）和逻辑（.nut）分离——跟我们的"技能配置 + SkillLogic 类"思路一致，方向没错。
2. **知识库 16 篇几乎覆盖 Q1/Q2/Q4/Q5/Q8/Q9/Q10/Q11 的入门**，且带真实 API。**第一轮应以知识库为主、源码为辅**（人整理过的效率高一个数量级）。
3. **`.ani.als` 与 `.ani` 同名并存**（如 `bstart2_6blackdust.ani.als`），遍布各 animation 目录。初步猜测是动画的伴随附加配置（事件表/附加属性），**具体格式待 Q1 验证，别当结论**。
4. `passiveobject` 目录既有配置也有逻辑——DNF 的弹道/持续区域/召唤物统一叫"被动物体"，**这套抽象跟我们阶段6的 Bullet/Area 统一抽象思路可以互证**。
5. `appendage` 是 DNF 对 Buff/状态/被动的总称，目录下按类型分子目录（changestatus/changeattackinfo/equipment...）。
6. 顶层 `哪些没提取.txt` 记录了提取缺口，查东西找不到时先看它。

## 3. 多轮工作流（新会话照此执行）

### 3.1 开场阅读顺序（固定，别颠倒）

```
① 读本文档（00-总览）           → 知道研究计划、进度、本轮范围
② 读【我们项目】的现状与设计     → 建立比对基准（读哪些见 §3.2）
③ 主会话从我们设计里提炼"问题清单" → 我们不确定/简陋/没设计的点，如"DNF 取消窗口是状态切换还是帧标记？"
④ 多 agent 并行读 DNF 资料       → 带着问题清单提取（agent 只管客观提取，不读我们项目）
⑤ 主会话综合映射 → 写总结 → 回写进度
```

**核心原则：先读我们项目（知道要问什么），再读 DNF（带着问题找答案）。**
反过来（先 DNF 后项目）= 漫无目的的考古，总结落不到点上。

### 3.3 每轮产出流程

**① 新建总结文档**：`Notes/dnf源码研究/NN-课题名-总结.md`（NN=轮次号），固定四段：

```
## 1. DNF 怎么做的        （机制 + 关键 API/文件清单，如生命周期事件全表）
## 2. 我们怎么对应        （映射表：DNF 的 X → 我们的 Y；我们没有的标"缺失"）
```

**② 回写本文档 §4 进度表**（状态 ✅ / 产出文档名 / 日期）。

研究轮只产结论，**不直接改** `Notes/技能系统/` 等设计文档——"建议改动"由用户决定后另改，避免边研究边改乱套。

### 3.4 并行 agent 分工模式

**原则：并行读、串行写。** 读和提取可多 agent 并行（资料是独立文件）；综合映射和写总结必须主会话一个脑子做（连贯性 + 交叉结论产生在课题交界处）。

```
分工示例（第一轮的完整 4-agent 方案见 §5）：

Agent A：读知识库 01-角色事件函数 + 02-技能系统
         → 产出：技能生命周期事件全表 + 各事件触发时机
Agent B：读知识库 03-状态系统
         → 产出：DNF 状态全表 + 切换规则
Agent C：读源码 sqr/character/atswordman_load_state.nut + 1-2 个鬼剑士技能 .nut
         → 产出：真实代码如何使用这些 API（验证知识库、纠正偏差）
Agent D：格式类专查（如 Q14 坐标系/包围盒）
         → 知识库相关篇 + 我们仓库实样对照 + WebSearch 社区逆向文档
         → 产出：坐标系对照表 + 格式结论（记来源）

主会话：  读我们项目设计（§3.2）→ 提炼问题清单 → 把问题塞进各 agent 的提取目标
         → 汇总所有 agent → 写总结（映射+建议） → 更新进度表
```

注意：
- Agent 2-4 个够，读深 > 读多。
- 同轮课题要相关（服务于同一综合目标）；无关课题才开并行轮。
- Agent 的提示词里要嵌入主会话提炼的问题清单（agent 不读我们的项目文档）。

### 3.5 铁律

- 每轮聚焦 1-2 个主课题（+至多 1 个可完全并行的轻量格式类课题，如 Q14）。
- 总结必须落到"对我们项目的指导"——纯 DNF 考古没价值。
- .skl/.ani 等二进制/未知格式文件，先用 file/xxd 看头判断格式，读不懂记"待解"，不硬猜。
- 知识库是二手资料，关键结论要用源码（②层 .nut）验证过才算数；**格式类结论（Q14 类）优先用 ④网络逆向文档，也要记录来源链接**。
