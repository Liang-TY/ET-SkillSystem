# 第二轮总结②：DNF 复杂技能案例拆解（弹道/抓取/召唤变身）

> 课题：Q7——不同原型的高级技能怎么写。
> 样本：冰波动剑 wavecut（弹道·链式）、崩山击波 grandwave（弹道·平移）、飓风超级过肩摔（抓取）、噬魂之手（抓取·不可抓分支）、召唤克鲁塔（召唤）、贝亚娜变身（变身）。
> 用途：给阶段4 SkillLogic / 阶段6 投射物 / 以后的抓取召唤做上限验证。**只列建议，改不改用户定。**

---

## 1. DNF 怎么做的

### 1.1 弹道类的三种形态

| 形态 | 样本 | 机制 | 适用 |
|------|------|------|------|
| **链式生灭** | 冰波动剑（PO 24328） | 不移动！第一段 PO 播 10ms 后在 `sq_GetDistancePos` 处**生下一段 PO**（同编号、段数+1），链式接力到 maxCount 段；终结段播爆炸+自毁 | 地波类；天然支持**每段属性不同**（后段伤害/异常可变） |
| **插值平移** | 崩山击波（PO 11/12/13） | 单 PO，出发时记 `[x0,xTarget]`，每帧 `sq_GetUniformVelocity` 匀速插值 `sq_setCurrentAxisPos(0,x)`，到 maxDistance 销毁 | 直线弹道 |
| **引擎托管一次性** | 爆炸帧用 `sq_createAttackObjectWithPath(obj, ani路径, atk路径, false, 倍率, size,…)` | 给定 ani+atk 直接生成一次性攻击对象，引擎代管生灭 | 瞬时爆炸判定 |

**弹道通用模式**：
- **传参协议**：`sq_StartWrite + N×WriteDword → SendCreatePassiveObjectPacket(编号,…)` ↔ PO 端 `setCustomData_po_*` 按序 `readDword()`（纯位置协议）。
- **多段间隔命中**：`obj.setTimeEvent(0, attackTerm, 0, false)` 定时 → 每 tick `obj.resetHitObjectList()` **清空已命中名单**——穿透弹道对同一目标按间隔反复结算（全库 364 处，多段 PO 标配）。
- **异常状态注入攻击信息**：`sq_SetChangeStatusIntoAttackInfo(attackInfo, 0, ACTIVESTATUS_FREEZE, 概率, 等级, 时长)`——命中即判定冰冻，不用在 onAttack 里写。
- **攻击盒随视觉缩放**：`sq_SetAttackBoundingBoxSizeRate(ani, r, r, r)`。
- **PO 销毁钩子必须回收视觉对象**（pooledObj），否则特效悬空。
- **onAttack 只做追加**（控制/特效/挂debuff），伤害本体在 attackInfo 数据里随引擎碰撞结算。

### 1.2 抓取类的双人状态同步

**判定（onAttack 里三查）**：
```
sq_IsGrabable(obj,damager) && sq_IsHoldable(obj,damager) && !sq_IsFixture(damager)
  && damager.isObjectType(OBJECTTYPE_ACTIVE)
成立 → obj.getVar().push_obj_vector(damager)   ← 受害者登记（可多个）
     + 挂 appendage（锁：parent=受害者 source=抓取者）
     + sq_HoldAndDelayDie(受害者, 抓取者, …, ap)  ← 受害者打入 STATE_HOLD(9)
```
BOSS 通常 fixture → 不可抓 → **抓空分支**：落空子状态 + `sq_SendHitObjectPacket` 直接补一发伤害结算（不可抓≠免疫）。

**同步（appendage 是跑在受害者身上的小状态机）**：
- 抓取者 `ap.setState(n)` 驱动受害者阶段（1=lerp到抓取者面前、2=升空、3=倒挂头顶）。
- 位置编排两种：**插值跟随**（`sq_GetUniformVelocity` 三轴 lerp）或**关键帧挂点表**（onKeyFrameFlag flag100~106 → 受害者钉在抓取者身上 (dx,dy,朝向) 轨迹——肘击连投的甩人）。
- **锁的失效**：`proc` 里 `source.getState()!=技能状态 || source.subState==终结段 → setValid(false)`——主人技能中断自动松绑，防悬挂。
- `onEnd`：复原倒转/姿态 + `sq_SimpleMoveToNearMovablePos(受害者,5000)` 防扔进墙。

**结算**：伤害不在抓取瞬���，在**终结帧**（爆炸 PO 或 HitObjectPacket）；**投出** = 移除 appendage + 受害者强制 `STATE_DOWN(4) + intVector[反向,…,抛力900/1600,…]`（受击表现绕过 damageAct，直接下发状态参数）+ 抓取者收招 500ms 无敌（`OBJECT_MESSAGE_INVANCIBLE` 开/延迟关）。

### 1.3 召唤（引擎 Monster + 标记 PO 握手 + appendage 寄生 AI）

1. `SummonMonsterPacket(施法者, 怪物ID, 队伍, 等级, 存活ms, x,y,z, 朝向)`——召唤物是**引擎级 Monster（ActiveObject）**，非 PO 非角色。
2. **异步拿引用的握手**：SummonMonsterPacket 是异步的，脚本拿不到直接引用 → 同时发一个**标记 PO（z=1111 暗号）**，PO 的 proc 轮询扫到新出生的该 ID 怪 → `sq_SendChangeSkillEffectPacket` 回执（带怪的 group/uniqueId 三元组）→ 施法者 `onChangeSkillEffect_*` 里 `sq_GetObject(mgr, group, uniqueId)` 接生（挂 AI appendage + `setMapFollowParent` 跨房间跟随）。
3. **AI = 挂在召唤物身上的 appendage**：timer_vector（每种攻击一个可调间隔计时器）+ `sq_FindTarget` 索敌 + `sq_AddSetStatePacketActiveObject(怪, STATE_ATTACK, [攻击分支])` 命令怪出招；**召唤物每次攻击的倍率经 `onSourceKeyFrameFlag` 实时取主人面板**（`sq_GetBonusRateWithPassive(主人, 技能,…)`）。
4. **寿命**：appendage 失效/主人死亡 → `sendDestroyPacket` 自毁（另有 summonTime 引擎到期杀）。
5. **单键多行为**：checkExecutable 先找"自己的存活召唤物"（按 appendage 里存的施法者判定归属，多人互不干扰）——有→召回分支；无→召唤；召唤中→警告。**指挥技**（repeatedsmashofrage）= 单独技能键，checkExecutable 找到自己的怪才可用，向怪发攻击指令。

### 1.4 变身（双 appendage 架构）

- **icon appendage**：`sq_SetValidTime(时长)` 管倒计时 + `sq_AddChangeStatus/addParameter` 通用属性修改通道（HP_MAX/攻防/攻速…）。
- **形态 appendage**（无时限）：proc 里 `obj.setSkillCommandEnable(83,false)` **屏蔽技能=技能替换的实现**（不换 UI 栏位，只开关可用性）；监视 icon appendage 到期 → 强制还原态；`sq_SetCustomDamageType` 持续改伤害类型；出图自动解除。
- 一键双态：checkExecutable 按"是否已挂形态 appendage"分流（变身中按键=解除）。

### 1.5 浮空/受击反应实战值（直接抄给调参）

| 场景 | damageAct | upForce | backForce | hitStunTime |
|------|-----------|---------|-----------|-------------|
| 普通连段命中（枪手 killpoint） | 1(僵直) | **10** | **3** | 默认 |
| 终结段击飞 | **2(DOWN)** | **300** | **300** | — |
| 多段持续 PO（防每跳硬直） | — | — | — | **设 0** |
| 上挑类（wind strike） | — | `sq_GetLevelData(列2)`（技能表配） | — | — |
| 施法中变相霸体 | 把来犯攻击的 DamageAct 临时改 NONE（先存后改，onAfterDamage 还原） | | | |

程序化抛体：上升 `sq_GetAccel(0,270,t,500)`，下落 `sq_GetUniformVelocity(zTop,0,t,800)`。

### 1.6 共性模式（六条，跨原型）

1. **对象+包+钩子三件套**：一切异步行为 = Write* 序列化 → Send*Packet → 对端具名钩子读包执行；只有 `isMyControlObject()` 端发权威包（≈帧同步的指令-表现分层）。
2. **appendage 是万能副作用容器**：debuff/控制锁/召唤AI/变身形态/属性 buff 全是它（parent/source 双引用 + ValidTime + proc/onChangeState/onSourceKeyFrameFlag/onEnd/drawAppend 钩子 + timer_vector）。
3. **状态机分型**：老技能=引擎内置+脚本钩子；新技能=纯脚本子状态机（subState switch + onEndCurrentAni/onProc/onKeyFrameFlag 推进）。
4. **伤害结算与受击表现解耦**：伤害=attackInfo 数据随碰撞走；脚本只追加；抓取/投掷完全绕过 damageAct 直接操纵受害者状态。
5. **对象寻址三元组**：group+uniqueId+GetObject——跨实体引用绝不经裸指针。
6. **清理责任到钩子**：PO destroy 回收视觉对象；appendage onEnd 复原姿态；召唤物随锁失效自毁——**泄漏=不同步，当硬规范**。

## 3. 建议改动清单

1. **`07-阶段6`：LSBullet 支持两种多段命中模式**——①整轮一次性（现有 HitTargets，攻击结束清空）；②**按间隔反复命中**（HitTargets 定时清空，`setTimeEvent + resetHitObjectList` 等价物，穿透/持续弹道用）。
2. **`07-阶段6`：加"一次性攻击对象"概念**——`SkillContext.SpawnOneShotAttack(动画clip, 攻击信息, 时长)`：瞬时判定体，播完自毁（爆炸帧/落点判定用，DNF `sq_createAttackObjectWithPath` 等价物）。≈ 短命 LSArea 特例。
3. **`04b`/AnimClipData：加霸体帧标记**（DNF `[DAMAGE TYPE] SUPERARMOR`）+ 命中检测检查霸体（霸体帧不受击反应，只扣血）——三查里最常用的一条。
4. **`05-阶段4`：ReplaceSkill 实现定案**——用"禁用旧技能 ID"（技能可用性开关表）而非换槽位；变身=倒计时 Buff + 形态 Buff 双层。
5. 召唤物（以后做）：LSUnit+AI 直接创建（我们比 DNF 简单）；**召唤物每次攻击的伤害倍率实时取主人 LSNumericComponent**（借鉴 onSourceKeyFrameFlag 模式）。
6. **`07/08`：清理规范写死**——Bullet/Area 的 Dispose 必须回收全部视图对象；Buff 移除必须复原所有状态（姿态/属性/屏蔽的技能）——**帧同步下泄漏=不同步**。
7. `04b` 调参参考值直接采用 §1.5 表（轻击 upForce=10/backForce=3；终结段 DOWN+300/300；多段 PO hitStun=0）。

## 4. 遗留/待验证

- 老技能（崩山击/经典过肩摔 state23）本体在 C++ 引擎，脚本层只有钩子——行为细节不可考（对我们影响小：新写法全脚本反而是我们要学的）。
- `sq_HoldAndDelayDie` 第 6/7 参确切语义（wavecut 传 200,200、suplex 传 0,0）——做抓取时再深挖。
- `SummonMonsterPacket` 的 aiType 参数怎么工作（引擎侧）。
- 蓄力机制（`sq_IsEnterSkillLastKeyUnits`）。
