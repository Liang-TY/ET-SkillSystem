# DNF 动画系统整体架构：一篇看懂

> 目的：把 01~08 号文档里的碎片知识拼成**一张总图**——整体框架是什么、流程怎么走、每个配置文件起什么作用。
> 不引入新结论，只做梳理。看完这篇再回去翻细节文档就不迷路了。

---

## 0. 一句话总纲

**DNF 的"动画系统"不是一个独立模块，它是状态机的"表现输出" + 碰撞判定的"数据载体"。**

动画播放本身很简单（按帧换贴图），但 DNF 把三样东西**编进了动画的帧数据里**：
1. **碰撞盒**（每帧的攻击盒/受击盒）——判定跟帧走
2. **帧标记**（SET FLAG）——播到某帧通知脚本干活
3. **渲染效果**（染色/加法混合/缩放）——特效跟帧走

所以理解 DNF 动画 = 理解"**帧数据是一切的节拍器**"。

## 1. 三层职责：引擎 / 脚本 / 数据

## 2. 数据层的六个文件——各自是什么角色

用"拍电影"打比方：

| 文件 | 比喻 | 实际内容 | 谁读它 |
|------|------|---------|--------|
| **`.img`** | 胶片素材 | 贴图集：一张张序列帧位图（在 NPK 包里） | 引擎渲染时按 .ani 的引用取图 |
| **`.ani`** | 分镜剧本 | **一个动作的帧序列**：每帧用哪张图、摆哪、停多久、盒多大、带什么标记/音效/渲染效果 | 引擎（播放/扫盒） |
| **`.ani.als`** | 后期特效单 | 往这个动画上**叠加特效层**的清单（哪帧开始、贴哪层）——不改原剧本一个字。**纯装饰、无判定**；技能真正的"会打人的特效"是 PO 被动物体（详见 10-技能特效架构.md） | 引擎加载 .ani 时自动应用 |
| **`.atk`** | 这招的"威力设定" | **命中后的属性**：伤害修正/浮空力/击退/僵直/命中方向/受击模式。**没有盒几何**（盒在 .ani 帧里） | 引擎命中时读 |
| **`.chr`** | 角色的"资源总菜单" | 把**数字索引**映射到 .ani/.atk 路径（[etc motion] 第 262 行=某动画）+ 角色基础数据 | 引擎（查表） |
| **`.skl`** | 这招的"说明书" | 技能数值：指令/CD/MP消耗/每级伤害列 | 引擎（消耗/CD）+ 脚本（取数值） |
| `.nut` | 导演的工作手册 | 技能/状态的行为逻辑（不是"数据"，是代码） | 引擎按函数名回调 |
| `.act` | 群演的简易手册 | 怪物/AI 的帧级行为（另一条链，与玩家技能无关） | 引擎 |

**为什么要有 .chr 这个"菜单"？** 脚本里写的是 `sq_SetCurrentAnimation(CUSTOM_ANI_XXX=262)` 这种**数字**，不写路径。引擎拿 262 去查这个角色 .chr 文件的 [etc motion] 表第 262 行，才知道"哦是 `Animation/tripleslash_bladespirit1.ani`"。好处：脚本短、换皮只改 .chr。

## 3. 一个 .ani 文件的解剖（帧剧本长什么样）

```
attack1.ani（鬼剑士普攻第一段，示意）
┌ 顶层 ────────────────────────────────┐
│ [FRAME MAX] 10          ← 共 10 帧    │
│ [LOOP]（不写=播完即停，状态机接管）      │
│ [SHADOW] 1               ← 有脚底影    │
├ 帧 0 ────────────────────────────────┤
│ [IMAGE] `sm_body%04d.img` + 0  ← 用哪张图│
│ [IMAGE POS] -249 -301        ← 图摆角色锚点哪 │
│ [DELAY] 50                   ← 停 50ms      │
│ [DAMAGE BOX] -9 -5 -6 55 10 100 ← 这帧的受击盒│
│ [PLAY SOUND] SM_BOONGSAN      ← 这帧出声      │
├ 帧 1~4（同结构，各有各的盒子）──────────┤
│ [ATTACK BOX] 25 -15 26 61 20 48 ← 攻击判定帧! │
│ [DAMAGE TYPE] SUPERARMOR       ← 这帧霸体      │
├ 帧 5~9（收招，盒子消失）────────────────┤
└───────────────────────────────────────┘
同名 attack1.ani.als（自动生效）：第 0 帧起叠一层剑光特效（z序+9999，画在身前）
```

**关键理解：盒子是帧的属性，不是技能的属性。** 第 0 帧没攻击盒（还没挥出去）、第 5 帧有（刀挥到了那里）——判定窗口天然由帧序列表达。这就是我们 hitFlag/attackBox 设计的同源逻辑。

> ⚠️ **上面的 [IMAGE] 只引用身体皮肤层**——角色是**多层合成**的，详见 §3.5。

## 3.5 角色多层合成（纸娃娃换装）★

上节 .ani 每帧只有**一个** `[IMAGE]`（`sm_body%04d.img`），只引用身体皮肤。那武器/上衣/裤子的图哪来？——**引擎按装备的层配置，用同一帧号去各层的 img 文件取图合成。**

### 3.5.1 机制

```
角色状态机 → 查 .lay/.chr → 得到当前 .ani → .ani 给出帧号 N

身体层：  sm_body0000.img  ← 帧 N            ← .ani 直接引用
上衣层：  coat_a0185.img   ← 帧 N            ← 引擎按 .equ [layer variation] 注册
裤子层：  pants_a0185.img  ← 帧 N            ← 同上
鞋层：    shoes_a0185.img  ← 帧 N
武器前：  sswdc0011.img    ← 帧 N            ← 武器 c=front 层
武器后：  sswdb0011.img    ← 帧 N            ← 武器 b=back 层
…
全部子层共享帧号 N → 完美同步（setCurrentFrameWithChildLayer API）
```

### 3.5.2 层从哪来

- **.ani 只管身体层**：每帧 1 个 `[IMAGE]`（`sm_body%04d.img`），无任何层字段。武器/衣服的图不在 .ani 里。
- **装备 .equ 注册子层**：`[layer variation] 层号 资源组名` → 如 `2300 coat_c`；`[variation] 变体号` → 如 `185`。引擎拼出 img 文件名 `coat_c0185.img`，注册为该角色的一个子层。
- **皮肤是 base 层**：路径来自 `.chr [body image path]`，不走 .equ。
- **换装 = 换层**：脱上衣→引擎移除该子层；穿上衣→按新 .equ 注册新子层。

### 3.5.3 层号 = z 序（升序 = 底→顶，画家算法）

| 层号 | 资源组名 | 部位 |
|------|---------|------|
| 0 | sm_body | 皮肤（最底） |
| 100 | face_b | 脸 |
| 500 | coat_d | 上衣后摆 |
| **650** | sswdb/katanab/clubb/lswdb | **武器背层**（b=back） |
| 1800 | coat_a | 上衣主体 |
| 2000 | hair_a | 前发 |
| 2500 | cap_c | 帽顶 |
| **2790** | sswdc/katanac/clubc/lswdc | **武器前层**（c=front） |
| 2860 | （光环） | 最顶 |

千位 = 身体大区（0xxx=身体/脸/后摆/武器背；1xxx=腿/腰/鞋；2xxx=躯干/发/帽/武器前/光环）。

### 3.5.4 武器前后两层靠"空帧"切换

- **b 层(650)** = 武器背后/收刀态：在身体后摆之上、腿之后。挥击时该层 img 对应帧为透明（不画）。
- **c 层(2790)** = 武器身前/挥击态：在所有衣物之上。收刀时该层 img 对应帧为透明。
- **两层每帧都画**，靠 img 帧内容本身（有/无像素）决定哪层可见——**不是引擎按状态切层，而是贴图帧内容决定显示**。

### 3.5.5 怪物不分层

怪物 .mob 没有 `[equipment]`/`[layer variation]`；怪物 .ani 每帧只有 1 个 `[IMAGE]`（如 `Monster/Bantu/BantuAmazones.img`），**单层，不能换装**。

### 3.5.6 .als 与此体系无关

.als 的 z 序(±9999) 是给"动画帧挂技能特效子动画"用的（[use animation]+[none effect add]），不是角色部件的 z 排序。角色部件层(0-2860) 与场景对象层(ENUM_DRAWLAYER_*)、.als 特效层是**三套独立的 z 系统**。
│ [SHADOW] 1               ← 有脚底影    │
├ 帧 0 ────────────────────────────────┤
│ [IMAGE] `sm_body%04d.img` + 78   ← 用哪张图│
│ [IMAGE POS] -249 -301        ← 图摆角色锚点哪 │
│ [DELAY] 50                   ← 停 50ms      │
│ [DAMAGE BOX] -9 -5 -6 55 10 100 ← 这帧的受击盒│
│ [PLAY SOUND] SM_BOONGSAN      ← 这帧出声      │
├ 帧 1~4（同结构，各有各的盒子）──────────┤
│ [ATTACK BOX] 25 -15 26 61 20 48 ← 攻击判定帧! │
│ [DAMAGE TYPE] SUPERARMOR       ← 这帧霸体      │
├ 帧 5~9（收招，盒子消失）────────────────┤
└───────────────────────────────────────┘
同名 attack1.ani.als（自动生效）：第 0 帧起叠一层剑光特效（z序+9999，画在身前）
```

**关键理解：盒子是帧的属性，不是技能的属性。** 第 0 帧没攻击盒（还没挥出去）、第 5 帧有（刀挥到了那里）——判定窗口天然由帧序列表达。这就是我们 hitFlag/attackBox 设计的同源逻辑。

## 4. 完整流程走一遍：按 X 键 → 怪物挨打

```
 ① 按 X 键
    ↓ 引擎（普攻不是技能，走原生状态）
 ② 角色切进 STATE_ATTACK(8)
    ↓ 引擎回调脚本：getAttackAni_(obj, 0)？getDefaultAttackInfo_(obj, 0)？
 ③ 脚本回答：动画=索引N，攻击信息=索引M
    ↓ 引擎查 .chr 菜单：索引N → attack1.ani；索引M → attack1.atk → 加载
 ④ 引擎开始播 attack1.ani
    · 每帧按 [DELAY] 停留
    · 按 [IMAGE]+[IMAGE POS] 把 .img 里的图摆到角色位置（含 .als 特效层）
    · 按 [RGBA]/[GRAPHIC EFFECT] 渲染
 ⑤ 播到有 [ATTACK BOX] 的帧
    ↓ 引擎扫碰撞：这帧的盒子 × 当前 .atk → 撞到怪物的受击盒？
 ⑥ 命中！
    ↓ 引擎读 attack1.atk 的反应参数（lift 75/push 30/僵直）
 ⑦ 怪物被切进 STATE_DAMAGE(3)，播它自己的 damage1.ani（受击动画），扣血
    ↓ 硬直结束，怪物回 STATE_STAND
 ⑧ 同时：引擎记下"这帧这怪已打"（防一帧多段）
 ⑨ 播到 cancelStartFrame 后玩家又按了 X
    ↓ 引擎切子状态 1 → attack2.ani（第二段，.atk 反应更重）
 ⑩ 三段打完（attack3.atk：击飞 DOWN+lift300）→ 怪物进浮空/倒地链
 ⑪ 动画播完 → onEndCurrentAni 回调 → 脚本切回 STATE_STAND
```

**技能（如波动剑）多两步**：按 Z → 脚本 checkExecutableSkill（sq_IsUseSkill 校验 CD/MP）→ 切技能状态 → onSetState 里设动画+攻击信息+**伤害数值（从 .skl 按等级取）** → 之后同 ④~⑦；另外帧上的 [SET FLAG] 会回调脚本 onKeyFrameFlag，脚本在那时**创建弹道 PO**——PO 自己播它的 .ani、带它的 .atk，飞出去再命中。

## 7. 一页速查

```
看到 .img   → 像素（贴图）
看到 .ani   → 动作剧本（帧序列：图/摆位/时长/盒子/标记/效果）
看到 .als   → 动画的特效叠加清单（同名自动生效，纯装饰无判定；会打人的特效=PO）
看到角色多层 → .ani只驱动身体层，武器/衣服的图由引擎按.equ的层配置用同一帧号对齐取图合成
看到 .atk   → 攻击命中属性（浮空/击退/僵直——盒子不在这！）
看到 .chr   → 角色资源菜单（数字索引→文件路径）
看到 .skl   → 技能数值表（CD/MP/每级伤害）
看到 .nut   → 行为脚本（Squirrel 代码）
看到 .act   → 怪物行为脚本（与玩家技能无关）

引擎职责：状态机/播放/扫盒/受击/渲染
脚本职责：什么时候用什么（回调+指令）
数据职责：素材
铁律：帧数据是节拍器（判定窗口/特效时机/标记全按帧走）
```
