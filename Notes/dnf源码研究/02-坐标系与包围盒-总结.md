## 1. DNF 怎么做的（坐标系结论）

### 1.1 结论速览

| 坐标 | 基于什么原点 | 单位 | 正方向 | 用途 |
|------|-------------|------|--------|------|
| IMG 帧 `X/Y` | 帧画布（FrameWidth×FrameHeight）**左上角** | 像素 | x 右正、**y 下正**（图像坐标） | 位图在画布内的摆放偏移 |
| `FrameWidth/Height` | — | 像素 | — | 帧画布尺寸（本图集统一 500×500），**运行时定位不需要它**，属编辑器画布元数据 |
| .ani `[IMAGE POS]` | **角色锚点 = 脚底中心**（地面与身体中轴交点） | 像素 | x 右正、**y 下正**（-301 = 在脚上方 301px） | 帧画布左上角相对锚点的位置 |
| `[DAMAGE BOX]` | 角色逻辑位置（脚底中心，z=0 地面） | 像素 | x 右正（**规范朝向=面右**）；y=纵深；**z=高度（上正）** | 受击盒，6 值 minX minY minZ maxX maxY maxZ |
| `[ATTACK BOX]` | 同上 | 像素 | 同上 | 攻击盒，同格式，判定帧才有 |
| DNF 世界坐标（nut getXPos 等） | 房间 | 像素 | x 右正；y=纵深（上下键）；z=高度（跳跃） | 官方公告"Y轴：250 PX"即纵深判定 |

**最容易搞错的点：DNF 的 y 不是上下屏幕，是地面纵深；z 才是高度。** .ani 的 IMAGE POS 是纯屏幕 2D 坐标（x、竖直y），和盒子的 3D（x、纵深y、高度z）是两套 y。

### 1.2 摆位公式（实证，误差 ≤2px）

```
位图左上角(相对角色锚点) = [IMAGE POS] + (IMG帧x, IMG帧y)     ← y 向下为正
```

**实证铁律**（核了 30+ 帧无一例外）：`imagePos.y + imgY + 位图高 ≈ 0~1 像素`——**位图底边正好落在脚底原点**。DNF 美术是"画布 500×500 固定、精灵悬在画布中部、.ani 里逐帧用 imagePos 抵消画布偏移"来制作的。imagePos 是 -301 这种大负数，主要在抵消画布内偏移（y≈195..280），不是精灵尺寸。

我们的实测表（BantuAmazones，帧画布 500×500）：

| 帧 | 位图 w×h | IMG x,y | imagePos | 位图左上=和 | damageBox x / z |
|---|---------|---------|----------|-----------|-----------------|
| 0(stay) | 53×107 | 216,195 | -249,-301 | (-33,-106) | x[-21..44]，z[-5..106] |
| 9(move0) | 54×101 | 222,201 | -249,-301 | (-27,-100) | x[-16..29]，z[-5..106] |
| 12 | 57×103 | 229,199 | -259,-301 | (-30,-102) | x[-13..26]，z[-5..106] |

### 1.3 z=高度的铁证

- 倒地动画 `fallen_asil/down.ani`：站立帧 z 0..108 → 倒下过程 0..34 → 躺平帧 **0..5**（高度塌了），同时 x 扩到 -59..113（身体放平摊开）、y 恒 -5..10（厚度不变）。
- 地板攻击特效 ATTACK BOX：z **0..10**（贴地薄饼）、y -19..36（纵深展宽）。
- ⚠️ **信源警告**：GitHub heihuo000/DNF-PVF-file-Reference 声称"Y轴上下、Z轴前后"——与全部硬数据矛盾（该库有 AI 生成痕迹），**不采信**；其 IMAGE POS/盒子功能描述与实测一致可用。

### 1.4 包围盒怎么来的：**逐帧手配，不是自动算**

证据：① 213188 帧里只有 92 处 DAMAGE BOX / 53 处 ATTACK BOX（自动算法不会"大部分帧没盒"）；② 盒与位图剪影不一致（stay 帧：位图 x[-33..20]，盒 x[-21..44]，右侧超位图 24px 是武器/预判余量）；③ 有 min>max 倒序脏数据（人手敲的）；④ 盒形随帧快速变形且只在活跃帧出现——典型格斗 frame data 手工打磨。社区有可视化 .ani 编辑器（梦太晓 Ani 编辑工具）。**运行时不做自动剪影碰撞，确定。**

### 1.5 .ani 帧字段全集（213188 帧统计）

`[IMAGE]` `[IMAGE POS]` `[DELAY]` `[GRAPHIC EFFECT]` `[RGBA]` `[DAMAGE TYPE]`（含 SUPERARMOR 霸体帧标记）`[IMAGE RATE]`（缩放/负值=水平翻转）`[IMAGE ROTATE]` `[INTERPOLATION]` `[ATTACK BOX]` `[DAMAGE BOX]` `[FLIP TYPE]` `[PLAY SOUND]` **`[SET FLAG]`**（关键帧标记，对应 onKeyFrameFlag 回调）`[SHADOW]` `[LOOP]` `[COORD]`

## 2. 我们怎么对应（采样公式 + 一个现行 bug）

### 2.1 ⚠️ 发现现行代码 bug：`LSSpriteAnimViewComponentSystem` 的 imagePos 偏移不完整 —— ✅ 2026-08-17 已修复（阶段3.5）

**暴露现象**：接入 kneekick 攻击动画后，起手瞬间角色左漂 0.81 单位、收招帧回来。Idle/Move 一直"正常"——它们各帧 NpkSprite.X 聚在 216~229 误差一致；膝踢帧 X=259~290，缺项暴露。

**根因**：旧代码 `localPosition = imagePos / 100`（pivot 0.5,0.5）——imagePos 锚定的是**帧画布**（500×500），内容中心真实位置还要加 `(X,Y)+(w/2,h/2)`（y 翻转），`X + 宽/2` 项被丢了。

**修复实现**（视图层三处，逻辑层零改动）：

> **✅ 最终方案（2026-08-18 阶段6 弹接入后升级为绝对公式）**：相对修正只对"imagePos 量级相同"的资源成立
> （角色 -301 vs 波动剑 -106，差 2 单位高）。最终实现（单位+弹+以后所有资源共用）：
> `renderer local = ((imagePos.x + X + 宽/2)/100, -(imagePos.y + Y + 高/2)/100) − prefab中间层偏移`
> 其中 **prefab 中间层偏移运行时自标定**（renderer.parent 世界位 − 根GO 世界位，即 Unit2D prefab 里烤的补偿常数 C≈(2.4,3.5)，直读不硬编码）；
> 图集侧 AtlasOffsets（相对校准帧）已替换为 **AtlasCenters（绝对内容中心 = X+宽/2, Y+高/2）**。
> stay 帧 0 实测（53×107@216,195）代入验证：单位渲染值与旧公式完全一致（数学等价），任意画布尺寸资源自动落对。
1. `LSAnimResComponent.FrameOffsets`（`Dictionary<int, Vector2>`，8 字节/精灵，运行时字典不落盘）：建图集时按**校准帧 = 图集首个实体帧**（= idle 首帧）算相对修正 `dx = X+w/2 − (X₀+w₀/2)`，`dy = −(Y+h/2) + (Y₀+h₀/2)`
2. `LSAnimResComponentSystem.InitAsync` 填充 + `GetFrameOffset(index)` 访问器
3. `LSSpriteAnimViewComponentSystem.Update`：`localPosition = (imagePos + FrameOffsets[image.index]) / 100`

**取舍**：没直接用下面的绝对公式——那会把所有动作平移 ~(+2.4, +3.5) 单位、要动 prefab 校准。相对修正让 idle 零变化、其余帧回到真实**相对**锚定（膝踢 x、down.ani 的 y 都回正）。残余：imagePos.y 偏离校准帧大的帧有 ≤2×偏差量（约 0.04 单位）的 y 残差，要绝对精确再做 prefab 校准。

⚠️ **通用坑（以后所有图集/动作接入）**：Sprite 按紧致内容框裁剪时，摆位**必须**补 `NpkSprite.X/Y` 内容偏移——只在"各帧偏移接近"时看着正常，一换偏移大的动作就漂。修复时还曾写错一版"画布中心对称"公式（`FW/2 − X − w/2`，仅内容居中于画布时成立），别再犯。

**正确公式**（绝对锚定，做 prefab 校准时用）：

代入 stay 帧 0：dx = (-249+216+26.5)/100 = **-0.065**，dy = -(-301+195+53.5)/100 = **+0.525**——精灵中心在锚点上方 0.525 单位（底边 ≈0 贴地 ✓）。而现行代码算出的是 (-2.49, -3.01)——**偏差 2.4×3 单位**（怪物此前看着"能看"是因为偏差方向恰好朝下后方，相机视角下像纵深）。需要修 + 需要在 LSAnimResComponent 打包时把 imgX/imgY 存下来（现在只存了 Sprite，丢了原画布偏移）。

### 2.2 受击盒 AABB 采样公式（阶段2 直接用）

我们坐标：TSVector(x=横向, y=高度, z=纵深)，1 单位=100px，Position=脚底中心。DNF→我们轴映射：`我们.x ← DNF.x`（右正）；`我们.y ← DNF.z`（高度，上正，0=地面）；`我们.z ← DNF.y`（纵深）。**除以 100**。

```csharp
long s = 100;
// 先归一化（DNF 有 min/max 倒序脏数据）
int minX = Math.Min(box.min.x, box.max.x), maxX = Math.Max(box.min.x, box.max.x);
// ... minY/maxY/minZ/maxZ 同理

long wx0 = facingRight ? minX : -maxX;   // 面左：x 区间镜像，y/z 不变
long wx1 = facingRight ? maxX : -minX;

var worldMin = new TSVector(pos.x + wx0/s, pos.y + minZ/s, pos.z + minY/s);
var worldMax = new TSVector(pos.x + wx1/s, pos.y + maxZ/s, pos.z + maxY/s);
```

move.json 首帧代入（面右）：世界盒 x[-0.16, 0.29]，**y[-0.05, 1.06]（角色高约 1.06 单位）**，z[-0.07, 0.14]。z(minDNF)=-5 是允许脚底下探的余量，保留（忠实原作）。**纵深跨度 0.21 单位——我们阶段2 的 z 轴判定阈值应与这个量级匹配。** 贴图像素与判定像素 1:1，pixelsPerUnit=100 直接成立，不要再缩放。

### 2.3 朝向镜像的正确做法

DNF 面左 = x 区间取反 + 贴图水平翻转（绕角色锚点整体镜像）。我们现用"子节点 scale.x=-1"是**绕精灵自身中心**镜像——数学上差 `2×偏移x`（本例 0.13 单位）。严格做法：`localPosition.x = facingRight ? dx : -dx` **加上** scale.x 翻转，两者配合才是绕锚点镜像。偏差小（0.13 单位），可以先不改，但采样公式（2.2）里的盒子镜像是必须的。
