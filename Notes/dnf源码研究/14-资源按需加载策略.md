# DNF 资源按需加载策略与我们的对应方案

> 承接 09~13 系列。本文档讲资源加载策略：DNF 怎么做到不启动全解压、我们对应怎么做。
> 结论：按需加载是标准做法，YooAsset 天然支持；当前规模全加载没问题，多怪/多房间时改成按配置列表加载。

---

## 0. 一句话结论

**DNF 按需加载：谁要用才解压谁，不用了就卸载。** 我们的 YooAsset 天然支持这种模式；当前规模（一只怪）全加载没问题，等怪多了按房间配置列表加载即可。

---

## 1. DNF 的资源加载时机

```
游戏启动
  │  加载：引擎核心 + PVF（配置/脚本层，文本） + 登录界面资源
  │  PVF 是文本配置（.skl/.ani/.atk/.equ/.mob 等），启动时读
  │  NPK 文件被"挂载"（建虚拟文件索引）——索引便宜，像素不进内存
  │
  ▼ 选角色界面
  │  加载：玩家拥有的职业角色的 IMG（精灵图集）+ 选角 UI
  │  没魔法师 → 魔法师相关 NPK/IMG 不解压
  │
  ▼ 进入城镇
  │  加载：这个城镇的 tile/背景/BGM/NPC 外观 + 城镇 UI
  │  玩家角色 IMG 已在内存（选角时加载，跨场景常驻）
  │
  ▼ 进入副本房间
  │  加载：这个房间的 tile + 这个房间的怪物 IMG + 房间内技能特效
  │  只加载当前房间用到的——不需要整个副本的全部怪
  │
  ▼ 清怪 → 走门 → 下一房间
  │  卸载：上一个房间的 tile + 上一个房间的怪物 IMG（不再用的）
  │  加载：新房间的 tile + 新房间的怪物 IMG
  │  玩家角色 IMG 常驻（不卸载）
  │
  ▼ 离开副本回城镇
     卸载：副本全部资源（地图 + 怪物 + 副本特效）
     重新加载：城镇资源（如果之前卸载过）
```

### 关键概念

| 概念 | 说明 |
|------|------|
| **挂载 ≠ 解压** | NPK 文件被挂载（建虚拟文件路径索引）很便宜（一个文件句柄+目录）；IMG 像素数据解压进内存才是贵的（GPU 纹理）。挂载了所有 NPK 但没解压不需要的 IMG = 内存里没有那些像素 |
| **常驻资源** | 玩家角色 IMG、UI 图标、公共特效——一次加载整个会话不卸载 |
| **场景资源** | 地图 tile、怪物 IMG、副本特效——进场景加载、离场景卸载 |
| **配置 vs 资源** | PVF 里的 .skl/.ani 配置（文本，小）启动时全读；NPK 里的 IMG 像素（大）按需解压 |

## 2. 我们项目当前的状态与问题

### 当前实现

```csharp
// LSAnimResComponentSystem.InitAsync（进战斗场景时调用）
string imgPath = "Packages/cn.etetet.lockstep/Bundles/AnimRes/bantuamazones.img.bytes";
TextAsset imgAsset = await resLoader.LoadAssetAsync<TextAsset>(imgPath);
// 解析 → RectpackSharp 打图集 → Sprite.Create → 缓存
// 注册 stay.json / move.json
```

**当前状况**：一只怪 71KB，全加载完全没问题。

### 以后的瓶颈

当游戏有 20 种怪、每种 3-5MB（高分辨率序列帧），全加载 = 60-100MB 像素进内存——太多。而且某个房间可能只有 3 种怪，另外 17 种加载了纯属浪费。

---

## 3. 我们该怎么改（分阶段）

### 阶段 1：当前（1-5 种怪）——不改

全加载在 `LSAnimResComponent.InitAsync`。5 种怪 × 3MB = 15MB，可接受。

### 阶段 2：多怪/多房间（做怪物配置系统时）——按配置列表加载

```csharp
// 房间配置里声明这个房间有哪些怪
// RoomConfig:
//   monsters: [5001, 5002, 5003]  ← 只有这三种

public static async ETTask InitAsync(this LSAnimResComponent self, Room room)
{
    ResourcesLoaderComponent resLoader = room.GetComponent<ResourcesLoaderComponent>();

    // 只加载这个房间配置里列出的怪物
    RoomConfig roomConfig = RoomConfigRegistry.Get(room.RoomId);
    foreach (int monsterId in roomConfig.MonsterIds)
    {
        string imgPath = $"Packages/.../Bundles/AnimRes/monster_{monsterId}.img.bytes";
        TextAsset imgAsset = await resLoader.LoadAssetAsync<TextAsset>(imgPath);
        self.BuildAtlas(monsterId, imgAsset.bytes);  // 解析打包
    }

    // 玩家角色的 img 单独加载（常驻，不跟房间走）
    string playerImgPath = $"Packages/.../Bundles/AnimRes/player_{playerClassId}.img.bytes";
    self.BuildAtlas(PlayerKey, (await resLoader.LoadAssetAsync<TextAsset>(playerImgPath)).bytes);
}
```

### 阶段 3：多房间副本（做副本系统时）——离房卸载

```
进房间 → 加载该房间的怪物图集
离房间 → 卸载不再出现的怪物图集（resLoader.Release）
玩家角色图集 → 常驻（不卸载）
```

YooAsset 支持按引用计数释放资源（`Release()` / `ReleaseAllAssets()`），不需要自己写资源池。

## 4. YooAsset 天然支持按需加载

YooAsset 的 `LoadAssetAsync` 本身就是异步按需的：

| 操作 | 代码 | 行为 |
|------|------|------|
| 按需加载 | `await resLoader.LoadAssetAsync<TextAsset>(path)` | 异步加载，���调不加载 |
| 卸载 | `resLoader.Release(handle)` 或 `ReleaseAllAssets()` | 减引用计数，归零释放 |
| 常驻 | 加载后不 Release | 一直在内存 |
| 按需释放 | 离房间时 Release 该房间的资源 | 内存回收 |

**不需要额外设计——这就是 YooAsset 的常规用法。** 当前代码硬编码了 `bantuamazones.img.bytes`，以后改成从房间配置读列表再循环加载即可。

## 5. DNF 的 NPK vs 我们的 img.bytes 对照

| DNF | 我们 | 说明 |
|-----|------|------|
| NPK 文件（加密容器） | AssetBundle（YooAsset 管理） | 资源打包格式 |
| IMG（NPK 内的精灵图集） | .img.bytes（TextAsset，含 NpkSprite 序列帧） | 像素数据 |
| 挂载 NPK（建索引不解压） | YooAsset 初始化（加载 Bundle 目录不解压内容） | 便宜 |
| 解压 IMG 进内存 | LoadAssetAsync<TextAsset> + NpkImgParser.Parse + 图集打包 | 贵（这里做） |
| PVF 配置（文本，启动全读） | JSON 配置（stay.json/move.json，进房间时读） | 我们的粒度更细（更好） |

## 6. 内存预算参考

| 资源 | 大小（估算） | 策略 |
|------|-------------|------|
| 单只怪 img.bytes（压缩） | ~71KB（BantuAmazones） | 按需加载 |
| 单只怪运行时图集（RGBA32） | 2048²×4B = 16MB（打包后按 bounds 缩小，可能更小） | 按需加载+离房卸载 |
| 5 种怪全加载 | 15-80MB | 当前可接受 |
| 20 种怪全加载 | 60-320MB | **太多，必须按需** |
| 玩家角色 img（常驻） | 5-15MB | 不卸载 |
| 地图 tile | 每房间 1-5MB | 进房加载离房卸载 |

```

什么时候全加载？    启动时只加载配置层（PVF 文本）；像素层（NPK/IMG）按需
我们该怎么对应？    YooAsset 天然支持；当前全加载没问题，多怪时按房间配置列表加载
什么时候改？        做怪物配置系统/副本系统时（阶段 2/3）
需要额外设计吗？    不需要——YooAsset 的 LoadAssetAsync/Release 就是这套机制
玩家角色资源？      常驻（选角/进副本时加载一次，跨房间不卸载）
地图资源？          进房加载离房卸载
```
