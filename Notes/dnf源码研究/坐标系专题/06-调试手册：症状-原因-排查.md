# 06 · 调试手册：症状 → 原因 → 排查步骤

> 坐标问题的调试心法：**先分层定位，再查数值**。坐标链 = 数据(img/ani 原始值) → 打包(AtlasCenters) → 摆位(localPosition 公式) → 世界(Position/投影) → 判定(盒采样)。任何症状先判断错在哪一层，再按本手册的步骤走。
> 手算模板在文末 §9；所有"基准数值"来自 01-05 篇实证。

---

## 0. 三十分钟通用的排查地图

```
症状出现
 ├─ 贴图位置不对（看得见的错位） ──→ §1-§5
 │    依次确认：①帧原始值对不对 → ②AtlasCenters 对不对 → ③摆位公式入参对不对 → ④prefab chain 对不对
 ├─ 贴图"发糊/抖动"（位置对） ──→ 先查像素对齐（07篇），别动坐标公式
 │    静止清晰、运动糊/抖 = 亚像素采样（Lerp 小数坐标/奇数帧半像素/相机像素比）
 └─ 判定不对（打不中/隔空中，贴图正常） ──→ §6-§7
      依次确认：①盒原始值 → ②采样公式/面左镜像 → ③判定帧���口 → ④纵深阈值
```

每一层都有"独立验证点"，不要跳层乱试。

## 1. 症状：技能特效在角色头顶（或别的离谱位置）释放

**这是"生成点"与"摆位"两跳的复合问题，逐跳查。**

原因链：特效最终位置 = ①生成点（谁、挂在哪个节点、z 多高）→ ②特效自身摆位（imagePos+center 公式）。

排查：
1. **先查 ①生成点**：特效实体挂在哪个 transform 下？`parent == unit 根（脚底）` 还是 `挂点节点` 还是 `场景根`？
   - 挂到"头顶"多数是把特效挂错了节点/或生成时加了错误的高度偏移（把锚点当成了"中心"算了半个人高）。
   - DNF 的地面特效 z 从 0（地面）起；角色贴身特效挂身体挂点。对号入座你的特效类型。
2. **再查 ②摆位**：特效资源锚点=视觉中心（02 篇 §4.2），位图应围绕生成点展开。用 normalwave 数据校验你的实现：位图 x 应在锚点两侧近似对称（-41..+42）。
3. 数值工具：打印 `生成点世界位 / 特效 renderer.local / (imagePos, center)` 三个数，手算 `(imagePos+center)/100` 是否等于 local+chain。
4. 概念检查：不要给特效再用"角色脚底锚"的假设去"修"位置——错上加错。

## 2. 症状：角色/怪物播放某动作时整体漂移（起手偏、收招回来）

**教科书案例：本项目阶段 3.5 的膝踢漂移 bug。**

原因：摆位用了"整段动画共用的偏移"（或丢了 img X/Y 项），而 imagePos 逐帧独立（kneekick 内 posX 从 -330 跳到 -249，81px）。

排查：
1. 该动作各帧 `(imagePos, X, Y, W, H)` 打表（`数据/*_ani数据.csv` + `*_img帧数据.csv` 里都有，或跑 CoordAnnotator 重出）。
2. 逐帧手算 `(posX+X+W/2, posY+Y+H/2)`，画在纸上——那就是内容中心轨迹，应基本稳定在锚点附近。
3. 和渲染值对比：哪帧开始偏，偏差量 = 该帧少加的那项（旧 bug 里 X 项被丢，膝踢帧 X=259..290 vs 站立 216，差出的 0.4-0.7 单位就是漂移量）。
4. 确认公式代码没退回 `imagePos/100` 裸用（05 篇 §3.2）。

## 3. 症状：角色悬空 / 陷进地里

原因：y 方向基准丢了——锚点应=脚底（y=0 地面线），渲染把锚点画在了别处。

排查：
1. stay 帧 0 手算：内容中心 y = (posY+Y+H/2) = (-301+195+53.5) = **-52.5px → Unity +0.525**。渲染 local.y 应≈ +0.525-chain.y。
2. 若角色悬空约 1 单位 → 多半把"帧域中心"（500/2）当成了内容中心，或 chain 没减。
3. 若陷入地里 0.5 单位上下 → y 翻转忘了（DNF y 下正，Unity 上正，必须取负）。
4. prefab 层级改动过？chain 是运行时自标定的（parent 世界位−根世界位），prefab 改层后旧常数会失效——这正是"不硬编码"的原因，但也要确认 prefab 里没有残留的手摆偏移节点。

## 4. 症状：怪看起来"能看"但位置总有点说不清的歪（整体偏 2.4×3 单位）

历史坑：prefab 中间层偏移 C≈(2.4,3.5) 是老版本校准烤入的。现在公式已把它作为 chain 显式扣除。若换 prefab/公式后出现整体平移，先查 chain 计算的父子层级是不是你真正挂 renderer 的那层。

## 5. 症状：面左后贴图位置不对 / 和判定盒对不上

两层原因：
1. **绕中心 vs 绕锚点**：只翻贴图（scale.x=-1 打在 renderer 上）= 绕内容中心镜像，与盒的"绕锚点镜像"差 2×中心偏移x（stay 帧 0.13 单位）。修法：面左时 `localPosition.x` 同步取负（05 篇 §6 一行代码）。
2. **翻在根节点**：scale.x=-1 打在 Unit 根上会连 prefab 层级/chain 一起镜像，产生跳变——必须打在 renderer 所在子节点（现行正确）。

验证：面左站立帧，受击盒 Gizmo 右缘应贴着角色背面（x 区间镜像后 [-44..21]），贴图剪影与盒偏差不应超过手配余量。

## 6. 症状：打不中 / 隔着很远也中（判定错位）

贴图正常、判定不对 → 查盒链路：
1. **盒原始值**：该帧 csv 里有没有盒（攻击盒只在判定帧有！kneekick 帧 0/4 无攻击盒是正常的）。
2. **采样公式**：对照 `LSHitboxComponentSystem.SampleBox`——归一化做了吗（源数据 min>max 脏值）、面左 x 镜像做了吗、轴重排对吗（ts.y←dnfZ 高度、ts.z←dnfY 纵深，翻过来角色盒会变成"横躺的"一眼假）。
3. **纵深阈值**：角色盒纵深只有 ~0.21 单位（y -7..14px）。我们引擎 z 向判定阈值若取 1 单位就会"隔街打人"；应与 0.21 量级匹配或用盒精确相交（现行 AABB 相交即精确）。
4. **AABB 构造**：走对象初始化器 `new AABB{Min=,Max=}`，Id 恒 0（AABB 静态计数器是 desync 雷，见 AABB.cs 说明）。

## 7. 症状：判定帧窗口不对（起手就能打到人 / 收招还在打）

判定窗口=帧数据驱动：只有带 attackBoxes 的帧激活攻击盒。查：
1. 该动作哪些帧有盒（csv 一眼看清）；是否把"动画播放到第 N 帧"和"判定帧"搞混。
2. `AnimId` 门禁：攻击盒采样当前绑死 `AnimId.Attack1`（LSHitboxComponentSystem:44），换动作/新技能没接进来就是"永远不判定"或"一直判定"。
3. 命中防重：HitTargets 每轮攻击要清（ClearHitTargets），否则第二段打不出效果。

## 8. 症状：某帧贴图不显示 / 显示成别的帧

1. **空图占位帧**：[IMAGE] 值为空（normalwave 帧0 ``）——就是不显示，纯延时，正常现象（GetSprite 对空路径返回 null 的处理）。
2. **引用帧**：img 帧是 REFERENCE，取像素要解引用（GetImage 已自动；但元数据 w/h/X/Y 要取**被引帧**的，ResolveFrame）。
3. **图集 key 对不上**：json 里 image.path 文件名 vs 注册的 atlasName（大小写/后缀），打 Warning 看日志。
4. **帧号越界**：ani 引用的 imgIndex 超过图集帧数（资源版本不匹配，v5/v2 混了）。

## 9. 手算模板（打印贴桌边）

```
输入：frame.imagePos=(px,py)  img帧=(X,Y,W,H)  facingRight
─────────────────────────────────────────────
位图左上(DNF) = (px+X, py+Y)
内容中心(DNF) = (px+X+W/2, py+Y+H/2)
渲染 local    = ((px+X+W/2)/100 − chain.x,  −(py+Y+H/2)/100 − chain.y)
面左          = local.x 取负（+scale.x=−1）
盒(世界)      = pos + ([minX..maxX]镜像?, minZ..maxZ, minY..maxY)/100
─────────────────────────────────────────────
基准样例（Bantu stay 帧0）：pos=(-249,-301) img=(216,195,53,107)
  → 位图左上(-33,-106)  内容中心(-6.5,-52.5)  local=(-0.065,+0.525)
  → 底边 y = -301+195+107 = +1 ≈ 0（贴地验证）
```
