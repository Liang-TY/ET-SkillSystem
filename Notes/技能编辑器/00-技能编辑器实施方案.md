| 痛点 | 编辑器解法 |

## 2. 参数层设计（P1 核心）

### 2.1 文件布局

```
Packages/cn.etetet.skill/Bundles/SkillParams/
  skills/<skillName>.json      每技能一份（SkillId → 文件映射表见 2.4）
  bullets/<bulletName>.json    弹体参数（NormalWave/IceBreath/ThrustBeam/GrandWave）
  areas/<areaName>.json        区域参数（14 个 Area）
```

放 Bundles 下原因：与 SkillContent.dll.bytes 同目录约定，YooAsset 收集一致；编辑器 File IO
直读（Editor 不走 YooAsset），运行时走 YooAsset TextAsset（AnimRes 双通道先例）。

### 2.2 技能 JSON schema（通用骨架 + 类型特化，五块）

```json
{
  "id": 24, "name": "怒气爆发", "type": "AreaBurst",
  "cooldownMs": 2000, "totalTimeMs": 400,
  "requireAirborne": false, "manualCooldown": false, "minCastHpPct": 0,

  "phases": [
    { "animId": "attack2", "durationMs": 400, "cancelMs": -1,
      "clearHitTargets": true, "superArmorMs": 0,
      "movement": { "distance": 0, "durationMs": 0, "stopOnHit": false },
      "nextSkillId": 0, "nextTrigger": "none" }
  ],

  "hitReactions": { "0": { "damage": 80, "hitstunMs": 500, "kbX": 0, "launchY": 150,
                            "procBuffId": 0, "procChance": 0 } },
  "hitActions": ["MeleeHit"],

  "manualBoxes":  [ { "phase": 0, "onMs": 575, "offMs": 725,
                       "offset": [0.5, 0.35, 0], "half": [1.1, 0.7, 0.7] } ],

  "spawnEvents":  [ { "atMs": 0, "action": "createArea", "area": "bloodblast_pre", "at": "self", "dist": 0 },
                    { "atMs": 0, "action": "createBullet", "bullet": "grandwave" },
                    { "atMs": 760, "action": "superArmor", "durationMs": 540 } ],

  "hitEvents":    [ { "on": "hit", "action": "nextPhase" } ]
}
```

字段语义（新会话实现时以此为准）：

| 块 | 语义 | 消费的现有框架机制 |
|---|---|---|
| `phases[]` | 段表：线性段序列。animId=该段 PlayAnim 的 AnimId 名；durationMs=段时长；cancelMs=取消窗口（-1=无）；superArmorMs=该段起霸体时长；movement=段内位移（stopOnHit=撞敌停驻）；nextSkillId+nextTrigger=段末/命中/按键转派另一技能 | 单 cast 段状态机（SubState=段号、Phase=段起点），第 1 批普攻/三段斩范式 |
| `hitReactions{}` | key=段号 → HitReaction。**等价替换 SkillLogic.PhaseHitReaction** | 第 2 批分段反应机制 |
| `hitActions[]` | ActionIds 名数组 | 现有 HitActions |
| `manualBoxes[]` | 手动盒窗口（帧驱动盒不在此——json 动画自带，只读） | SetAttackHitbox 现机制 |
| `spawnEvents[]` | 定时事件：createArea（at=self/inFront+dist）/createBullet/superArmor/playAnim | OnUpdate 的 SubState 守卫一次性触发，改为通用事件调度 |
| `hitEvents[]` | 命中时事件：nextPhase/nextSkill/grab（预留） | 框架新增（P4 段末转派一并做） |

**预留字段**（本期只占位不实现）：`hitEvents[].action:"grab"`（抓取——框架件 GrabController 待做）、
`"summon"`（召唤物 AI）、`"transform"`（变身）。魔法师/圣职者扫描确认这三大族是新框架件解锁，
参数层先留扩展位，编辑器结构不变。

### 2.3 弹体/区域 JSON

直接对位现有 BulletDefinition/AreaDefinition 的全部虚属性（speed/totalTimeMs/destroyOnHit/
hitResetIntervalMs/halfExtents/spawnOffset/viewOffset/viewGrounded/viewAnimId/hitReaction/hitActions/
enter/tick/exitActions/tickTimeMs/viewBackAnimId/viewEndAnimId）——字段名与 C# 属性一一对应，
无新概念。hitActions/hitReaction 同技能 schema 复用。

### 2.4 SkillId ↔ 文件映射 + Id 字符串化

- AnimId/SkillId/AreaId/BulletId/ActionId/BuffId 在 JSON 里**全用字符串名**（"attack2"、"MeleeHit"），
  消费时经各 Loader 的名字反查表转 int——新建 `ContentIds` 静态类统一管理 name↔id 双向表
  （注册时自动从 [SkillId]/[AnimId 常量表] 等收集；AnimId 现在是 const 散列，需加一份 name 注册，
  见 §6 工作项 4）。
- 技能注册：`SkillIds.ButtonToSkill` 的硬编码 case 改为读 `skillparams/index.json`
  （`{"button": 24, "skill": "BloodBlast"}` 数组）——按键映射也数据化。

## 3. 技能类型模板（覆盖度结论，新技能设计入口）

| 模板 type | 覆盖技能（已实现+待实现主力） | 特化字段 |

## 4. 编辑器双区架构

### 4.1 Editor 编辑窗（UIToolkit，非 Play）

- **段表泳道时间轴**（自绘，不用 Unity Timeline——那是演出编排，与帧同步参数模型不匹配）：
  每段一行，行内画 动画块/盒窗口块/位移块/事件标记；转派边用箭头连接段与段/段与技能
- **资产浏览器**：列出 AnimConfigRegistry 全部已注册动画（含试播窗——复用 SpriteAnimView
  逐帧逻辑，注意切片/悬停帧钳制的特殊注册要在编辑器侧一致跑），选用即填入参数
- **变换管道检查器**：选中特效/盒，列出 DNF像素→/100→y/z对调→imagePos+center→ViewOffset→面左镜像
  每步中间值，最后一步与预览窗渲染位置连线——"对不上"定位到具体哪步
- **帧盒查看**：读翻译产物 json 的 attackBoxes/damageBoxes 逐帧展示（P4 才做编辑回写，P3 只读）
- **保存**：序列化回 SkillParams JSON → 热重载字典

### 4.2 游戏内调试面板（IMGUI OnGUI，运行时）

**不做独立 Play 调试场景**——直接做常驻调试组件，现有战斗场景内热键开关（建议 F1）：

| 功能 | 实现 |
|---|---|
| 技能施放面板 | 下拉选 SkillId → 对假人施放（SkillCastHelper.TryCast），不依赖按键映射 |
| 判定可视化 | LSHitboxComponent 的 CurrentAttackBoxes/CurrentHurtBoxes、LSArea 盒画线框（攻击绿/受击红/Area 蓝）；位移轨迹画线；命中点标记 |
| 时间控制 | timeScale=0 暂停 + 单帧按钮（手动 tick LSWorld——帧同步天然适合单帧步进）+ 帧号跳转 |
| 命中日志 | 每帧命中事件滚动：谁打谁/哪段反应/伤害/盒值（接 LSHitboxComponentSystem.ApplyHit 已有 Log） |
| 单位状态 | 点选单位看 HitstunTimer/Velocity/IsJump/SuperArmorTimer/Buff 列表实时值 |
| 参数热重载 | 按钮 → SkillParamLoader.Reload() → 立即可放 |

生命周期隔离：调试组件不依赖 YIUI 面板栈（项目红线：正式 UI 面板冻结不加功能）；
不上屏零开销（OnGUI 只在开启时跑）。

### 4.3 Editor 调什么、Play 验什么（分工闭环）

- **Editor**：静态对位（角色精灵+特效精灵同坐标系叠加+盒线框）——动画级，无物理
- **Play**：动态手感（真命中结算/击退浮空轨迹/多段时序）
- 参数变更从任一侧发起，共享同一 SkillParams 层

新机制类型（抓取/召唤/炫纹/变身）才加模板——参数层已预留。

## 10. 风险与已知困难

1. **迁移回归**（最大风险）：缓解=逐技能对照表+用户逐测；ContentIds 转换错 name 会静默 0，
   Loader 加载时对未知名字 Log.Error 拒载（fail fast 不 fail silent）
2. **ET.Skill 程序集边界**：ParametricSkillLogic 放 ET.Skill（要访问 LSCast/LSBulletSystem）；
   JSON 解析用 Newtonsoft（com.unity.nuget.newtonsoft-json，字典/嵌套/缺省字段处理远强于 JsonUtility）
2b. **luban 生成类兼容性**（见 §2.6）：生成类能否直读我们的 JSON 是 P1 第一验证点，
   fallback = luban 只做校验 + C# 类手写，架构不变
3. **Play 单帧步进**：timeScale=0 时 OnGUI 仍跑（IMGUI 不受 timeScale 影响 ✓）；
   手动 tick 要绕过 LSClientUpdater 的自动驱动——实现时读 Room/LSClientUpdater 驱动链找注入点
4. **AnimId 字符串化改造波及面**：AnimId const 被 lockstep/npkparser/skill 三包引用——
   const 保留（兼容），新增名字表并行，逐步切
5. **编辑器侧动画注册**：Editor 下 AnimConfigRegistry 是运行时注册的（LSAnimClipRegistrar 走 YooAsset）——
   编辑器要自己触发一次注册（直接调 LSAnimClipRegistrar.RegisterAll 的资源加载在 Editor 可用 YooAsset
   EditorSimMode，实现时验证）

## 11. 决策记录（用户确认）

- Unity 内做；Editor(UIToolkit) 编辑 + Play(游戏内 IMGUI 面板) 验证，不做独立调试场景
- 状态机不做节点图：段表+转派边（DNF 技能实际全是线性段，自由图无必要）
- 运行时调试 UI 不用 YIUI（正式 UI 冻结红线+调试隔离诉求），IMGUI
- 参数一次性全迁移，用户逐个测试汇总
- replay 旧版本失真不管
- CD 数值等游戏手感参数全在 JSON 里，后续调参不再改 C#
- luban：复制 etmaster `cn.etetet.yiuiluban` 整包（独立工具包，不依赖 YIUI/ET 版本）；
  数据源定位 = 我们的 SkillParams JSON（非传统 Excel 源+产物 bytes）
- 编辑器代码落位：Editor 窗/P3 → cn.etetet.skill/Editor/SkillEditor；运行时调试面板/P2 →
  cn.etetet.lockstep/.../Debug（依赖方向）；生成类 → skill/Runtime/SkillParamsGen
