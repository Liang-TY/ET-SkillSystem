## 2. 为什么做

现状是修改技能参数需要改 C#、编译、等待 Unity，再通过 Play 猜测结果；特效、动画中心点、
判定盒和多段时序的错位难以定位。目标是把可调内容放到可校验的 SkillParams JSON，并在
Unity Editor 中用真实资源进行确定性对位，最后在真实战斗中用 Play IMGUI 验证手感。

目标分三层：

- 看：角色、特效、动画帧、判定盒和位移在同一坐标系中对位；
- 调：字段、时间窗口和引用可撤销编辑、校验、保存、Reload；
- 助：AI/模板可以通过语义接口批量检查或修改数据，但不绕过规则。

## 3. 已确认的硬决策

| 主题 | 决策 |
|---|---|
| 数据源 | SkillParams JSON 是唯一可编辑源；Luban 管 schema、校验和生成类 |
| 引用 | animId、skillId、areaId、bulletId、actionId、buffId 一律整数；名称只用于文件名、显示、搜索和日志 |
| 内容范围 | Skill、Bullet、Area、Buff、Action 一次性纳入参数化迁移 |
| 当前数量 | 22 Skill、4 Bullet、14 Area、4 Buff、7 Action、18 按键映射 |
| 时间边界 | 定时事件按 previousTime < atMs <= currentTime；atMs=0 在创建/进入阶段时处理 |
| 命中策略 | FirstHitInCast、FirstHitInPhase、OncePerTargetInPhase、EveryResolvedHit 由技能配置决定 |
| Cast 状态 | LSCast.SubState 只表示 Phase 索引，LSCast.Phase 只表示 Phase 起始时间；事件游标/命中掩码/待处理目标独立保存 |
| Editor 技术 | UI Toolkit、自绘时间轴、真实 SpriteRenderer/PreviewRenderUtility；不使用 Unity Timeline |
| Editor 边界 | 不执行真实碰撞、伤害、物理、联网、回滚或 LSCast；帧盒首版只读 |
| Play 技术 | P3 才做游戏内 IMGUI，不做独立调试场景，不接正式 YIUI 面板栈 |
| 依赖方向 | Editor 在 cn.etetet.skill/Editor/SkillEditor；Play 调试面板在 lockstep Debug，避免反向依赖 |
| AI 操作 | UI、Unity Pipeline CLI、可选 batchmode 共用同一核心 Operations；不模拟鼠标、不执行任意代码 |
| 兼容取舍 | 参数变更导致旧 replay 失真暂不处理 |

Buff 和 Action 的迁移原则与 Skill 相同：行为仍在有限的 C# 注册类，持续时间、Tick、数值、
整数引用和动作列表进入 JSON；JSON 不保存任意方法名或脚本。

## 4. 数据和代码边界

数据目录：

~~~text
Packages/cn.etetet.skill/Bundles/SkillParams/
  skills/*.json
  bullets/*.json
  areas/*.json
  buffs/*.json
  actions/*.json
  index.json
~~~

代码目录：

~~~text
Packages/cn.etetet.skill/
  Luban/Config/              schema、配置和生成脚本
  Runtime/SkillParamsGen/    Luban 生成类，禁止手工修改
  Runtime/                   DTO、Loader、ID 目录和参数化执行桥接
  Editor/SkillEditor/        P2 Editor 和自动化适配器
~~~

Editor 直接读写上述 JSON；运行时通过 YooAsset/Loader 读取同一份内容。生成目录不能当作
编辑器资产，也不能由 Inspector 直接改。校验需尽量对当前内存 DTO 做无副作用检查；只有显式
Save/Reload/回归才更新全局运行时缓存。

## 5. 技能表达范围

首版用通用段表和事件表达已有技能：

- MeleeCombo：近战连段和普攻；
- Dash：突进、位移和撞停；
- Projectile：投射物；
- AreaBurst：区域、多段 Tick；
- Buff：自身增益或状态链。

空中、落地等是状态前置字段，不单独做模板。抓取、召唤物 AI、炫纹、变身和属性消费链
属于缺少运行时框架件的新机制；参数层可以预留字段，但不能用字符串脚本在 Editor 中绕过。

## 6. P2 Editor 总体形状

Editor 采用“核心服务先行 + HardAttack 纵向切片”：

~~~text
Window / Unity CLI / Batchmode
            -> Operations
                -> Session / DocumentStore / Commands / Validation / TimelineProjection / Preview
                                                     |
                                                     v
                                               JSON 唯一真相
~~~

模块职责、窗口布局、坐标管道、动画资源映射、代码骨架和 Step 0–4 施工顺序见
02-P2-Editor详细设计.md。AI 命令、请求 JSON、返回码、路径限制和冲突策略见
03-P2-Editor-AI自动化接口.md。不要先堆一个没有可验证链路的“大窗口”，也不要把 P3
战斗模拟提前塞进 P2。

P2 的结果必须回答三件事：

1. 能否正确加载、编辑、撤销、保存和 Reload 参数；
2. Editor 的 Sprite、中心点、镜像、ViewOffset、盒体和时间轴是否与运行时一致；
3. AI 是否能用结构化 CLI 重复同样操作并得到可审计结果。

## 9. 变更控制

下列变化必须先更新文档并取得确认，再改代码：

- 修改 JSON 身份、整数引用或 atMs/HitPolicy 语义；
- 改变 LSCast 快照、MemoryPackOrder、SkillContext 或程序集拓扑；
- 让 Editor 执行真实战斗、回写 NPK、提前实现 Play IMGUI；
- 扩大 CLI 写入目录、增加任意脚本/命令执行或批量删除迁移；
- 发现 AnimRes 映射无法保证 Editor 与运行时一致。

其余局部 UI、占位资源、性能和空引用问题可按 04 文档分级记录后继续。
