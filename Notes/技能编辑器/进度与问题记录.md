## 已确认决策

1. JSON 中的 `animId`、`skillId`、`areaId`、`bulletId`、`actionId`、`buffId` 全部使用整数。
   名称只用于文件名、Editor 显示/搜索和错误信息，运行时不做 name→id 转换。
2. Luban 使用 XML schema，实际数据源使用 JSON；若 3.11 生成器无法按当前 JSON 直接反序列化，
   采用“Luban 做 schema/校验/生成文档，运行时使用手写 POCO + Newtonsoft 读取 JSON”的 fallback。
3. Editor 使用 UI Toolkit、自定义时间轴和 PreviewRenderUtility/隐藏预览场景，不使用 Unity Timeline。
   角色、特效和资源视觉使用真实 SpriteRenderer；盒体、坐标轴、标签使用辅助绘制层。
4. Editor 预览是无副作用的确定性采样，不执行真实物理、命中结算、联机或回滚；Play IMGUI 放到最后。
5. 当前 `[SkillId]` 技能类按 22 个统计；NormalAttack 的空中连斩是同一技能分支。另迁移 4 个 Bullet、
   14 个 Area、4 个 Buff 和 7 个 Action 注册类。

6. Editor 采用“核心框架先行 + 一个技能纵向切片收敛”的方式：先固定 Session/Document/Command/Validation/
   Preview 契约，再扩展时间轴、Inspector、资源和全量回归；不先实现 Play IMGUI。

7. Editor 的 A 类问题（程序集拓扑、参数语义、回滚字段、资源坐标管道、JSON 格式或阶段边界发生变化）必须
   先汇报并暂停对应阶段；普通 UI、占位资源和局部空引用可记录后继续。具体规则见 04。

8. Editor 的 UI、Unity Pipeline CLI 和可选 batchmode 入口共用同一个 Operations 核心。AI 使用整数 ID、
   语义字段路径、dryRun 和 expectedHash 操作；不通过鼠标坐标控制窗口，也不提供任意代码执行能力。

## 问题记录

### ISSUE-001：原方案的内容引用使用字符串

- 现象：旧草案示例把 Anim/Area/Bullet/Action 引用写成名称，运行时还需要反查整数。
- 影响：引用链增加转换层，名称拼写或目录缺失可能静默得到 0。
- 结论：已统一改为整数引用；`ContentIds` 只保留 `id → name` 显示目录和校验用途。
- 状态：已解决（文档层）。

### ISSUE-002：原方案阶段编号与用户要求的执行顺序冲突

- 现象：旧文档把 Play IMGUI 标为 P2、Editor 标为 P3，和“先 Editor、最后 Play”冲突。
- 影响：施工顺序可能在 Editor 尚未验证前先投入运行时调试面板。
- 结论：重新定义为 P1 参数化、P2 Editor 及现有技能回归、P3 Play IMGUI、P4 高级助力。
- 状态：已解决（文档层）。

### ISSUE-003：现有技能数量口径不一致

- 现象：旧文档写 19 个技能，但当前仓库存在 22 个 `[SkillId]` 技能类。
- 影响：迁移清单和验收数量不完整。
- 结论：P1 按 22 个技能类统计；空中连斩作为 NormalAttack 分支，不重复创建 SkillId。
- 状态：已解决（文档层，施工时仍需逐类扫描确认）。

### ISSUE-004：Luban 3.11 对 JSON 数据和生成类的兼容性待验证

- 现象：已知 Luban 有 XML/Excel schema loader 和 JSON data loader，但当前项目需要确认生成类能否
  直接读取现有嵌套 JSON 结构。
- 影响：会决定使用生成 POCO，还是使用手写 POCO + Newtonsoft；不影响整体 JSON 参数架构。
- 后续动作：先用一个 SkillParam、一个 Phase 和一个样例 JSON 跑 LubanGen/反序列化，记录实际命令、
  生成文件和错误信息。
- 实测结果：使用 XML schema + JSON data loader，嵌套 bean/list、枚举、可空 int 和整数 ID 均已加载、校验
  通过，并生成 C# 类型；正式 schema 继续沿用该方式。Luban map 的 JSON 形式是二维数组，为保持数据可读性，
  `hitReactions` 采用带 `phase` 字段的 list，运行时再建 phase 索引。
- 状态：已解决（最小样例）；正式字段扩展时继续补充验证。

### ISSUE-008：XML schema loader 的 type 配置

- 现象：`schemaFiles[].type` 写成 `"xml"` 时，Luban 报 `can't find schema loader for type:xml extName:xml`。
- 结论：Luban 的 `XmlSchemaLoader` 注册为 `[SchemaLoader("", "xml")]`，XML schema 的 `type` 必须是空字符串。
- 状态：已解决。

### ISSUE-009：schema module 名称使用 C# 保留字

- 现象：module 名 `cn.etetet.skill.params` 生成时被拒绝，报 namespace contains preserved keyword。
- 结论：改为 `cn.etetet.skill.skillconfig`；正式生成命名空间固定使用 `ET.skillconfig` 下的安全名称。
- 状态：已解决。

### ISSUE-010：正式表使用目录输入时的空目录处理

- 现象：正式 Skill/Bullet/Area/Buff/Action 目录初始为空，必须保证目录存在才能让 Luban 读取。
- 结论：各目录放置 `.gitkeep` 作为初始占位；生成器会忽略点号文件，首次生成后会移除生成目录中的占位文件，
  后续由实际 JSON 文件维持目录。
- 状态：已解决（正式生成已通过）。

### ISSUE-007：本机 .NET SDK 无法直接构建复制的 Luban 工程

- 实测环境：已安装 .NET SDK `8.0.130`、`9.0.101`；没有 .NET 10 SDK。
- 额外环境：`E:\global.json` 将 SDK 选择固定在 `8.0.126` 补丁系列；安装 .NET 10 后不能只在项目
  根目录直接重试，否则仍可能选到 .NET 8。应在 Luban 工具目录放置项目级 `global.json` 指向 net10
  SDK，或从不受该文件影响的目录调用指定 SDK 后再执行生成脚本。
- 实测命令：`dotnet build Packages/cn.etetet.yiuiluban/DontNet~/luban/src/Luban/Luban.csproj -c Release`
- 结果：Luban 3.11 源码及其 22 个项目目标为 `net10.0`，本机报 `NETSDK1045`（当前 SDK 不支持面向
  .NET 10.0）。尝试使用 `-p:TargetFramework=net8.0` 后，NuGet 还原又报 `NU1301`，无法访问
  `https://api.nuget.org/v3/index.json`。
- 当前已收到完整的预构建 `.Tools/Luban` 目录，目录内的 Luban 及依赖 DLL 齐全，不再需要为“运行已构建工具”
  下载 NuGet 包。
- 运行仍需要用户准备：安装 .NET 10 **Runtime**（如果后续需要从源码重建，则安装 .NET 10 SDK），当前
  `Luban.runtimeconfig.json` 明确要求 `Microsoft.NETCore.App 10.0.0`。
- 如果改为源码重建，才需要允许 NuGet 访问；至少需要还原
  `CommandLineParser 2.9.1` 和 `YamlDotNet.NetCore 1.0.0` 及其传递依赖。也可以提供已构建的
  `Luban.dll` 和依赖目录，放入 `Packages/cn.etetet.yiuiluban/.Tools/Luban/`。
- 临时方案：若不能提供 .NET 10/依赖，继续采用文档约定的 fallback（Luban 仅做 schema/文档，
  Skill 参数由手写 POCO + Newtonsoft 读取），但这会推迟 Luban 生成验证。
- 状态：已解决；.NET 10 Runtime 安装后 `Luban.dll --help`、schema 加载和样例数据生成验证均已通过。

### ISSUE-006：当前 LSCast 的 Phase/SubState 兼有事件标志含义

- 现象：部分技能把 `SubState` 当段号，部分技能把它当一次性事件开关；`Phase` 通常是段起始时间，
  个别技能又有额外含义。
- 影响：直接做通用事件调度会破坏回滚和多段行为。
- 结论：参数化时约定 `SubState` 只表示 Phase/段号、`Phase` 只表示 Phase 起始时间；必须记忆的事件
  触发状态另设 cursor/mask，并纳入 LSCast 快照字段。跨帧命中先增加 `PendingHitTargets`，但仍需 Unity/F6
  验证 MemoryPack 和复杂技能行为。
- 状态：基础约定已落代码，待 Unity/F6 与行为回归。

### ISSUE-013：AnimId 与 AnimRes 文件没有直接的 Editor 映射

- 现象：AnimRes 目录实际以 `*.ani.bytes` 为主（另有少量动画/overlay `*.json`），文件本身不携带统一的
  AnimId；AnimId→地址、切片和 overlay 别名关系主要写在运行时 `LSAnimClipRegistrar`。
- 影响：Editor 不能只扫描 `*.json` 或按文件名猜 ID，否则会漏掉资源或与运行时注册结果漂移；预览资源链路和
  `ET.Skill.Editor` 的依赖边界需要重新核对。
- 当前结论：已把它列为 02 的 Editor 第 0 步探针和 04 的 A 类暂停条件。候选方案是抽取

- 状态：待用户确认方案后验证。

### ISSUE-014：Editor 校验不能直接复用全局运行时缓存

- 现象：当前 `SkillParamEditorLoader.ReloadFromDisk()` 会调用 `SkillParamLoader.Clear()`，再把磁盘全量加载到
  全局静态字典；如果 Inspector 每次输入都调用它，会影响其它 Editor 预览/校验上下文，也无法正确校验尚未保存的
  单文档状态。
- 影响：Session 的 dirty 文档、全局运行时缓存和多个窗口之间可能互相覆盖，违背编辑状态与运行时状态分离。
- 结论：P2 的 `ValidationService` 先对 DTO 与独立目录快照做无副作用校验；只有显式 Save/Reload 或回归步骤才调用
  全局 Loader。是否抽取公共纯校验方法，待新会话实现时按程序集边界验证。
- 状态：已纳入设计约束，待实现验证。
