# P1 参数化与数据规范

> 本文承接总纲，集中说明 Luban、SkillParams JSON、运行时加载和当前内容迁移规则。
> P1 的具体施工步骤见 `P1-任务书.md`；本文不描述 Editor UI。

## 1. 目标和边界

P1 的目标是把当前已经实现的技能及其资源效果从 C# 数值表迁移为可校验的 JSON 参数：

- 22 个 Skill（NormalAttack 的空中连斩是同一 SkillId 分支）
- 4 个 Bullet
- 14 个 Area
- 4 个 Buff
- 7 个 Action 注册类
- 18 个按键映射

行为代码仍由 C# 注册类提供；数值、时序、动画和跨内容引用来自 SkillParams。

P1 不做：

- Editor UI、PreviewRenderUtility 和时间轴
- Play 模式 IMGUI
- NPK/动画帧盒写回
- GrabController、召唤物 AI、炫纹和变身等新框架件
- nextSkill 转派框架的完整扩展（字段可以保留，未使用时为 0）

## 2. 文件布局

~~~text
Packages/cn.etetet.skill/
  Luban/Config/
    luban.conf
    Defines/skill.xml
    LubanGen.ps1
  Runtime/
    SkillParamModels.cs       # 可编辑 JSON DTO 和运行时只读参数
    SkillParamLoader.cs       # 加载、缓存、跨表引用校验
    ContentIds.cs             # 只用于显示和诊断的 id -> name
    ParametricSkillLogic.cs   # 通用技能执行器
    ParametricDefinitions.cs  # Bullet/Area/Buff 参数桥接
    SkillParamsGen/           # Luban 生成，禁止手工修改
  Bundles/SkillParams/
    skills/*.json
    bullets/*.json
    areas/*.json
    buffs/*.json
    actions/*.json
    index.json
~~~

Editor 直接读写 `Bundles/SkillParams`；运行时通过 YooAsset manifest 读取相同内容。

## 3. 引用和命名规则

以下字段在 JSON 中始终是整数：

- animId
- skillId
- areaId
- bulletId
- actionId
- buffId

名称只用于文件名、Editor 显示/搜索和错误信息。运行时不做 name 到 id 的反查，避免名称表缺失或拼写错误
静默变成 0。Editor 可以显示 `14 - BloodBlastOuter`，保存时仍写入 `14`。

文件顶层 id 是唯一身份；文件名只作管理用途，重命名不改变引用。

## 4. Skill 参数模型

Skill 文件由五块组成：

1. 基础属性：id、name、type、cooldownMs、totalTimeMs、空中条件、手动 CD、HP 条件。
2. phases：线性段表；每段包括 animId、durationMs、cancelMs、霸体、位移、清命中表和转派字段。
3. hitReactions：以 phase 标记的伤害、硬直、击退、浮空和 ProcBuff。
4. manualBoxes：以 phase 局部时间表示的手动攻击盒窗口；动画自带帧盒首版只读。
5. spawnEvents / hitEvents：定时事件和命中事件。

最小示例：

~~~json
{
  "id": 11,
  "name": "HardAttack",
  "type": "MeleeCombo",
  "cooldownMs": 6000,
  "totalTimeMs": 950,
  "phases": [
    {
      "animId": 49,
      "durationMs": 950,
      "cancelMs": -1,
      "clearHitTargets": true,
      "superArmorMs": 0,
      "movement": { "distance": 0, "durationMs": 0, "stopOnHit": false },
      "nextSkillId": 0,
      "nextTrigger": "none"
    }
  ],
  "hitReactions": [
    {
      "phase": 0,
      "damage": 80,
      "hitstunMs": 800,
      "kbX": 300,
      "launchY": 300,
      "procBuffId": 0,
      "procChance": 0
    }
  ],
  "hitActions": [1],
  "manualBoxes": [
    {
      "phase": 0,
      "onMs": 300,
      "offMs": 550,
      "offset": [0.9, 0.8, 0],
      "half": [0.8, 0.6, 0.3]
    }
  ],
  "spawnEvents": [],
  "hitEvents": []
}
~~~

## 5. 时间和命中语义

### 5.1 定时事件

时间事件统一采用：

~~~text
previousTime < atMs && atMs <= currentTime
~~~

- atMs 使用毫秒；atFrame 只在 AnimationFrame 基准下使用。
- CastTime 事件以整个施放为范围。
- PhaseTime、PhaseEnter、PhaseEnd、Landing 事件带 phase。
- phase = -1 表示 cast-wide 事件。
- phase 进入时 phase 级事件执行一次；同一 phase 重入时按事件游标规则重新判断。
- Input 事件可用 untilMs 表示窗口上限，必须满足 untilMs >= atMs。
- atMs = 0 在施放创建或进入对应 phase 时执行，不依赖“跨过 0”的假帧。

### 5.2 命中事件

HitPolicy 是技能配置自由度，不在 Editor 中替用户选择：

- FirstHitInCast：整个 cast 第一次解析命中
- FirstHitInPhase：每个 phase 第一次解析命中
- OncePerTargetInPhase：每个目标在每个 phase 一次
- EveryResolvedHit：每次解析命中

SubState 只表示 phase 索引，Phase 只表示 phase 起始时间。事件游标、命中掩码和跨帧待处理目标放在
LSCast 快照字段中，不能复用 SubState 作为事件开关。

### 5.3 命中表现范围

- 浮空、击飞、击倒、推拉和硬直由 hitReaction 的 launchY、kbX、hitstunMs 等字段表达。
- 出血、冰冻、燃烧、眩晕等由 procBuffId/procChance 引用 Buff；霸体由 Phase 或 spawnEvent 的
  superArmor 参数表达。
- 多段技能可以为每个 phase 配置独立反应；juggle 维持使用各段的 launchY/硬直参数。
- grab 目前只保留 hitEvent 占位，等 GrabController 框架件确认后再实现；Editor 不用脚本字符串模拟抓取。

## 6. Bullet、Area、Buff、Action

### Bullet

对位 BulletDefinition 的速度、寿命、穿透、命中重置间隔、半尺寸、出生偏移、视图偏移、视图动画、命中反应和
HitActions。

### Area

对位 AreaDefinition 的半尺寸、持续时间、Tick 间隔、Enter/Tick/Exit Actions、命中反应和前后/结束视图动画。

### Buff

参数包括持续时间、Tick 间隔、最大层数、刷新规则和 Add/Tick/Remove ActionId 数组。复杂的受击触发流程仍由
技能或后续框架负责。

### Action

使用有限的 kind 和 typed parameters（value、intervalMs、buffId 等）。JSON 不填写任意 C# 方法名，也不保存脚本。
C# 注册类只负责行为，数值和整数引用来自参数表。

### 6.1 统一迁移流程

Skill、Bullet、Area、Buff、Action 按同一条流水线迁移，不能只把 Skill 的数值搬到 JSON：

1. 扫描现有 Attribute/Definition 和 C# 注册类，冻结每个内容的整数 ID，建立旧字段清单。
2. 为每个内容生成一个 JSON 文件；先填写能表达当前行为的字段，缺失机制登记到迁移对照表。
3. 让运行时桥接按整数读取参数：Skill 由 ParametricSkillLogic 执行，Bullet/Area 由对应 Definition
   桥接，Buff/Action 由现有注册行为类消费参数。
4. 将 Skill、Bullet、Area、Buff 之间的引用全部改为整数并运行跨表校验；名称只留在显示目录。
5. 以旧 C# 行为逐字段对照，先保留旧实现作为可回退依据；用户完成 Play 回归后再删除已确认的旧数值。

Buff 的持续时间、Tick、层数和刷新规则进入 buffs 表，Add/Tick/Remove 的 ActionId 列表也在表内；
Action 的 kind 和 typed parameters 进入 actions 表，但 ActionId 注册类仍是行为入口。这样 Buff/Action
可以被 Editor 单独打开和调参，又不会把任意脚本执行能力引入数据层。

## 7. 技能模板

| type | 适用范围 | 主要字段 |
|---|---|---|
| MeleeCombo | 普攻、月光斩、三段斩、里鬼等 | phases、hitReactions、manualBoxes |
| Dash | 破军、突进、多段突刺等 | movement、stopOnHit、末端事件 |
| Projectile | 波动剑、冰息、邪光等 | createBullet、Bullet 参数 |
| AreaBurst | 怒气、血爆、落地冲击波等 | createArea、Area 参数、Tick |
| Buff | 自身增益和状态链 | addBuff、Buff 参数 |

空中、落地等状态前置是正交字段，不单独创建模板。抓取、召唤、炫纹、变身等新机制需要先补框架件，再增加
对应模板；不能在 Editor 中用字符串脚本绕过。

## 8. 代码和加载边界

- Luban XML schema 管理字段、枚举、嵌套 bean、列表和表索引，并生成 `Runtime/SkillParamsGen`。
- `SkillParamLoader` 使用 Newtonsoft DTO 读取 JSON，维护按整数 ID 的缓存并执行 fail-fast 引用校验。
- `ContentIds` 只提供 id 到 name 的显示目录，不参与运行时引用解析。
- `ParametricSkillLogic` 保留现有 [SkillId] 注册协议：每个技能由无状态薄子类注册，
  基类按 ConfiguredSkillId 或当前 cast 的 skillId 查询参数；不把可变配置写进逻辑实例。
- `LSCast.PendingHitTargets` 用于跨帧命中交接；新增快照字段必须递增 MemoryPackOrder 并经过 Unity/F6 验证。

## 9. P1 证据和遗留项

已验证：

- 预构建 Luban 可运行
- 正式表生成成功
- 独立 Loader 校验：skills=22、bullets=4、areas=14、buffs=4、actions=7、buttons=18
- loaderValid=True、referenceErrors=0

尚未等价证明：

- Unity/F6 编译和 MemoryPack 新字段
- 22 个技能的 Play 行为回归
- 复杂技能的特殊分支（NormalAttack 空中、HopSmash 多段、ChargeCrash 撞停、GoreCross 输入窗口等）

这些证据在 P2 Editor 回归和用户逐个 Play 测试时补齐，不把“参数能加载”写成“行为已完全一致”。
